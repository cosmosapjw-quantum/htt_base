# AUDIT_SK-01S1_2026-04-21

## 1. Audit target reconstruction

- Target: close the S1-lane skeleton packet for VER2 BASS algebra/geometry/background contracts.
- Semantic SSOT: `docs/ver2_upgrade/*` only.
- Upstream shared-schema owner: `htt/src/common/*` from `SK-01C`.
- Packet write scope used:
  - `htt/bass/background/*`
  - `htt/bass/tilt/*`
  - packet-local background tests only
- Required packet outputs from SSOT:
  - one algebra object for all eleven Bianchi types,
  - canonical structure-constant / Jacobi surfaces,
  - tetrad connection and spatial-curvature operators,
  - Gauss/Codazzi/Bianchi-identity residual stubs,
  - orthogonal and tilted IC-builder interfaces,
  - 1+3 background RHS assembly surface,
  - Weyl diagnostic hooks.

### Candidate layouts considered

1. Retrofit the existing reduced modules (`bianchi_types`, `tetrad_state`, `einstein_bianchi`) only.
2. Add VER2 contract modules beside the reduced solver and bridge them with thin wrappers.
3. Create a separate `ver2/` subtree under `htt/bass/background`.

### Converged choice

- Choose layout 2.
- Reason:
  - preserves the current reduced solver without pretending it already satisfies VER2,
  - allows canonical algebra/geometry contracts to exist now with minimal regression risk,
  - keeps the future implementation path obvious: later packets can replace internals while reusing the same interfaces.

## 6. Ranked failure modes

1. `P0` mixed class-B axis conventions
   - symptom: geometry and tilt modules disagree on which axis carries `a_alpha`
   - root cause: reusing legacy Pontzen-Challinor frame directly in new modules
   - cheapest test: class-B canonical-axis tests on `BianchiAlgebra`
   - interpretation risk: wrong sign / wrong component in Codazzi and curl operators
2. `P0` type-specific geometry shortcuts re-enter the backend
   - symptom: RHS or diagnostics branch on type name instead of consuming `C`
   - root cause: incomplete algebra object contract
   - cheapest test: all-type build/geometry tests
   - interpretation risk: VII_h or I becomes privileged again
3. `P1` orthogonal/tilted admissibility inferred implicitly
   - symptom: a caller assumes a branch is valid without residual checks
   - root cause: missing machine-readable branch policy and residual output
   - cheapest test: IC builder tests on balanced vs unbalanced Type I tilt
   - interpretation risk: physically inadmissible ICs treated as solved
4. `P1` Weyl diagnostics use different conventions from the geometry module
   - symptom: magnetic Weyl nonzero in flat Type I diagonal-shear limit
   - root cause: separate sign conventions for curl vs connection
   - cheapest test: Type I curl/Weyl zero tests
   - interpretation risk: false “physics signal” from convention drift
5. `P2` reduced solver mistaken for VER2-complete background engine
   - symptom: callers treat `einstein_bianchi` as if it already consumed the new PSTF contracts
   - root cause: contract layer and executable layer not yet wired together
   - cheapest test: audit/ledger carry-forward plus later implementation packet checks
   - interpretation risk: solver-completeness overstated
