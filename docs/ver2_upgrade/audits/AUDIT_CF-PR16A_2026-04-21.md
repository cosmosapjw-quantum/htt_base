## Three-lane verification

1. Internal docs + local code:
   - `PR-16` requires executable checkpoint/restart, explicit tolerances, and restart reproducibility.
   - The native Tier-B runtime already exposed integrator-family metadata, but restart was not executable on the live path.
   - The first checkpoint implementation still under-recorded restart compatibility metadata; `bianchi_type` and `L_max` alone were insufficient for parametric classes and tilted-frame runs.
2. Web CRAG:
   - not needed; the deciding authority was the local VER2 SSOT and the shipped runtime contracts.
3. Integrated phys-math-code audit:
   - the load-bearing gap was not solver availability but restart contract completeness.
   - A checkpoint that omits structure constants / tilt / frame convention can replay the wrong physics while still looking numerically valid.

## Divergence -> verification -> convergence

### Candidate A

- land restart with only `bianchi_type`, `L_max`, and the packed radiation state

Rejected:
- too weak for the `PR-16` kill criteria; does not protect against structure-parameter or tilt/frame drift

### Candidate B

- serialize the entire runtime object graph including species/history builders

Rejected:
- oversized and brittle for a bounded repair; couples restart to many non-essential internals

### Candidate C

- serialize the minimal restart state plus the algebra/frame metadata that changes the physics:
  - structure label / `n_i` / `a_twist`
  - tilt rapidity / tilt direction
  - direction convention
  - output-grid and solver-method metadata

Chosen:
- smallest repair that makes restart compatibility explicit and machine-checkable without widening scope into full object persistence

## What is now closed

- the native Tier-B route can now checkpoint and restart on the live runtime path
- restart compatibility is checked against algebra/frame metadata instead of only shape metadata
- restart failures now happen before expensive background construction if the checkpoint is incompatible
