## 6. Ranked failure modes

1. `P0` validation remains prose-only
   - symptom: docs describe campaigns, but no machine-readable registry exists
   - root cause: no canonical schema surface
   - cheapest test: `htt/scripts/ver2_validation_registry.py --check`
   - interpretation risk: manuscript claims drift away from tests
2. `P0` warn campaigns treated as validated gates
   - symptom: incomplete campaigns silently support validated claims
   - root cause: no explicit pass/warn/fail semantics
   - cheapest test: `test_warn_does_not_promote_to_validated`
   - interpretation risk: premature science promotion
3. `P1` no-claim conditions omitted from campaign rows
   - symptom: registry contains tests but not downgrade triggers
   - root cause: schema does not require no-claim metadata
   - cheapest test: dataclass construction checks in `validation_registry.py`
   - interpretation risk: failures degrade into vague caveats
4. `P1` manuscript export not blocked on fail
   - symptom: fail state does not stop export
   - root cause: missing fail-block function
   - cheapest test: `test_fail_blocks_manuscript_export`
   - interpretation risk: invalidated result pack still exported
5. `P2` hostile audit lacks category separation
   - symptom: runbooks collapse into one undifferentiated checklist
   - root cause: no structured runbook buckets
   - cheapest test: `test_hostile_audit_runbook_has_all_check_buckets`
   - interpretation risk: adversarial and numerical checks disappear into generic CI language
