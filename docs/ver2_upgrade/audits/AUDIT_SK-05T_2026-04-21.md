## 6. Ranked failure modes

1. `P0` TSC becomes hidden runtime owner
   - symptom: TSC object exposes `allow_reduction` or imports BASS runtime writers
   - root cause: adapter overreach
   - cheapest test: field-absence plus AST import scan
   - interpretation risk: runtime authority silently migrates away from BASS
2. `P0` TSC overclaims BB/full-polarization/family identification
   - symptom: artifact text claims BB or family validation by TSC
   - root cause: missing lint / missing quarantine
   - cheapest test: forbidden phrase scan on snippets/metadata
   - interpretation risk: trace semantics mistaken for full morphology proof
3. `P1` source adequate conflated with observable adequate
   - symptom: propagation-pending cases reported as validated results
   - root cause: channel budgets lack explicit pending state
   - cheapest test: overlay snippet on pending budgets
   - interpretation risk: EE/TE/BB claims become overstated
4. `P1` TSC dataclasses duplicated outside common schema owner
   - symptom: incompatible report definitions across packages
   - root cause: local redefinition instead of aliasing
   - cheapest test: import alias checks
   - interpretation risk: later package bindings drift semantically
5. `P2` richer TSC public labels diverge from shared base enums
   - symptom: local label semantics not representable in common fields
   - root cause: coarse shared status enums chosen earlier for barrier stability
   - cheapest test: compare budget/report statuses against allowed combined labels
   - interpretation risk: downstream teams assume the common enum already carries the richer semantics
