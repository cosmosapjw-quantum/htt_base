# AUDIT_SK-01C_2026-04-21

## 1. Audit target reconstruction

- Target: close the shared VER2 contract skeleton layer after the schema barrier landed in `SK-00`.
- Semantic source of truth: `docs/ver2_upgrade/*` only.
- Code source of truth for shared schema:
  - `htt/src/common/contracts.py`
  - `htt/src/common/departure_contracts.py`
- Thin wrapper layer:
  - `htt/workspace/contracts/*`
- Required surfaces from SSOT for this packet:
  - `Owner`, `ClaimTier`, `ImplementationScope`, `ProductionStatus`
  - `ArtifactManifest`
  - `SolverCoreOutput`
  - `ObservableVector`
  - `AtlasEntryLite`
  - `DepartureReport`
  - `MioCertificate` overlay hook
  - `TscAdequacyOverlay` wrapper hook
  - status snapshot / claim ledger / sky-support stubs

### Candidate schema layouts considered

1. Keep all VER2 contracts in `common.contracts`.
2. Make `workspace/contracts` the owner of cross-package schemas.
3. Split canonical base contracts and x/Q/Pi/F/G contracts:
   - base ownership/manifest/atlas/TSC contracts in `common.contracts`
   - x/Q/Pi/F/G contracts in `common.departure_contracts`
   - workspace layer remains thin aliases only

### Converged choice

- Choose layout 3.
- Reason:
  - keeps the canonical owner path inside `htt/src/common/*`,
  - prevents `workspace/contracts` from becoming a second schema owner,
  - keeps x/Q/Pi/F/G surface isolated without bloating the base module.

## 6. Ranked failure modes

1. `P0` duplicate shared schema outside `htt/src/common/*`
   - symptom: incompatible enums or manifests across packages
   - root cause: wrappers or producers owning shared dataclasses
   - cheapest test: AST schema-barrier test over `workspace/contracts/*`
   - interpretation risk: false sense of cross-package compatibility
2. `P0` owner drift on serious artifacts
   - symptom: HTT/MIO/BASS/TSC artifacts carry the wrong owner
   - root cause: manifest hooks accepted without validation
   - cheapest test: construct wrappers with mismatched manifest owners
   - interpretation risk: claim-tier and runtime authority confusion
3. `P1` missing claim-ledger row contract
   - symptom: generated docs later invent a second schema
   - root cause: claim ledger exists only as prose
   - cheapest test: import/use `ClaimLedgerEntry`
   - interpretation risk: manuscript claim drift
4. `P1` missing TSC overlay hooks on reporting objects
   - symptom: downstream packets patch report schemas incompatibly
   - root cause: overlay attachment postponed without reserved field
   - cheapest test: dataclass field presence check
   - interpretation risk: TSC caveats silently dropped
5. `P2` common module bloat causing circular import pressure
   - symptom: producers import `workspace/contracts` back into `common`
   - root cause: wrong ownership direction
   - cheapest test: keep workspace wrappers as pure aliases
   - interpretation risk: architectural workaround disguised as schema progress
