## 6. Ranked failure modes

1. `P0` exactness flags inferred rather than declared
   - symptom: downstream users cannot tell whether a subsystem is exact, approximate, or disabled
   - root cause: missing feature-status contract
   - cheapest test: `SolverFeatureFlags` construction tests
   - interpretation risk: production claims attached to approximate paths
2. `P0` FLRW scalar kernel reused as production propagator
   - symptom: anisotropic propagation collapses to scalar `j_l` behavior outside validation mode
   - root cause: missing propagator-mode gate
   - cheapest test: `SourcePropagatorConfig` validation tests
   - interpretation risk: anisotropy falsely suppressed by implementation shortcut
3. `P1` solver output drifts into observational interpretation
   - symptom: BASS output starts carrying likelihood/posterior/p-value fields
   - root cause: no canonical neutral builder
   - cheapest test: `build_solver_core_output` metadata tests
   - interpretation risk: package-boundary violation between BASS and HTT
4. `P1` cutoff campaign silently under-runs
   - symptom: one cutoff or missing rows presented as a convergence study
   - root cause: no explicit campaign request/result contract
   - cheapest test: missing-cutoff summary test in `ver2_cutoff_campaign`
   - interpretation risk: false convergence confidence
5. `P1` legacy runtime test failure misread as an S3 regression
   - symptom: `htt/bass/runtime/test_end_to_end_wiring.py` fails at collection
   - root cause: pre-existing `bass.background` ↔ `bass.tilt` import cycle
   - cheapest test: run that test directly and inspect the import traceback
   - interpretation risk: packet-local contract work blamed for an out-of-scope package export cycle
