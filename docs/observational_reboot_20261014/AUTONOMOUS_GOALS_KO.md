# 모든 실행 가능한 분석을 완결하는 Codex 운영 목표

2026-10-14 사용자 추가 지시: **지금까지의 이론과 코드를 가지고 할 수 있는 분석은 전부 수행하고, Codex가 goal을 지정해 계속 작업한다.** 이 지시는 특정 PR 하나나 SMICA 그림 하나를 만든 뒤 종료하는 흐름을 대체한다. 현재 세션의 재시작 패키지와 후속 과학 캠페인의 완료는 구별한다.

## 최상위 목표

현재 저장소의 이론·코드·접근 가능한 실제 관측자료·검증된 시뮬레이션을 연결하여, 가능한 모든 분석을 결과·수치자료·그림·보고서까지 완결한다. Planck SMICA morphology와 p, 물리 dipole, local observer boost와 global tilt의 분리, 조건부 Bianchi morphology 및 적격 native atlas가 도착한 뒤의 family 비교를 핵심 질문으로 유지한다. CF4/SDSS 거리·속도, DESI, Union3, ACT, CLASS 편광, Gaia/JWST 및 기존 이론의 부분 식별·tensor/MES·깊이 통계를 capability inventory에 따라 병렬로 확장한다.

‘전부’는 현재 준비된 검증·계산을 생략하지 않는다는 뜻이다. 무한한 통계량 조합을 만들거나 같은 분석을 표현만 바꾸어 반복하는 것은 포함하지 않는다. 입력·관측량·물리 모형·검정법·민감도 축의 유한 조합을 먼저 등록하고, 새로 발견된 실행 가능한 분석은 근거와 소비할 과학적 질문을 붙여 큐에 추가한다. inventory를 읽었다는 사실만으로 전체 저장소의 가능성을 모두 열거했다고 선언하지 않는다.

## Goal을 지정하고 계속하는 알고리즘

1. 시작할 때 현재 branch/HEAD/status, `NEXT_TASK.json`, `DELIVERY.json`, `GOALS.json`, `REBOOT_PLAN.json`을 읽는다. 이전 입력·식·코드가 유지된 근거는 재사용하고, 현재 runtime과 경로만 재확인한다.
2. `python scripts/reboot_task_packet.py --ready`로 의존성상 준비된 작업을 얻는다. `research/ANALYSIS_OPPORTUNITY_INVENTORY.json`에서 현재 자료가 준비된 추가 분석도 찾는다. 상태는 계산 권한과 과학적 수용을 구별한다.
3. **이번 단계의 구체적인 goal을 직접 지정한다.** 질문, 대상 데이터/모형, 실제 만들 수치·그림, 비교/반증 조건, 출력 경로, 완료 판정을 5–8문장으로 기록한다. ‘조사하기’로 끝나지 말고 조사 후 연결할 결과를 적는다.
4. 선행 입력이 모두 있는 분석은 실행한다. 코드 연결이 필요하면 구현→대상 테스트→실제 데이터 실행으로 이어간다. 연구 유도가 필요한 곳은 식→전제→계산식→구현 계약을 완성한다. 완료 상태가 다른 하위 작업을 통째로 묶어 PASS 처리하지 않는다.
5. 독립 작업은 native subagent에 작은 맥락으로 맡긴다. 부모 포함 최대 4개, production writer는 부모 1개다. 겹치지 않는 patch를 받아 통합하고, 별도 fresh-context reviewer가 과학/코드/그림을 한 번 검토한다. 종료한 worker는 닫는다.
6. 결과를 얻으면 숫자와 불확실성, 처리·null·모형·단위·frame·source를 함께 저장하고, 그림을 직접 읽어 수정한다. 각 PR은 테스트·독립 검토·상태/DAG 동기화 후 commit/push한다. 사용자 요청으로 이미 승인된 reversible 구현과 일반 push에 매번 재허가를 묻지 않는다. main merge나 별도 유료 서비스·새 서버 조달은 이 지시의 일부가 아니다.
7. **한 goal이 끝나면 같은 실행 흐름에서 다음 준비된 goal로 즉시 이동한다.** 계획, checkpoint, 통과 보고, handoff 작성, PR 개수나 한 장의 그림을 종료 사유로 삼지 않는다. 5개 PR 단위의 기존 progress 규칙을 적용하되 숫자 증가를 연구 성과로 대신하지 않는다.
8. 한 경로가 막히면 원인을 DATA/MODEL/CODE/NUMERICAL/ENVIRONMENT/ACCESS로 분류하고, 실제로 부족한 파일·법칙·값·권한과 다음 획득/유도/구현 명령을 남긴다. 접근 가능한 파일의 다른 alias·기존 accepted cache·출처가 명확한 조건부 모형·부분 식별로 수행 가능한 일을 먼저 한다. 다른 ready goal로 넘어가며 전체 연구를 정지시키지 않는다.
9. 맥락이나 host 실행 경계가 다가오면 현재 goal, 완료 근거, 수정 파일, 실행 중 PID/seed/batch, 다음 **한 명령**을 기존 checkpoint에 기록한다. 재개 시 이미 성공한 큰 계산을 다시 하지 않는다. 자동 재개 기능이 제공되지 않는 host에서 세션 경계를 스스로 넘겼다고 주장하지 않는다.
10. 큐를 다시 조사하여 실질적인 실행 가능한 분석이 모두 소진됐을 때만 캠페인을 종료한다. 남은 각 goal에 외부 입력/권한/실행 의존성의 정확한 근거가 있어야 한다. 코드가 미완성이라는 사실, 오래된 HOLD, 불명확한 모델 이름, 시간이 오래 걸릴 것이라는 추측만으로 준비된 일을 남기지 않는다.

## 결과의 폭과 깊이

각 데이터에서 가능한 기술통계·관측량 복원·null 검정·반응/식별성·모형 적합·PPC/잔차·민감도·부분 식별·교차자료 조합을 차례로 검토한다. 모든 데이터에 모든 추론법을 억지로 적용하지 않고, 실제 법칙과 관측 반응이 뒷받침하는 분석을 택한다. 새로운 family나 prior를 골랐으면 비교 대상과 선택 과정을 기록한다.

모수·마스크·multipole·통계량·깊이 cut을 바꾸는 민감도는 유한 집합으로 정하고 전체 선택을 calibration에 반영한다. 더 작은 p를 찾는 방향으로 실험을 무기한 늘리지 않는다. 이미 본 같은 하늘을 새 세션에서 열었다고 독립 확인자료나 사전등록 연구가 되지는 않는다.

현재 SMICA pilot의 60/240 split은 동일 noise 재활용 문제를 피하는 실행 단위다. 물리적 관측과 전달된 simulation의 교환가능성을 새로 증명하지 않는다. 다음 goal은 이 결과를 멋진 숫자로 포장하는 것이 아니라 처리 응답/전경·systematics와 실제 source law를 개선하여 관련 질문의 신뢰도를 높이는 것이다.

## 저비용 LLM 작업 계약

작업자는 `reboot_task_packet.py --task RBxx`와 직접 필요한 코드/테스트/문헌 절만 읽는다. 반환 JSON에는 goal/task ID, 기준 HEAD, 수정 경로, 실행 argv/exit, source, 결과·단위, 실패와 남은 의무, 다음 행동을 넣는다. 설명만 있는 README를 구현 성공으로 세지 않는다. 독립 검토에서 물리적 선택이 해결될 때까지 계산 가능한 조건부·탐색 결과는 정확히 표시해 보존한다.

통계 정밀도와 근거가 필요한 작업에 무조건 가장 싼 모델을 배치하지 않는다. routine extraction/patch/tests에는 작은 bounded packet을 주고, 물리법칙 선택·nonlinear degeneracy·강한 claim·실패 원인에 대한 판단은 도메인 검토로 올린다. 요청 model/effort와 관찰 runtime은 별도로 기록한다. 외부 API 구독이나 모델 서버 설치를 자동으로 시작하지 않는다.

## 종료 때의 필수 반환

완료된 분석과 실제 scientific result/plots/reports, 조건부/탐색/수용 상태, 아직 실행하지 못한 goal별 정확한 원인, 테스트·review 결과, 실제 push ref/commit/tree, 다음 실행 명령을 반환한다. ‘모든 분석 완료’는 실행 큐와 capability inventory가 그 상태를 실제로 뒷받침할 때만 쓴다.
