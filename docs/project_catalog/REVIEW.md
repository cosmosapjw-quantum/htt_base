# 카탈로그 도구 검토와 수정

독립 검토는 한 차례 수행했다. 원래 판정은 **FAIL**이며, 발견한 5개 결함과 재현
방법을 [원본 결과](review/static-review.json)에 그대로 보존했다. 주 작성자가
아래 수정을 적용하고 회귀 테스트를 확인했다. 원래 FAIL을 독립 재검토 PASS로
바꾸지 않는다. [수정 대응표](review/repair_resolution.json)는 주 작성자의 확인이다.

| 결함 | 적용한 수정 |
|---|---|
| F-001 | Git clean filter가 실행될 수 있는 diff 기반 감지를 제거. 원시 바이트 비교, fsmonitor 비활성화. |
| F-002 | conjecture/experiments 등 경로에 따른 분류 문맥과 캐시 키를 통일. |
| F-003 | 추출 제한 변경 시 기존 DB 보존 후 새 DB로 전체 재생성을 요구. |
| F-004 | 출처 목록 조회에서 `--source` 필터 적용. |
| F-005 | `--not-in-ref all/working`을 명확한 오류로 처리. |

추가 자체 검수로 중복 함수 선언 보존, 추상 인터페이스와 스텁 구분, 원문 이식
언급의 부정·계획 상태 보존, 원본 저장소와 PyYAML 없이 조회하는 경로를 확인했다.
길잡이의 명시적 버전 연결이 증분 수집에서 사라지는 결함도 별도 fixture로
재현한 뒤, 일반 Git 경로 해석이 그 연결을 덮어쓰지 않도록 수정했다.
설치 의존성 9개 출처의 metadata-only 범위는 유지됐지만 종류 필드가 일반 Git으로
남는 upsert 누락도 수정했다. 관련 fixture는 의존성 커밋 기록만 남고 프로젝트
심볼이 생성되지 않는지 확인한다.
최종 테스트 명령과 실제 결과는 [작업 기록](EXECUTION.md)에 남긴다.

서브에이전트는 지정된 카탈로그 작업트리에서 등록된 할당을 읽고 결과를 작성했다.
종료 훅이 기본 체크아웃의 별도 과거 실행을 선택한 경로 불일치는 원본 결과의
limitations에 보존했다. 그 과거 실행에 결과를 복사하거나 상태를 바꾸지 않았다.
두 에이전트 스레드는 종료했다.

검토 범위는 정적 수집기와 검색 도구다. 연구 코드, 과학적 주장, CAS/Lean 증명의
정당성을 재검증하지 않았다. 정적 연결은 대표 관찰 버전에 묶이며, 같은 원문이
존재하는 모든 후속 커밋에 대한 근거 적용성을 자동으로 보증하지 않는다.

전체 증분 수집에서 새로 관찰된 17개 파일은 모두 자동 `.remember` 실행 로그·캐시였다.
이 디렉터리는 프로젝트 코드·설계에 해당하지 않아 재귀 수집에서 제외했다. 과거에
관찰한 위치·크기·처리 상태는 유지하고 추출 본문과 의미 레코드는 DB에서 제거했다.
원래 캐시 파일은 수정하지 않았다. 배포 DB는 live page만 `VACUUM INTO`로 복사하므로
사용하지 않는 SQLite 페이지를 포함하지 않는다.

기록 상태의 부분 문자열 `PROVENANCE`를 `PROVEN`으로 읽은 실제 1개 항목도 수정했다.
부정 표기와 토큰 경계를 구분하고 명시적 CANDIDATE를 후보로 분류했다. 원문 상태는
변경하지 않았으며 파생 분류 275개를 보정한 [전후 기록](review/status_normalization.json)을
남겼다. 이 보정은 새로운 증명·검증을 수행하거나 원문 레지스트리를 승격한 것이 아니다.
