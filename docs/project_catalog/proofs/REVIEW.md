# 정적 증명 근거 검토와 검수 범위

Owner: COMMON. Scope: 기존 증명 근거의 검색용 파생 목록. 과학적 승인 자료가 아니다.

## 판정의 의미

확인 목록은 기존 증명 본문과 가정·대상 소스 버전에 대응하는 기록을 읽은 결과다.
이번 작업에서 연구 코드, Lean, CAS, 기존 연구 테스트를 실행하지 않았다.
수학적으로 독립인 정리 수를 계산하지 않으며, 원문 레지스트리의 상태를 수정하지 않는다.

`PROVEN/DERIVED` 계열 455개 레코드는 17개 제목으로 묶이는 검토 대상이었다.
그중 454건은 명제 전체와 대응하는 정확한 증명 본문을 확인하지 못해 미확인으로 남겼다.
나머지 C-PR173-MC-CERTIFIER 1건은 구현 계약의 준비 상태여서 수학 명제 목록에서 제외했다.
관련 구버전 문서·구현·빠진 부록의 위치와 제한은 `source_review_summary.json`에 있다.

별도로 Lean 원문 35개 내용 버전을 읽고, 실제 선언의 전체 증명 본문과 저장된
컴파일 기록의 소스 해시·명령·상태·제한을 대조했다. 확인된 개별 보조정리의
상위 CAS 과제가 INCONCLUSIVE/FAIL인 경우 그 상태와 좁은 적용 범위를 함께 보존했다.
`native_decide`를 포함한 소스 단위는 확장된 native 평가 신뢰 기반을 명시했다.

총 931개 검토 단위가 원본 1,135개 레코드에 연결된다. 나머지 검색 결과는
원문 상태와 보수적 추출 규칙에 따라 미확인 또는 제외로 분류했다.
모든 문장을 사람이 각각 수학적으로 심사했다는 뜻이 아니다. 원문 검색의 제안 후보에는
추가 문맥 대조가 필요한 일반 언급도 남을 수 있다. 미확인은 거짓이나 반증을 뜻하지 않는다.

## 독립 검토와 수정

독립 검토자는 확인 근거 345개 단위의 서로 다른 발췌 365개를 40개 소스·기록 파일과
직접 대조했고, 원문·줄 범위 불일치가 없음을 확인했다. R8 AC/D, PR254의 부분 빌드,
PR270 r2의 전체 FAIL, native 평가의 제한을 별도로 확인했다.
검토 시점의 27,122개 명제 ID 집합과 전체 561,595개 검색 레코드의 배타적 분류도
대조했다. 이후 추가 원문 검색·출력 분할은 부모 에이전트의 최종 전수 검수 범위다.

원문 수집 중 TAR 판독에서 ZIP 형식 검사 후 파일 위치를 되돌리지 않는 오류를 발견했다.
이를 수정하고 5,634개 내용 버전을 다시 읽었다. 단일 파일을 가리키는 길잡이 주석
locator도 처리해 1개 내용 버전을 추가로 읽었다. `source_scan.csv`의 `errors`에는
최초 오류도 보존되므로 최종 성공 여부는 `processing_status`로 판단한다.
판독이 끝난 내용을 전부 재수집하거나 연구 코드를 실행하지 않았다.

## 검수와 남는 제한

- 카탈로그 전용 43개 테스트: 동일 ID/다른 가정, 조건부 상태, ZIP/TAR 사본,
  선언/PASS만 존재하는 경우, 철회·대체, 누락·상충 근거, 읽기 전용 DB,
  원본 없는 재생성, 추가 원문 검색, 압축 분할의 행 보존을 확인한다.
- DAG 196개 구조 검증: 통과. 이 사용자 요청 PR만 추가하며 과학적 상태는 유지한다.
- 최초 문법 오류와 동시 수정 중 형식 fixture 실패를 보존했고, 최종 테스트에서 해결했다.
- PDF 484개 내용 버전은 텍스트를 읽었다. 수식 이미지·레이아웃·읽기 순서를 시각 감사하지 않았다.
- 기존 DB 스냅샷 이후 바뀐 `EXTERNAL-FUSION-FOLLOWUP-20260829/launches/deliveries.jsonl`
  1개 내용 버전은 바이트가 달라 원문을 대체하지 않았다. 기존 DB 발췌와 미확인 상태를 유지한다.
- 빈 비문서 내용 1종(15개 파일 위치)은 별도 처리 상태를 남겼다.
- 개별 검토의 로컬 결과 파일은 존재하지만, 매퍼 결과의 봉투 형식 오류와 원본 체크아웃에
  연결된 종료 훅 때문에 공통 에이전트 하네스 전체의 정상 종료는 통과하지 않았다.
  이 작업트리의 포인터만 해제하고 결과·실패 기록 및 원본의 다른 실행은 보존했다.
  이를 증명 검증이나 전체 하네스 PASS로 표시하지 않는다.

최종 전수 검사·반복 생성·원격 게시 결과는 `validation.json`과
`PUBLICATION_RECEIPT.json`에서 확인한다.
