# 10 — CONVENTIONS / OPERATING RULES

## Physics and mathematics

- Metric signature `(-,+,+,+)`.
- Spatial orientation `epsilon_123=+1`.
- Retain `c` explicitly unless a source section declares a consistent adapter; never mix geometric numerator rates with inverse-time denominators.
- Accepted local-observer sky convention: outward `n=-e`.
- `beta=v/c`; `beta_RO`, `beta_RM`, `beta_MO` are different typed frame relations.
- Observable `Q_ab`, `O_abc` are temperature tensors. They are not congruence shear/vorticity merely because representations match.
- Default spatial tensor norm is the full Euclidean Frobenius contraction. Half-contraction conventions require an explicit adapter.
- Raw-real and orthonormal stored-real harmonic coordinates require their declared component metric/adapter.
- A missing component is unavailable, not zero. Typed abstention is an allowed scientific output.
- Weak premises imply non-strict bounds; do not promote them to strict claims.
- Continuum, finite-pixel, exact algebraic rank, tolerance-dependent numerical rank, error-conditional robust rank and singular-subspace orientation are different claims.
- A realised compatibility set, a population identified set and a confidence region are different objects.

## Evidence / claim policy

- `FACT`: durable source/test/receipt, directly verified repo state, owner decision or exact derivation under explicit assumptions.
- `CONDITIONAL`: carry every model/statistical/regularity premise near the claim.
- `HYPOTHESIS`: useful candidate, not established.
- `OPEN`: unresolved or missing required evidence.
- `DEPRECATED`: retired path; retain tombstone and reusable residue only.
- `TRANSCRIPT-ONLY`: never upgrade without durable evidence.
- A passing software test proves only its contract. Do not equate test count with scientific completeness.
- Exact-source native, source-equivalent, symbolic proof, numerical stress, document review and hosted CI are distinct evidence grades.
- Preserve failed/negative evidence; later repairs do not erase failure history.
- No canonical promotion from T9 v4/30 or the 40-candidate map without explicit owner decision.

## Workflow

- Current route: **MAIN conversation <-> Local Codex**.
- MAIN performs all feasible scientific derivation, literature/source review, specification and returned-result adjudication.
- Local Codex is reserved for workstation-dependent implementation, numerical execution, selected-data intake, plotting/rendering and Git return.
- Local Codex does **not** choose new physical models, priors, statistics, products or claim meanings when the frozen contract is incomplete.
- In an approved bounded work unit, multiple evidence-driven edit -> test -> diagnose -> edit iterations are allowed without repeated approval while objective, protected semantics and resource class remain fixed.
- Reapproval is required for new scientific scope, protected meaning changes, new consequential external action, or a true hard-limit change.
- One source writer per candidate branch.
- Prefer immutable Git-readable handoffs and returns. No mandatory WORK_THREAD or manual ZIP relay.
- Push only to isolated branches, non-force, and keep Draft unless the owner changes that rule.
- Do not merge, mark ready, change repository visibility, publish externally or send to recipients without explicit owner direction.
- Planning budgets are adjustable with reason and old/new/cumulative accounting. Explicit owner/platform/privilege/preregistered-experiment hard limits remain hard.
- Blind retry is bounded. Productive in-scope repair is **not** limited to one edit.

## Data

- Do not re-scan/re-hash the reported ~1.5 TB inventory.
- File counts are not independent sky or simulation counts.
- Partial/incomplete files are excluded, not deleted.
- Posterior draws are not null universes.
- Correlated reconstructions are not independent anchors.
- ACT lensing `kappa` is not a temperature/boost map.
- Lensing shear is not spacetime congruence shear.
- A missing exact product definition yields a typed product blocker. Do not substitute a convenient product autonomously.
