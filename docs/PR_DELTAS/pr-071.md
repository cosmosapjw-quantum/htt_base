# PR-071 - Harmonic and spin convention registry

## Goal

- Owner: OBSSTAT
- Depends: PR-070
- Level: L2
- Scope: pre-solver
- Risk: high

Add an OBSSTAT-owned convention registry for harmonic coefficient feature
exports. Harmonic payloads now need explicit metadata for basis,
normalization, phase, theta/phi convention, evaluator provenance, coordinate
frame, storage order, reality condition, spin weight, spin transform,
polarization basis, paired-map order, output-pair semantics, and `lmax/mmax`.

This PR is diagnostic observable-feature provenance only. It does not produce
HTT evidence, MIO certificates, native solver output, transfer validation,
morphology compatibility, or family-identification evidence.

## Chosen plan

- Add `htt.obsstat.alm_conventions` with:
  - frozen `AlmConvention`;
  - scalar-temperature and spin-2 canonical convention factories;
  - fail-closed `validate_alm_convention_metadata`;
  - `build_alm_feature` that attaches checked metadata, diagnostic claim
    tier, coefficient hash, and optional provenance;
  - `validate_alm_feature_conventions` for OBSSTAT export gates.
- Make `build_observable_vector` reject alm-like feature nodes with
  coefficients, `lmax/mmax`, `spin_weight`, or legacy `convention` fields
  unless the same channel-local node carries valid `convention_metadata`.
- Require alm convention coordinate frames to match `SkySupport.coordinate_frame`.
- Check healpy-style alm vector lengths without adding a runtime healpy
  dependency.
- Normalize NumPy arrays/scalars and complex coefficients to deterministic
  JSON-compatible payloads before hashing.
- Reject unknown metadata fields so posterior/evidence/native/family labels
  cannot hide inside convention metadata.

## Review findings and fixes

- Finding: raw alm payloads with only `"convention": "complex_alm"` were still
  accepted.
  - Fix: `build_observable_vector` now calls
    `validate_alm_feature_conventions` before constructing the canonical
    `ObservableVector`; raw legacy convention strings are rejected.
- Finding: the first spin-2 metadata pass recorded `spin_weight=2` and
  `healpy_map2alm_spin` but not Q/U ordering or output-pair meaning.
  - Fix: added `paired_map_order`, `spin_output_convention`, and
    `eb_sign_convention`; the canonical spin-2 metadata records Q-then-U input
    ordering and a no-E/B-export sign caveat.
- Finding: the evaluator wording was too generic and could be confused with
  older spherical-harmonic APIs.
  - Fix: added `harmonic_evaluator="scipy.special.sph_harm_y"` and explicit
    evaluator provenance metadata.
- Finding: coefficient hashes used JSON-like lists but not NumPy arrays/scalars.
  - Fix: NumPy arrays/scalars and complex coefficients are normalized before
    deterministic SHA256 hashing.
- Finding: healpy storage metadata did not constrain vector length.
  - Fix: `build_alm_feature` now checks the healpy m-major alm size formula and
    spin pairs require two same-sized arrays.
- Finding: parent convention metadata could silently cover mixed child payloads.
  - Fix: alm-like child nodes require channel-local `convention_metadata`; root
    metadata does not satisfy nested channels.
- Finding: convention coordinate frames could drift from sky-support metadata.
  - Fix: OBSSTAT export rejects mismatches against `SkySupport.coordinate_frame`.
- Finding: arbitrary extra convention fields could hide claim terms.
  - Fix: metadata validation rejects unknown fields.

## Risk log

- DoD:
  - Reality condition, spin convention, coordinate frame, normalization,
    evaluator, storage, and shape metadata are enforced for OBSSTAT alm export.
  - Invalid or missing convention metadata blocks feature export.
- Kill switch:
  - Harmonic coefficients must not be accepted without channel-local convention
    metadata.
- Residual risks:
  - The registry stores conventions and validates payload shape; it does not
    compute alms, validate maps, or compare to a native low-ell morphology atlas.
  - `spin_output_convention` intentionally records no E/B sign export for this
    PR because the checked healpy API page does not specify enough semantics to
    promote that claim.
  - Transfer-derived alm payloads still need PR-014 transfer metadata through
    the existing OBSSTAT transfer gate; convention metadata is not a transfer
    source.
