PR-050 signed `x_C` `DepartureBundle` with the PR-051 explicit denominator

## Chosen plan

- Add `NumeratorPolicy` with explicit `signed`, `absolute`, and
  `positive_part` modes.
- Add frozen `NormalizedScore` that requires:
  - a PR-050 `DepartureBundle`;
  - a PR-051 `BudgetSpec`;
  - `BudgetUse.SIGNED_PROJECTION_NORMALIZATION`;
  - matching comparator, frame, and units;
  - MIO owner, `mio` implementation scope, and `diagnostic_only` claim tier;
  - non-empty config/input hashes, deriving a stable Q config hash when no
    caller-specific Q hash is supplied.
- Serialize a Q payload with explicit numerator policy, denominator policy,
  denominator use, score kind, `x_C`, numerator value, Q value,
  comparator/frame/units, sky/covariance/null status, config/input hashes,
  and separate departure/budget transfer provenance.
- Do not serialize raw budget admissible-use lists into Q payloads, because
  PR-051 budgets can carry future certified-F use metadata that Q must not
  present as its own artifact language.
- Reject Q score labels, caveats, and artifact metadata that use F-style,
  inference, class-label, or solver-result wording.
- Export the new API from `mio.formalism` and add MIO boot-smoke coverage.

Alternatives rejected: updating legacy COMMON normalized-score skeletons,
placing Q in HTT posterior code, adding F/Pi/G_F fields early, clipping signed
Q to a physical interval, or accepting raw denominator floats.

## Review findings and fixes

- Finding: Q payloads must not leak future certified-F use vocabulary from
  admissible budget uses.
  - Fix: Q records the selected denominator use only
    (`signed_projection_normalization`) and does not serialize raw budget
    admissible-use lists.
- Finding: Q serialized budget labels and assumptions without scanning them
  for reserved F-style wording.
  - Fix: Q now scans serialized `BudgetSpec` denominator labels and
    assumptions and rejects reserved Q metadata terms before payload export.
- Finding: Q metadata and caveats missed prose forms of family/class-label and
  solver-result overclaims.
  - Fix: the reserved phrase list now covers family-identification,
    family-classification, class-label, solver-result, and
    external-transfer-as-native wording; focused tests lock those cases.
- Finding: Q could drift into legacy HTT/Common semantics if built from older
  normalized-score or posterior-pushforward paths.
  - Fix: the new contract requires `DepartureBundle` and `BudgetSpec` and
    lives only under `mio.formalism`.
- Finding: transfer-derived numerator and denominator paths can be
  accidentally mixed.
  - Fix: Q preserves separate departure/budget transfer metadata and rejects
    mismatched non-`none` transfer sources or mismatched transfer spec IDs when
    both inputs carry transfer specs.
- Finding: status artifact regeneration initially failed on YAML syntax.
  - Fix: replaced the colon in the plain status note and reran both generated
    artifact commands successfully.

## Claim-tier impact

This PR adds a MIO L2 diagnostic-only normalized-score contract for Q. It is a
pre-solver policy-normalized scalar diagnostic over `x_C` and an explicit
denominator policy. It does not implement certified F, Pi, G_F, HTT posterior
pushforward, HTT evidence, MIO certificates, native solver output, transfer
validation, morphology compatibility, or geometry/family-identification
evidence.

- owner: MIO
- implementation_scope: mio
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- transfer_source: none by default; external-transfer budget/bundle inputs
  keep PR-014 metadata and remain transfer-conditional
- sky_support_status: inherited from `BudgetSpec`; default `not_directional`
- null_mock_status: inherited from `BudgetSpec`; default `not_statistical`
- covariance_status: inherited from `BudgetSpec`; default `not_statistical`
- ppc_status: not_applicable
- loocv_status: not_applicable

## Risk log

- DoD:
  - Q carries explicit numerator policy.
  - Q carries explicit denominator policy.
  - Q payload avoids F-style language even when the denominator can also serve
    future certified-F PRs.
- Kill switch:
  - Reject any Q label, caveat, or artifact metadata that names Q as a
    certified-F artifact, physical occupancy/filling quantity, HTT
    evidence/posterior, solver-result transfer, or class-label claim.
- Residual risks:
  - Q remains a scalar diagnostic; negative values and values above one are
    possible under explicit policy choices and do not by themselves imply
    physical admissibility, morphology compatibility, or family identity.
  - `BudgetSpec` still owns denominator-policy validity; Q only verifies the
    denominator is admitted for signed-projection normalization.
  - External-transfer Q payloads are transfer-conditional only.
