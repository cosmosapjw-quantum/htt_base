## Scientific and publication boundary

### Attended publication drift repair

The owner subsequently reproduced a delivery-policy drift: GitHub authentication,
repository rulesets, branch protection, and the established reviewed-PR workflow
allowed ordinary review PRs, but PR-247's unattended default-deny rule had been
copied into PR-256 and later per-PR policies as an unconditional ban. The live
hook accepted no user-authorization input, every run plan required
`external_publisher_only`, and the repository supplied validation/nonce tools
but no callable transaction that actually pushed the sealed ref and created the
PR. This left an attended, explicitly authorized delivery in a dead-end state.

The repair preserves direct ordinary-agent denial and the stronger unattended
external-publisher default. PR-276 alone opts into a narrow
`attended_explicit_user` mode. The new serialized entrypoint:

- revalidates the exact candidate seal, registered independent review,
  latest-target integration, live PR inventory, target identity, policy bytes,
  exact PR title/body/base/head/draft state, and short-lived HMAC authorization;
- consumes a one-use nonce before mutation;
- creates the sole unused nonce ledger during authorization issuance, binds its
  path/device/inode/initial-ctime/zero-size identity into the HMAC, and exposes
  no execution-time ledger override;
- treats the exact sealed-SHA branch push as an internal step of the single
  semantic `CREATE_REVIEW_PR` action, not as a reusable push grant;
- refuses an existing mismatched remote head and verifies the post-push SHA;
- creates or verifies exactly one matching open review PR; and
- has no force-push, approval, merge, ruleset, data, or scientific action.

The attended lane honestly uses the current authenticated GitHub identity. It
is a current-turn owner-authorized procedural exception, not credential
isolation. Unattended execution cannot cache or replay it. Historical PR-247
and PR-256--275 policies and receipts remain byte-preserved.
