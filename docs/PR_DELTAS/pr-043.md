# PR-043 - Mock calibration harness for axis and direction claims

## Goal

- Owner: HTT
- Depends: PR-041, PR-042
- Level: L3
- Scope: pre-solver
- Risk: high

Replace self-attested axis mock adequacy with a report-backed directional
mock-calibration gate. Directional claims must record retention, directional
bias, coverage, and FPR metadata. Production-axis use must fail closed when
the calibration report is missing, hash-mismatched, or inadequate.

## Chosen plan

- Add frozen COMMON directional mock-calibration contracts:
  - `AxisMockCalibrationThresholds`;
  - `AxisMockCalibrationReport`;
  - `AxisMockCalibrationGateDecision`;
  - `build_axis_mock_calibration_report`;
  - `evaluate_directional_claim_mock_gate`.
- Compute a stable `sha256:` calibration hash from the full report payload.
- Record retention, directional bias and bias-tail, coverage, exact coverage
  and FPR event counts, Wilson intervals, raw and look-elsewhere adjusted FPR,
  scan-trial provenance, rank status, calibrated covariance status, null
  ensemble, detection rule, config/input hashes, full PR-040 sky-support
  metadata, sky/mask/scan hashes, caveats, generating command, git commit, and
  worktree state.
- Keep the report `diagnostic_only`; successful reports only raise the
  directional claim ceiling to `conditional`.
- Add a live HTT façade at `htt/htt/htt/nulls/axis_nulls.py`.
- Require `mock_calibration_report` in `evaluate_axis_promotion` and
  `require_axis_for_harmonic_synthesis`, with report hash and null status
  matched to `AxisPromotionRecord`.
- Thread the report through `restore_full_a2m` so later harmonic restoration
  cannot bypass PR-043.

Alternatives rejected: implementing the stale `htt/src/htt` path, accepting
bare `adequate` strings as sufficient, reusing scalar HTT null-runner FPR as
directional calibration, or promoting reports to posterior/evidence semantics.

## Review findings and fixes

- Finding: production-axis promotion accepted a matching
  `AxisPromotionRecord` without a concrete calibration payload.
  - Fix: `evaluate_axis_promotion` now requires an
    `AxisMockCalibrationReport` for conditional production-axis use and blocks
    missing reports above diagnostic-only.
- Finding: a forged `mock_calibration_hash` could remain hidden if the record
  and report were not compared directly.
  - Fix: promotion now compares the record hash to the full report payload hash
    and compares null mock status.
- Finding: zero-success mock banks could raise while building interval
  metadata instead of producing a blocked report.
  - Fix: zero-success reports serialize with intervals widened to `[0, 1]` and
    fail closed through normal blockers.
- Finding: the PR card names a stale file path under `htt/src/htt`.
  - Fix: the live HTT package path `htt/htt/htt/nulls/axis_nulls.py` is used,
    matching PR-041 and PR-042 package roots.
- Finding: the old PR13AJ synthesis lock could bypass the new report argument.
  - Fix: `restore_full_a2m` now passes `mock_calibration_report` into the
    harmonic synthesis gate.
- Finding: coverage uncertainty was recorded but not fail-closed.
  - Fix: the coverage Wilson interval must now fit inside the configured
    coverage window; the point estimate alone is insufficient.
- Finding: covariance status was fail-open.
  - Fix: production-axis calibration now accepts only calibrated directional
    mock covariance statuses.
- Finding: rank and null-space gates were too loose.
  - Fix: the default gate now requires full three-dimensional response rank and
    zero null-space dimension for conditional production-axis use.
- Finding: look-elsewhere adjustment was caller-asserted.
  - Fix: reports now require `scan_trial_count` and `scan_trial_hash`, and the
    look-elsewhere trial count must match the scan-trial count.
- Finding: coverage/FPR counts and bias-tail support were not explicit.
  - Fix: reports now require exact coverage and false-positive event counts
    plus `bias_direction_p95_deg`; inconsistent counts are rejected.
- Finding: transfer-source and sky-support metadata were too permissive.
  - Fix: PR-043 report and promotion metadata require `transfer_source="none"`
    until a real registry gate is wired, and report metadata must carry nested
    PR-040 sky-support fields rather than hashes alone.
- Finding: free-text report fields could carry reserved claim language.
  - Fix: report construction rejects family-identification, geometry,
    posterior/evidence, native-result, and truth-certificate wording in
    emitted free-text metadata.

## Claim-tier impact

PR-043 adds HTT-owned, diagnostic-only directional mock-calibration gate
metadata. A passed report can raise a directional axis claim ceiling to
conditional for production-axis gating, but the report itself remains
diagnostic-only and pre-solver.

- owner: HTT
- implementation_scope: htt
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- transfer_source: none by default
- sky_support_status: requires explicit PR-040 nested `SkySupport` metadata
  and matching hashes for production-axis use
- null_mock_status: `directional_null_mock_passed` or
  `directional_null_mock_failed`
- covariance_status: must be a calibrated directional mock covariance status
- ppc_status: not_applicable
- loocv_status: not_applicable

This PR does not create a production axis by itself, posterior evidence, MIO
certificates, native solver validation, transfer validation, morphology
compatibility, or geometry/family-identification evidence.

## Risk log

- DoD:
  - Directional claims record retention, directional bias, bias-tail, coverage,
    exact event counts, scan-trial provenance, and FPR.
  - Mock coverage gates production-axis promotion through a hash-matched report.
- Kill switch:
  - Missing or inadequate mock calibration blocks claims above diagnostic-only.
- Residual risks:
  - The report consumes caller-supplied mock metrics; it does not run a full
    production mock bank by itself.
  - Richer future null-ensemble calibration can still tighten thresholds, but
    current conditional gate use already fails closed on coverage intervals,
    calibrated covariance status, full-rank response, scan-trial provenance,
    exact event counts, and bias-tail metadata.
  - The live package path differs from the stale backlog card path and is
    documented here.
