- code_cartographer:
  - Steelman: put the active guard in `common.semantic_guards` so new
    COMMON-owned contract code can depend on it without importing TSC legacy,
    HTT inference, MIO certificate code, OBSSTAT features, or BASS adapters.
  - Attack: copying the existing TSC audit scanner would preserve old
    language ownership and miss the new PR-010/013/014 boundaries; putting the
    linter in docs tooling only would not give downstream code a reusable
    guard module.
- harness_engineer:
  - Steelman: provide a deterministic CLI with stable text/JSON output, clear
    exit codes, sorted traversal, missing-path handling, and pytest coverage
    for both module and command behavior.
  - Attack: a warning-only script or grep-style one-off check would violate
    the PR kill switch because forbidden production claims must fail.
- physics_stat_auditor:
  - Steelman: block the specific pre-native overclaim paths that could turn
    scalar summaries, direction coherence, low-ell feature norms, old TSC/Teff
    language, MIO diagnostics, or external transfer outputs into stronger
    claims than the current repo can support.
  - Attack: a broad word blacklist would create noise in negative guardrails
    and test fixtures while still failing to catch semantic phrases such as
    external-transfer/native conflation or MIO/HTT evidence merging.
- claim_gate_reviewer:
  - Steelman: encode rule families tied to claim boundaries and allow explicit
    negative/governance contexts so AGENTS, skills, and PR deltas can keep
    saying what is blocked.
  - Attack: suppressing all documentation or generated metadata would let
    production-facing captions and reports drift; scanning archives by default
    would instead drown new work in historical/provenance text that is not a
    production claim surface.
- regression_tester:
  - Steelman: use hostile examples as tests, include JSON metadata scanning,
    assert CLI exit codes, keep the exact PR-card command, and run adjacent
    ownership/transfer/obsstat/TSC guard suites.
  - Attack: testing only one banned phrase would leave the kill switch
    nominally present but brittle against the claim-drift modes this DAG is
    trying to stop.

## Chosen plan

- Add `common.semantic_guards.no_overclaim` with structured
  `ClaimLanguageRule` and `ClaimLanguageIssue` dataclasses, deterministic path
  traversal, JSON string-value scanning, archive/provenance skipping by
  default, and guardrail-context suppression for explicit negative language.
- Add `scripts/check_claim_language.py` as the PR-card CLI. It reports missing
  paths, returns 2 only when every requested root is missing, returns 1 on
  findings, and returns 0 for clean scans. `--dry-run` does not write files
  and still hard-fails forbidden production claims.
- Add `tests/contracts/test_claim_language_lint.py` to cover scalar-only
  family/geometry overclaims, direct geometry wording, TSC/Teff full-solver or
  full-polarisation language, MIO diagnostic promotion into posterior/evidence,
  external-transfer/native conflation, JSON metadata scanning, archive
  handling, text/JSON CLI output, missing roots, and no-write dry-run behavior.
- Reject alternatives that would make this a docs-only checker, TSC-owned
  legacy scanner, or warning-only grep harness.

## Claim-tier impact

scientific readiness evidence, native solver validation, transfer validation,

compatibility, or family-identification evidence. It carries no C5/C6 science
claim.

## Risk log

- DoD: blocks scalar-only geometry/family-identification production language.
- DoD: blocks TSC/Teff full-solver or full-polarisation production language.
- Kill switch: forbidden production claims return exit code 1; the linter is
  not warning-only.
- Residual risk: semantic regexes cannot prove every possible paraphrase.
  Future PRs should add rules from real findings rather than broadening into a
  noisy word blacklist.
- Residual risk: archive/provenance paths are skipped by default to keep active
  scans actionable. Use `--include-archives` for historical audits.
- Residual risk: JSON scanning reports flattened string-value line numbers,
  not original JSON source lines.
