## Entry and root cause

Implementation started from merged target
`cca54d95f0347cfa808d40c992437046b5dfc24c` in an isolated worktree. The exact
frozen 65-point, four-worker progressive node was reproduced before edits at
exit 1 after 1613.02 seconds with
`D_2 = 1.397179e17 microK^2`, a relative gap of `1.394e14`, and the
`astronomical` tier.

The first responsible production symbol was
`bass.spectrum.flrw_pipeline._los_and_wrap`. It divided an already computed LoS
transfer by `run.trace.seed_projection.projected_seed.amplitude`, a
constraint/shear projection quantity, instead of the configured linear
primordial curvature amplitude used by the Tier-B integrator. At `k=1e-3`, the
base path returned a raw transfer of `0.2498378171`, divided it by projection
amplitude `0.01389739205`, and inflated the returned amplitude to
`17.97731662`. The C_l assembly itself retained one `4 pi P_R` weighting and
one `T_CMB^2` to `microK^2` conversion; Doppler and neutrino feedback were not
the dominant defect.

## Implemented repair

1. `_los_and_wrap` now receives the same concrete linear primordial amplitude
   used to configure the per-k integrator. No spectrum path reads the
   constraint-projection amplitude as its normalizer.
2. Direct single-k execution resolves a callable once and reuses that exact
   float for both solve and LoS normalization.
3. Ordinary multi-worker grids resolve all `(k, amplitude)` pairs in parent
   k-order before process-pool creation. Both scalar and chunk workers receive
   only concrete floats, so stateful callable behavior no longer depends on
   worker partitioning.
4. Bias and target responses stay raw until subtraction, then divide exactly
   once by the parent-resolved target amplitude.
5. The linear-probe path likewise stays raw through subtraction and performs
   only its existing explicit probe-amplitude division.

The progressive guard, strict guard, 65-point grid, Planck-2018 species
fixture, worker count, pipeline and assembly configuration, D2 anchor, tier
thresholds, and C_l assembly were not changed. No static or Rust answer was
substituted.
