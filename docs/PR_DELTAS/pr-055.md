# PR-055 - G_F depth gap and log-gap robustness

## Goal

- Owner: MIO
- Depends: PR-053, PR-054, PR-040
- Level: L2
- Scope: pre-solver
- Risk: high

Add a MIO-owned diagnostic-only `G_F` / `log_g_F` depth-gap contract over
certified-F depth-bin summaries. The contract records explicit floor policy,
depth-bin metadata, covariance/null metadata, denominator-evolution split
fields, transfer provenance, and generation/worktree metadata.

This PR does not run or fake a native low-ell solver, calibrate p-values/FPR,
create HTT evidence/posterior content, create MIO certificate content, validate
transfer, establish morphology compatibility, or support global-tilt,
geometry, or family claims.

## Chosen plan

- Add `DepthBinMetadata` with explicit depth interval, bin assignment, sky/mask
  support, covariance metadata, null/mock metadata, denominator-evolution
  status, sample count, caveats, and recursive claim-language scanning.
- Add `DepthBinFRecord` to bind PR-053 `CertifiedFillingFraction` summaries to
  depth-bin metadata, requiring every budget to admit
  `BudgetUse.DEPTH_GAP_REFERENCE`.
- Add `IsotropyGap` and `build_isotropy_gap()` to emit MIO diagnostic-only
  `G_F`/`log_g_F` payloads with floor value/label/reason, raw/effective F,
  floor activation, denominator-evolution split fields, transfer comparability
  gates, config/input hashes, generating command, and git/worktree provenance.
- Export the new contract through `mio.formalism`, MIO boot imports, and
  package import smoke.

Rejected alternatives: raw unstabilized ratios, hidden clipping, p-values/FPR,
native solver adapters, HTT inference ownership, MIO certificate output, mixed
transfer comparisons, and scalar-to-tilt/geometry/family claim paths.

    metadata triggers the intended fail-closed validation.

  `G_F metadata`.

    specificity.

  metadata.
  - Fix: transfer-derived depth bins now require canonical matching

    source `transfer_spec_id`.
- Finding: denominator evolution was summarized only by means, while
  `F_Bayes` is the mean of sample-wise ratios.
  - Fix: the split payload now exposes sample-wise x_C, denominator, and F
    arrays and marks the mean summary as non-decompositional.

  - Fix: depth-bin metadata now uses controlled status vocabularies for
    covariance/null status and calibration status.
- Finding: the scalar-claim guard missed hyphenated wording and the checkpoint
  scoreboard could read as still unsatisfied.
  - Fix: claim scanning normalizes punctuation/hyphens, and the progress
    scoreboard records when a due checkpoint is satisfied by an artifact.

## Claim-tier impact

This PR adds MIO diagnostic-only depth-gap bookkeeping. `G_F` and `log_g_F`
are scalar depth-bin diagnostics over certified F summaries under explicit
floor and bin metadata policy. They are not posterior/evidence quantities,
p-values/FPR, MIO certificates, transfer validation, native solver results,
morphology compatibility, or geometry/family evidence.

- owner: MIO
- implementation_scope: mio
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- transfer_source: none by default; transfer-derived records require PR-014
  metadata, matching compared transfer source/spec IDs, and matching canonical
  transfer metadata hashes
- sky_support_status: required per depth bin
- mask_status: required per depth bin
- covariance_status: required controlled vocabulary and cannot be
  `not_statistical`
- null_mock_status: required controlled vocabulary and cannot be
  `not_statistical`
- ppc_status: not_applicable
- loocv_status: not_applicable

## Risk log

- DoD:
  - `G_F` and `log_g_F` handle floors explicitly.
  - Depth-bin covariance metadata and null/mock metadata are required.
  - Denominator evolution is split from numerator/F evolution in payloads.
  - `G_F` cannot be exported without depth-bin metadata.
- Kill switch:
  - `G_F` alone cannot trigger a global-tilt, geometry, or family claim.
- Residual risks:
  - PR-055 does not calibrate a null distribution, p-value, FPR, PPC, LOOCV,
    local-boost null, or survey/systematic null.
  - Downstream report cards must preserve `G_F` as one diagnostic block rather
    than collapsing x/Q/Pi/F/G into a headline score.
