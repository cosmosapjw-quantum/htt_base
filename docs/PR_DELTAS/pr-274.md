## Capability

PR-274 adds a fail-closed admission preflight for the six frozen candidate
input records in `PR274_CANDIDATE_INPUTS.yaml`. Admission requires:

- a non-placeholder source identity that is not merely the product name;
- an exact version-bearing release and non-empty license identity;
- an exact source/release/license triple registered against typed,
  hash-bound repository evidence bytes;
- complete acquisition outside the PR-151 background-only lane;
- explicit sky-support identity, directional convention, and covariance
  identity;
- regular non-symlink data, mask, and covariance files below the evaluated
  repository root with exact SHA-256 identities;
- every preregistered required field;
- `none_observer_side` transfer semantics in schema v1.

Transfer-dependent candidates are refused until a separately reviewed,
typed, non-native `TransferFunctionSpec` registry contract exists. A string
that merely names an external transfer is not registration evidence.

The frozen evaluation admits no candidate and deterministically emits
`NO_ADMITTED_DATA_PILOT`. It neither authorizes nor executes a pilot.

## Implemented change

1. Added immutable COMMON candidate, component-binding, decision, and report
   contracts with content identities and closed serialization.
2. Added exact frozen registry validation for date, scope, six candidate IDs
   in order, and per-candidate required fields.
3. Added semantic identity checks that prevent status-only promotion of
   missing source, release, license, sky-support, directional, or covariance
   metadata.
4. Added repository path confinement, parent/final symlink refusal,
   regular-file checks, and exact component hashes.
5. Added explicit refusal for product-name aliases, incomplete acquisition,
   PR-151 partial/background input, native transfer labels, and arbitrary
   unregistered transfer strings.
6. Added an OBSSTAT-owned facade and an HTT read-only future-eligibility
   consumer. No MIO, likelihood, posterior, evidence, or data-execution API is
   introduced.
7. Added deterministic build/check and portable focused, adjacent, and smoke
   runners.
8. Added a generated result carrying source identities, decision blockers,
   PR-151 semantics, allowed/forbidden uses, caveats, and the claim ceiling.
9. Added an initially empty typed data-identity registry. Populating it is a
   separate reviewed authority change; a `BOUND` status alone cannot create a
   registry row.
