# PR-092 - Morphological information gain report

## Goal

- Owner: COMMON
- Depends: PR-090, PR-091, PR-011
- Level: L3
- Scope: pre-solver
- Risk: medium

Add a COMMON-owned, manifest-backed, diagnostic-only MES information-gain
compositor that consumes already-gated PR-090 template-mean and PR-091
covariance/BiPoSH branch reports. The compositor reports separate
diag/template/cov/dyn rows, computes `I_morph = B_diag/B_final` only from
positive-finite, provenance-matched template/cov branch bounds, and prevents
invalid, blocked, or no-gain rows from being plotted or labeled as
improvements.

## Chosen plan

- Added `htt.statistics.mes_information_gain` with
  `MesInformationGainBranch`, `MesInformationGainReport`, and
  `build_mes_information_gain_report()`.
- The compositor accepts PR-090 `MesTemplateBoundResult` and PR-091
  `MesCovarianceBoundResult` wrappers and consumes only their gated
  `FullCovMESReport` branch outputs.
- The report revalidates positive-finite diagonal and branch bounds before
  exposing a ratio, binds source branch manifest config/input hashes to the
  aggregate report, fails closed on source provenance mismatch, and rejects
  corrupted positive-claim source reports with non-finite bounds.
- The report emits explicit `diag`, `template`, `cov`, and `dyn` rows.
  Template/cov rows can be `improvement`, `no_gain`, `no_claim`, or `missing`.
  Dyn remains `auxiliary_*` and is not a morphology-branch gain candidate.
- The report's manifest is COMMON, implementation scope `common`, claim tier
  `diagnostic_only` when at least one morphology branch is valid and `blocked`
  otherwise, transfer source `none`, with config/input hashes, source artifact
  ids, branch statuses, sky/mask/covariance/null status summaries, command,
  git/worktree state, and caveats.
- Corrected the stale PR-092 backlog path from
  `htt/src/htt/statistics/mes_information_gain.py` to
  `htt/htt/htt/statistics/mes_information_gain.py` across YAML, JSON, and
  markdown mirrors.

Rejected alternatives: fake native solver values, recomputing PR-090/091
branch physics, treating blocked fallback `information_gain=1` as morphology
gain, merging dyn with template/cov, adding HTT likelihood/evidence plumbing,
adding MIO certificate plumbing, and any geometry/family wording.

## Review findings and fixes

- Finding: the initial report design could allow a valid branch to survive
  even if another supplied branch had provenance mismatch.
  - Fix: any source owner/scope/transfer/config/input mismatch now blocks the
    aggregate morphology-gain report fail-closed; a mixed template-mismatch
    plus otherwise valid covariance branch regression covers this path.
- Finding: post-review found that source manifest failed gates could still
  produce `I_morph` if the wrapper's `synthetic_bound_available` flag was
  forged or stale.
  - Fix: source manifest `failed_gates` now always become branch no-claim
    reasons and block aggregate gain; a focused forged failed-gate regression
    covers this path.
- Finding: post-review found top-level `no_claim_reasons` included missing
  optional morphology branches and missing auxiliary dyn rows even when another
  morphology branch was valid.
  - Fix: missing optional/dyn reasons remain branch-local unless no valid
    morphology branch exists.
- Finding: post-review found invalid-bound coverage was too narrow.
  - Fix: added parametrized zero/negative/non-finite coverage for explicit
    diagonal, source diagonal, template/covariance branch bounds, and branch
    final bounds.
- Finding: PR-092 path mirrors still referenced the stale package root.

compositor. It is not scientific readiness evidence, native solver validation,
transfer validation, HTT posterior evidence, MIO diagnostic certificate
content, morphology compatibility, or geometry/family evidence. It carries no
C5/C6 science claim.
