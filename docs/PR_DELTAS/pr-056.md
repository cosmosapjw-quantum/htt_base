## Chosen plan

- Added `mio.reports.departure_report` as a report-card composer over existing
  validated formalism objects.
- Kept all score sections separate and exposed explicit `f_status`, `g_status`,
  per-section transfer provenance, manifest metadata, and status summaries.
- Rejected report-level combined-score/headline/rank, HTT inference, native
  validation, and geometry/family-ranking fields rather than trying to sanitize
  them later.
- Rejected raw dict report construction in favor of objects exposing
  `as_payload()`, preserving the typed formalism layer as the validation source.

## Review findings and fixes

- Finding: the test scaffold initially guessed older constructor names for
  x/Q/Pi/F/G helpers.
  - Fix: rewired fixtures to the existing `BudgetSpec`, `DepartureBundle`,
    `ExceedanceCurve`, `CertifiedFillingFraction`, and `IsotropyGap` APIs.
- Finding: the report could accidentally use a single transfer source summary
  while hiding score-specific provenance.
  - Fix: added `transfer_provenance_by_section` and only summarize as
    `mixed_by_section` when supplied sections differ.
- Finding: missing F/G could be read as zero or unavailable without context.
  - Fix: `f_status` and `g_status` emit explicit `not_provided` or
    `available` status records.
- Finding: arbitrary section payloads could carry reserved headline,
  inference, native, or geometry/family keys while still declaring
  MIO/diagnostic-only owner fields.
  - Fix: section payloads now receive recursive reserved-key/value scanning
    while preserving validated component caveats.
- Finding: report metadata exact-key guards did not catch variants such as
  posterior-probability or native-solver labels.
  - Fix: metadata keys now use normalized exact and pattern-based rejection,
    with tests for common variants.
- Finding: the repo-root `htt.mio.reports` alias is not an installable temp-CWD
  public surface.
  - Fix: package probes advertise and test `mio.reports.departure_report` only;
    repo-root `htt.mio` remains compatibility behavior, not PR-056 API.
