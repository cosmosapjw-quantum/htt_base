## 주요 설계 결정

### 1. MB-95 `camb_rhs:462-481` 을 primary oracle 로 직접 port

Sync-gauge metric 은 convention 혼재 위험 없음 (PR-022b 의 `collision_lm` 같은 bug 의심 경로 없음). MB-95 의 수식을 그대로 매핑:

```
MB-95                          ↔  PSTF (PR-023a)
─────────────────────────────────────────────────────────────
y[i_etak]                      ↔  state[i_metric_etak()]
y[i_sigma]                     ↔  state[i_metric_sigma()]
dgq (L466-469)                 ↔  pstf_momentum_constraint_dgq()
dgq = (4/3)·ρ·(4·Θ_1) + ...    ↔  dgq = (16/3)·ρ·Θ_1 + ... (algebraic)
etakdot = dgq/2 (L470)         ↔  etakdot (written to dy)
hdot = 2·k·σ − 6·etakdot/k     ↔  pstf_hdot() (algebraic, not in state)
sigmadot = −2ℋ·σ − dgs/k + etak↔  sigmadot (written to dy)
−hdot/6 (photon ℓ=0 coupling)  ↔  pstf_metric_monopole_source() export
```

G2 test 에서 각 formula 를 inline 으로 재구성하여 bit-identical 비교.

### 2. Metric block (11 DOF) 중 [0]=etak, [1]=σ 배치 확정

PSTF `LmLayout::n_metric = 11` 은 Bianchi I 의 Z_{ab} 대칭 tensor (3×3 symmetric = 6 DOF + 추가 1+3 covariant scalar들) 를 위해 예약됨. PR-023a 에서는 FLRW 극한 2 DOF (`etak`, `σ`) 만 활성화. `metric[2..=10]` 는 `caveat_metric_block_reserved_for_bianchi` test 로 zero 유지 보장.

이 배치는 PR-025 FLRW equivalence test 에서 MB-95 `CambLayout::i_etak/i_sigma` 와 1:1 매핑하기 쉽게 설계 — offset [0], [1] 은 MB-95 의 `i_etak = 0`, `i_sigma = 1` 과 동일한 순서.

### 3. `v_b` dependency 처리

Metric RHS 의 `dgq` 는 baryon v_b 를 read 해야 함. PR-023a 는 fluid RHS 를 포함하지 않으므로 (PR-023b scope), `v_b` 를 **함수 parameter** 로 받음:

```rust
pub(crate) fn pstf_metric_rhs(state, dy, v_b: f64, inputs, layout)
```

Test 에서는 state[baryon_start + 2] 를 직접 주입. PR-023c dispatcher 에서는 state 에서 read 하여 전달.

이 interface 결정은 **sub-track 간 coupling 을 명시적으로** 드러냄 — fluid sector 와 metric sector 가 서로 의존하나 구현 시 분리 가능하다는 점을 API 레벨에서 표현.

### 4. Additive accumulation (PR-022 pattern 계승)

`pstf_metric_rhs` 는 `dy[i_metric_etak] += etakdot`, `dy[i_metric_sigma] += sigmadot` 형태로 additive. PR-022a/b/c 와 동일 pattern — PR-023c dispatcher 에서 모든 sector 를 순차적으로 composable.
