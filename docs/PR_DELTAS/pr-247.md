## Scope and reproduced failures

The supplied Universal PR Guard archive was treated as an unauthenticated
input snapshot, inspected without extraction into the repository, and adapted
rather than copied. Its SHA-256 is
`c7d7f28e77c37603db8c5fdbffe43a7912a57a78fa9002e036dc8b4f2b44c199`.
Read-only probes reproduced command-classifier bypasses, an arbitrary
`true`-style integration receipt, change-set aliases, remote drift, replayable

The repository audit then reproduced further transitive-integrity failures:
freezing a run invalidated mutable implementer assignments; authorization used
a movable branch source; integration logs and merge trees were not
recomputed; PR inventory admitted missing metadata, incomplete file lists,
duplicate heads, aliases, and stack cycles; booleans could enter integer
budgets; JSON admitted duplicate keys or non-finite numbers; runtime paths,
external secrets, and nonce ledgers needed stronger path and hard-link
controls; and the live `--repo-slug` query was not bound to the Git remote
identity.
The final subprocess-path audit also reproduced an integration-policy command
that could invoke publication beneath the provider hook; policy loading now
rejects publication-capable argv before rehearsal.
Executing the exact tracked policy then exposed a deterministic environment
blocker: bare `/usr/bin/python3` had no pytest. The policy now uses a portable
`{python}` token. Candidate-A review then exposed that resolving a venv
launcher symlink before execution silently selected bare Python again. The
rehearsal now preserves the absolute invocation path, separately records the
resolved binary path, and hashes the binary bytes.
Candidate-B review then supplied an executable provider-protocol oracle. The
current Antigravity hook documentation uses
`toolCall.name`/`toolCall.args`, while Google's secure-agentic-coding codelab
uses the older top-level `tool_args.CommandLine` shape. The adapter now accepts
only one recognized envelope at a time, inspects both documented forms, and
denies missing, malformed, mixed, ambiguous, or unmatched-tool envelopes
fail-closed. Current nested calls receive the documented decision JSON; legacy
top-level calls use the codelab's nonzero-exit denial contract. The installed
hook registration continues to follow the current official hooks schema.
Remote userinfo was also rejected so a credential-bearing URL cannot be copied
into the seal or authorization.

Three registered mapping/threat audits ran under
`pr247-publication-integrity-p0-20260726`, returned 19 unique preliminary
findings with no conflicts, and were closed. They are implementation input,
not a frozen-candidate review.

## Implemented P0 boundary

- Internal `work_unit_id`, coherent `change_set_id`, and sole
  `publication_group_id` are distinct. One failure type produces a finding or
  commit; it does not create a GitHub PR.
- Schema-v2 run plans and schema-v3 assignments/results bind the change-set and
  candidate state. Implementers operate only while mutable; reviewer and
  adjudicator assignments require a committed, clean, frozen candidate.
- The candidate seal recomputes the exact remote target, base, candidate,
  merge-base, tree, ordered commit set, binary diff, changed-file set,
  integration policy, remote URLs, and canonical GitHub host/repository.
- Review coverage is a machine-readable 13-cell matrix. `FAIL` and `WAIVED`
  block readiness; R2/R3 require at least one executable, artifact-bound
  oracle. Same-model repetition is recorded as correlated review.
- Latest-target integration uses a temporary detached worktree, the exact
  policy argv, recomputed merge tree, return codes, timestamps, and
  hash-checked stdout/stderr logs.
- The live inventory binds the queried GitHub repository to the sealed remote,
  rejects duplicate-key/non-finite JSON, incomplete file lists, missing
  metadata, file overlap, duplicate change-set/group/head, stack cycles, stale
  observations, and PR budgets.
- Authorization binds the repository identity, push URL, sealed candidate SHA,
  SHA-sourced refspec, exact PR title/body/base/head/draft state, four evidence
  files, bounded time, and a one-use nonce stored outside the workspace.
  `pr_publication_gate.py` only validates and consumes authorization; it never
  publishes.
- Codex, Claude Code, and Antigravity repository hooks deny ordinary-agent
  shell and GitHub mutation paths. They are explicitly guardrails, not the hard
  capability boundary. The hard boundary remains administrator-managed policy
  or network isolation plus publisher credentials unavailable to agent
  sandboxes.
- Normal unattended completion produces local commits, a candidate/report
  bundle, and zero GitHub PRs.

Provider hook shapes were checked against the current official documentation:
[Codex hooks](https://learn.chatgpt.com/docs/hooks),
[Claude Code hooks](https://code.claude.com/docs/en/hooks), and
[Antigravity hooks](https://antigravity.google/docs/hooks), plus Google's
[secure-agentic-coding codelab](https://codelabs.developers.google.com/secure-agentic-coding?hl=en)
for the legacy Antigravity envelope still shown there.
