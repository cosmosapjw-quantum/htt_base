# PR-073 - Morphology axes and alignment features

## Goal

- Owner: OBSSTAT
- Depends: PR-071, PR-042
- Level: L2
- Scope: pre-solver
- Risk: high

Add OBSSTAT-owned diagnostic morphology-axis and alignment features while
keeping diagnostic axes separate from HTT production axes. This PR packages
feature descriptors and null/look-elsewhere metadata only; it does not create
HTT evidence, MIO certificates, transfer validation, native solver output,
morphology compatibility, or geometry/family-identification evidence.

## Chosen plan

- Add `MorphologyNullCalibration` for morphology p-values with null ensemble,
  look-elsewhere status, tail definitions, mock count, covariance/mask status,
  scan volume, and trial count.
- Add `DiagnosticMorphologyAxis` as an OBSSTAT local diagnostic axis record,
  not a production axis type. Its `to_preferred_axis()` adapter always returns
  a COMMON `PreferredAxis` with `production_allowed=False`.
- Add `MorphologyAxisSummary` and `summarize_morphology_axes()` to extract
  principal and plane-normal antipodal axes from a caller-supplied finite
  symmetric 3x3 morphology tensor.
- Record eigenvalues, eigenvalue gaps, degeneracy tolerance, response rank,
  effective rank, null-space dimension, condition metadata, planarity
  descriptors, alignment features, config/input hashes, definitions, and
  caveats.
- Preserve the existing OBSSTAT `ObservableVector` firewall by routing the
  payload through `morphology_features`, rejecting overclaim text before
  serialization, and keeping `transfer_source="none"`.
- Update OBSSTAT exports and package alias tests for
  `htt.obsstat.morphology` and top-level `obsstat.morphology`.

Alternatives rejected: accepting raw production-axis fields, computing or
mocking a native morphology atlas, claiming transfer-dependent morphology
compatibility, or using p-values without null/look-elsewhere metadata.

## Review findings and fixes

- Finding: missing `tail_definitions` produced a raw constructor `TypeError`.
  - Fix: `tail_definitions` defaults to an empty mapping so domain validation
    raises a targeted `ValueError`.
- Finding: the default morphology null caveat contained an inference-shaped
  word and was rejected by the module's own free-text guard.
  - Fix: reworded the caveat to neutral `not HTT model output` language.
- Finding: package alias checks covered the scalar module's last import order
  only.
  - Fix: tightened the scalar loop while adding the morphology alias identity
    check.
- Finding: degenerate eigenspaces still produced precise-looking alignment
  angles from arbitrary eigenvectors.
  - Fix: alignment features now suppress angle/dot values when the relevant
    morphology axis is degenerate and record gap/tolerance caveats instead.
- Finding: matrix rank was mislabeled as a response-rank audit.
  - Fix: payload now separates `tensor_rank`,
    `axis_identifiability_rank`, and `axis_identifiability_status`.
- Finding: singular tensors hid condition information by emitting only a null
  condition number.
  - Fix: payload now records explicit `condition_status` values for finite,
    singular/rank-deficient, and zero-tensor cases.
- Finding: the original planarity ratio measured top-axis separation, not
  planarity.
  - Fix: payload now separates `axiality_ratio` from `planarity_ratio`, with
    planarity tied to the middle-low eigenvalue gap.
- Finding: morphology p-value metadata was too easy to spoof.
  - Fix: p-value keys must be known morphology diagnostics, mock count must be
    at least 100, scan volume must carry targets, statistic keys, trial count,
    and global/local status, and supplied p-value keys must match available
    summary features.
- Finding: public diagnostic-axis constructors could serialize
  posterior/native-looking source fields.
  - Fix: `DiagnosticMorphologyAxis` now requires
    `source="raw_diagnostic"`, `weight_mode="uniform_fallback"`, and
    `selection_mode="none"`.
- Finding: morphology payloads could serialize placeholder config/input
  provenance.
  - Fix: `MorphologyAxisSummary` now rejects placeholder config hashes and
    empty or placeholder input hashes.

## Claim-tier impact

This PR adds OBSSTAT diagnostic feature extraction and payload metadata only.
It does not add a solver, transfer calculation, HTT model input, MIO output,
native validation, morphology-compatibility output, or geometry/family claim.

- owner: OBSSTAT
- implementation_scope: obsstat
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- statistic_role: feature_only unless explicit null calibration is supplied
- model_role: not_model_input
- transfer_source: none
- sky_support_status: carried by the consuming `ObservableVector` manifest and
  unchanged by this morphology module
- null_mock_status: absent for feature-only payloads; required metadata for
  null-calibrated morphology p-value payloads
- covariance_status: required only when null-calibration p-values are supplied
- ppc_status: not_applicable
- loocv_status: not_applicable

## Risk log

- DoD:
  - Alignment and planarity features separate diagnostic axis from production
    axis.
  - Look-elsewhere metadata is supported for morphology p-values.
- Kill switch:
  - Reject if a morphology axis can bypass the PreferredAxis gate.
- Residual risks:
  - The tensor is caller-supplied and pre-solver diagnostic input. This module
    does not compute alms, BiPoSH morphology, or a native low-ell morphology
    atlas.
  - Degenerate tensors still serialize diagnostic metadata, but axis status is
    flagged as degenerate and the adapter remains non-production.
  - Null-calibrated p-values are metadata-bearing diagnostic features only.
    Full null ensemble generation and broader look-elsewhere bookkeeping remain
    later DAG work.
