## Design

### `PstfFlrwLayout`

FLRW-specialized wrapper over `LmLayout`:

```rust
pub(crate) struct PstfFlrwLayout {
    pub(crate) inner: LmLayout,                // full (ℓ,m) layout, reused
    pub(crate) ell_max_gamma: usize,
    pub(crate) ell_max_nu: usize,
    pub(crate) ell_max_pol: usize,             // 0 (off) or ≥ 2 (on)
    pub(crate) n_state: usize,
}
```

**m=0 primitive accessors**:
- `i_photon_i_m0(ell)` — photon intensity, ℓ ≥ 0
- `i_photon_e_m0(ell)` — E-mode, ℓ ≥ 2 (requires `has_pol()`)
- `i_photon_b_m0(ell)` — B-mode, ℓ ≥ 2 (requires `has_pol()`)
- `i_neutrino_m0(ell)` — massless ν, ℓ ≥ 0

### `validate()` — FLRW invariants

4 hard assertions:
1. `ell_max_gamma ≥ MIN_LMAX_G` (= 3, `core::ssot::constants`)
2. `ell_max_nu ≥ MIN_LMAX_G`
3. `ell_max_pol == 0` or `ell_max_pol ≥ MIN_LMAX_POL_WHEN_ON` (= 2)
4. `n_state == inner.total_dof`

`has_pol()` semantics parallel `CambLayout::has_pol()` — cross-formalism 일관성 보장.

### Reference coefficients (helpers)

```rust
pub(crate) fn mb95_down_coefficient(ell: usize) -> f64  // ℓ / (2ℓ+1)
pub(crate) fn mb95_up_coefficient(ell: usize) -> f64    // (ℓ+1) / (2ℓ+1)
```

**삭제된 helper**: `flrw_norm_ratio_down` — 초기 설계에서 PSTF/MB-95 FLRW normalization 을 단순 (2ℓ+1)/(2ℓ−1) 비율로 encode 하려 했으나, **ℓ=1 에서 factor-9 error** 로 실패. 올바른 FLRW equivalence 는 PR-025 의 subject. 해당 helper 는 제거하고 주석 블록에 "자명하지 않음" 을 명시.

## Pre-audit risks — 실증 결과

`pr-020-design.md §8` 에서 명시한 4 위험 중 1 건이 **실제로 발현**:

- 🟢 `src/pstf/` test 통과 상태 확인 → 130/130 PASS ✅
- 🟢 Collision operator 재유도 필요 → PR-022 로 이관 (scope 밖)
- 🔴 **Metric sector 대응 — "code 로 옮길 때 sign/factor 주의"** → 예상대로 normalization 이슈 발생. 초기 `flrw_norm_ratio_down` 이 factor-9 error 를 일으켜, helper 자체를 삭제하고 PR-025 로 이관. Pre-audit 경고가 올바르게 작동.
- 🟡 FLRW equivalence tolerance ±0.5% → PR-025 에서 실측 예정

이 한 번의 pre-audit 경고 → 실증 → 조기 scope 축소는 big-bang 재작성 회피의 효용 을 예증. 만약 PR-020 이 더 큰 scope (예: RHS 포함) 였다면 같은 normalization 오류가 훨씬 깊은 자리에서 발현했을 것.
