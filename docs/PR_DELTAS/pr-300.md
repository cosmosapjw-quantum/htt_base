# PR-300 — one-command observed-program readiness

## Scope

This PR repairs the PR-299 PPC consumer-plan admission bug and adds exactly one
manual dispatcher for the seven canonical PR-279 observed-data runbooks. It is
not an observed-data run, does not open any payload, and writes no scientific
result.

## One command

```bash
PYTHONPATH=htt/src:htt/htt venv/bin/python -B \
  scripts/codex_harness/run_authorized_observational_program.py --execute-authorized
```

The command first performs an all-lane preflight. It invokes no entrypoint
unless every canonical lane has a checked-in execution entrypoint, terminal
dependencies, and its own current human authorization. `--check` prints the
same machine-readable plan without dispatching anything.

## Current outcome

All seven lanes are `BLOCKED`. In particular, PR-151 is
`INVALIDATED_PENDING_FORMALISM_REVALIDATION`; its old runner and deleted output
cards are not reusable. The remaining lanes lack their future post-275
integration entrypoints and/or prerequisites and authorizations. This is an
observable readiness result, not a scientific result.

## Claim and process watchdog

- Claim tier: `diagnostic_only`; `observed_data_executed=false`.
- Transfer: no transfer output is loaded or relabeled.
- Drift: one dispatcher and one focused test; it consumes existing canonical
  runbooks and PR cards rather than adding a second program registry.
- Decision: `STOP_PROCESS_ASSURANCE_INFLATION` if a further wrapper does not
  eliminate a concrete missing-entrypoint or authorization failure.
- Falsifier: any blocked lane causes a subprocess invocation, or a duplicate,
  reordered, stale, or unknown PPC plan reaches `READY`.
- Next action: implement the individual missing post-275 lane entrypoints only
  in their named scientific PRs, then rerun this command manually after the
  required human receipts exist.
