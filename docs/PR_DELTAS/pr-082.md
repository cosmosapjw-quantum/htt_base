# PR-082 - AtlasEntryLite and transfer side-by-side comparison schema

## Goal

- Owner: BASS_PY
- Depends: PR-080, PR-081, PR-070
- Level: L2
- Scope: pre-solver
- Risk: medium

Add a BASS_PY metadata-only AtlasEntryLite comparison schema under the live
`htt/bass/atlas` package. The schema lets current external/proxy transfer
entries and future native schema-only entries coexist side by side while
preserving transfer provenance and blocking atlas membership from being used as
observed data, posterior/evidence, MIO certificate input, native solver output,
or family-identification evidence.

## Chosen plan

- Add `bass.atlas.AtlasEntryLite`, a frozen metadata-only BASS atlas row that
  stores transfer metadata, comparison group, config hash, input hashes,
  generating command, worktree state, caveats, and a deterministic entry hash.
- Add `AtlasTransferComparison`, a side-by-side collection that requires at
  least one external/proxy transfer entry and one future native schema entry.
- Add constructors from `TransferFunctionSpec` and `TransferRegistry` plus
  `build_default_transfer_side_by_side_comparison()` using PR-080 external
  transfer specs and PR-081 native low-ell schema specs.
- Enrich bare external `TransferFunctionSpec.to_metadata()` records with
  explicit atlas-side `claim_tier="conditional"`,
  `production_status="diagnostic_only"`, `transfer_conditional=true`, and
  `native_solver_result=false`.
- Preserve PR-081 native schema-only flags:
  `schema_status=schema_only_no_solver_output`, `returns_values=false`,
  `outputs_available=false`, and `consumable_as_result=false`.
- Add fail-closed `to_observed_data()`, `to_posterior_input()`, and
  `to_evidence_input()` methods that raise instead of converting atlas
  membership into data or inference input.
- Require callers of the default comparison builder to provide explicit
  `git_commit_or_worktree_state`; no placeholder worktree state is emitted.
- Export `bass.atlas` and add package import coverage.

Alternatives rejected: evaluating external transfer callables inside the atlas
constructor, calling the native adapter stub, creating a fake native value,
changing the canonical COMMON AtlasEntryLite contract in this PR, or allowing
atlas membership to stand in for observed data, HTT evidence, MIO certificate
content, not morphology compatibility, and not family identification.

## Review findings and fixes

- Finding: `entries_from_transfer_registry` was implemented but not exported
  from `bass.atlas`.
  - Fix: added the symbol to `htt/bass/atlas/__init__.py`.
- Finding: bare PR-080 `TransferFunctionSpec.to_metadata()` records do not
  contain adapter-level claim fields.
  - Fix: `AtlasEntryLite` enriches external/proxy metadata with explicit
    conditional, diagnostic-only, transfer-conditional, and non-native flags.
- Finding: legacy COMMON `AtlasEntryLite` remains too thin to enforce PR-082
  side-by-side transfer semantics.
  - Fix: PR-082 adds a narrower BASS atlas metadata schema without changing
    the COMMON contract in this PR.
- Finding: an atlas comparison with only external entries would satisfy a weak
  constructor but not the PR DoD.
  - Fix: `AtlasTransferComparison` requires both external/proxy and future
    native schema entries.
- Finding: active-role metadata keys could smuggle posterior/evidence meaning.
  - Fix: transfer metadata validation rejects active observed-data and
    inference role keys unless explicitly non-consumable.
- Finding: persisted metadata validation did not re-check top-level native,
  data, inference, MIO, HTT, and family-role fields after serialization.
  - Fix: `validate_atlas_entry_lite_metadata()` now rejects tampered
    top-level native-output, observed-data, posterior, MIO-certificate, HTT
    evidence, and family-identification roles.
- Finding: future native schema metadata could still include nested
  value-bearing fields while setting `returns_values=false`.
  - Fix: native schema metadata now rejects value-like solver and observable
    payload keys such as `values`, `alm_T/E/B`, `cl`, `BiPoSH`, and map fields.
- Finding: MIO certificate semantics were not part of the active-role scanner.
  - Fix: certificate/certification terms now fail closed unless explicitly
    marked as non-consumable or negative guard metadata.
- Finding: the default comparison builder used a placeholder worktree-state
  string.
  - Fix: `git_commit_or_worktree_state` is now required by the default builder.
- Finding: external/proxy transfer metadata used defaults that could preserve
  caller-supplied stronger claim/status overrides.
  - Fix: external/proxy entries now require `claim_tier="conditional"`,
    `production_status="diagnostic_only"`, `transfer_conditional=true`, and
    `native_solver_result=false`.
- Finding: raw future-native schema mappings could spoof native validation
  with `calibration_status="native_validated"` or validation gates.
  - Fix: future-native schema entries now require
    `calibration_status="native_provisional"` and no passed validation gates.
- Finding: family-identification and morphology-compatibility phrases were
  not blocked unless they also contained observed-data or inference terms.
  - Fix: transfer metadata and custom caveats now reject active family,
    geometry, morphology-compatibility, ranking, and native-validation phrases
    unless the phrase is explicitly downclaimed or blocked.

## Claim-tier impact

This PR adds BASS_PY atlas comparison metadata only. It does not run a solver,
load a solver artifact, evaluate external transfer callables, generate native
values, validate native transfer, create HTT evidence, create MIO certificate
content, or support morphology compatibility or family-identification claims.

- owner: BASS
- implementation_scope: bass_py
- pr_scope: pre-solver
- claim_tier: diagnostic_only for AtlasEntryLite comparison metadata
- external_transfer_claim_tier: conditional on embedded PR-080 external/proxy
  transfer metadata
- future_native_claim_tier: diagnostic_only/schema_only on embedded PR-081
  native schema metadata
- production_status: diagnostic_only
- transfer_source: AniCLASS_external, empirical_proxy, or
  BASS_native_provisional depending on entry
- atlas_membership_role: metadata_only_side_by_side_transfer_reference
- native_solver_result: false
- returns_values: false for future native schema metadata
- outputs_available: false for future native schema metadata
- consumable_as_result: false for atlas entries and future native schema
  metadata
- consumable_as_observed_data: false
- consumable_as_posterior: false
- sky_support_status: not_directional
- null_mock_status: not_statistical
- covariance_status: not_statistical

## Family-identification gate verdict

## Requested claim tier

PR-082 requests L2 pre-solver schema/provenance work, not family
identification.

## Allowed claim tier

Atlas comparison metadata is diagnostic-only. Embedded external/proxy transfer
metadata remains conditional. Embedded future native metadata remains
schema-only and non-consumable. No C5/C6 claim is made.

## Missing gates

Native low-ell morphology atlas, real native solver artifact values,
null/mask/covariance gates, equivalence-class graph, response-rank audit,
PPC/LOOCV for HTT inference, and MIO diagnostic cross-check without posterior
merge.

## Equivalence-class risks

The `family` field on transfer metadata is provenance only. It does not rank,
identify, or break Bianchi family equivalence classes.

## Transfer/source risks

External/proxy transfer remains external or empirical proxy. Future native
schema entries remain no-value and non-consumable until a real external solver
artifact and validation gates exist.

## Required downclaim or next PR

Downclaim to `AtlasEntryLite side-by-side transfer provenance schema`. PR-083
may build budget-ceiling policy interfaces on this schema, but it must keep
transfer source and admissible-set provenance explicit.

## Risk log

- DoD:
  - External/proxy and future native schema AtlasEntryLite entries coexist in
    a single `AtlasTransferComparison`.
  - Atlas membership is metadata-only and not empirical data or posterior.
- Kill switch:
  - `to_observed_data()`, `to_posterior_input()`, and `to_evidence_input()`
    raise; metadata validators require non-consumable atlas roles.
- Residual risks:
  - The new schema does not attach real native solver artifacts or values.
  - Future PRs must not treat side-by-side metadata as a numeric external-vs-
    native validation comparison until native outputs and validation gates
    exist.
  - The older COMMON `AtlasEntryLite` remains for legacy/shared contract
    consumers; PR-082 does not migrate all downstream atlas users.
