## Implemented changes

1. Added `OrbitCatalogueV2Spec` and factory-only
   `OrbitCatalogueV2Report` for the typed representation
   \(V_2^\sigma\oplus V_{1,\mathrm{axial}}^\omega\oplus
   V_{1,\mathrm{polar}}^\beta\).
2. The frozen catalogue contains exactly twelve degree-bounded polynomials:
   five even sigma/beta polynomials, one reflection-odd beta Krylov
   determinant, three even omega polynomials, and three reflection-odd mixed
   beta/omega polynomials. The four odd quantities are explicitly
   pseudoscalars, not O(3) invariants.
3. Every report numerically checks the trace-free three-dimensional
   Cayley–Hamilton matrix identity, its beta-beta, omega-omega, and
   beta-omega contractions, and the beta Krylov Gram-determinant syzygy.
4. `generic_orbit_separation_status` and
   `degree_completeness_status` are forced to `UNPROVEN`. The exact
   `beta=0`, generic `omega` versus `-omega` witness preserves identical
   catalogue values for distinct states and prevents finite-vector tests from
   promoting a complete-catalogue claim.
5. Added exact OBSSTAT intervention types for:
   - nonlinear \(m^2\) phase;
   - one common proper \(z\)-axis rotation;
   - scalar parity \(a_{\ell m}\mapsto(-1)^\ell a_{\ell m}\).
   Each `intervention_id` is now a factory-derived content identity over the
   exact factor, operator, and hexadecimal floating-point angle semantics; it
   is not a caller-supplied receipt.
6. Identity and common-rotation phase angles are rejected. Scalar parity does
   not admit an added rotation and does not claim a T/E/B convention.
7. `LowEllMorphologyFeaturePacket` binds the dense real-field \(a_{\ell m}\),
   exact selected multipoles, \(C_\ell\), power tensors, a factory-derived
   signed scalar-BiPoSH vector, harmonic convention, typed anchor identity and
   stress interval, frame, mask, beam, and foreground identities. Available
   feature blocks retain the exact source-\(a_{\ell m}\) content identity.
8. `MatchedCounterpairReport` replays the exact registered coefficient action,
   requires one byte-for-byte identical registered \(C_\ell\) tuple, separately
   checks each packet's coefficient-derived power within the declared numerical
   tolerance, requires corresponding feature provider/configuration identities
   to remain fixed, and reports which available feature blocks separate the
   pair. Caller-supplied BiPoSH vectors are rejected.
9. Directional-wavelet and T/E/B cross-morphology providers remain
   `MISSING_FEATURE_PROVIDER`. A missing block cannot carry values, including
   zeros, and the availability mask is frozen in the protocol before scoring.
10. Added a factory-only HTT benchmark contract for nine fixed
    representations. Seven are available; the two missing providers remain in
    the fixed family rather than being removed after scores are seen.
11. Available representations must share one parameter label, normalizer,
    baseline observable, transfer identity, mask identity, covariance support
    tolerance, and baseline information matrix. Rank and singular values come
    from the PR-255 supported quotient, never the raw feature matrix.
12. The benchmark uses a fixed nearest-centroid open-set rule with abstention
    cost 0.5. Rank-zero, zero-null-scale, low-margin, and distant unknown cells
    abstain. Every representation binds the same train, validation, held-out,
    and unknown partition identities and byte-identical target vectors.
13. The preregistered descriptive max statistic uses a train-only class-zero
    center and scale on the frozen available coordinate set. Exact center and
    scale receipts, zero-scale coordinates, held-out mean max-\(|Z|\), and
    empirical 95% max-\(|Z|\) quantile are reported; a zero scale suppresses
    the statistic and forces abstention.
14. Reports distinguish generator-label loss, unknown known-assignment rate,
    mask/beam/foreground decision changes, supported singular spectrum, and
    identified-set contraction status. Scalar-relative loss reduction is a
    paired estimand with an explicit paired MCSE. None is serialized as a
    p-value, posterior, e-value, physical source, or family label.
15. A benchmark cannot reach `MEASURED` below the preregistered minimum 20,000
    held-out replicates even if an empirical rate happens to be exactly zero.
    The frozen artifact uses 40,000 held-out draws per factor, satisfying the
    0.0025 worst-case Bernoulli MCSE ceiling.
16. Added a second executable numerical oracle. It directly evaluates all
    twelve Cartesian polynomials, independently applies polar/axial O(3)
    actions, checks Cayley–Hamilton on 300 random STF matrices, and evaluates
    each harmonic intervention from its closed-form coefficient action.
17. Added package exports and alias registration, an isolated wheel import
    probe, portable focused/benchmark/CAS/adjacent/claim integration modes,
    a one-change-set/one-PR publication policy, focused destructive tests, and
    the PR-257 claim-registry row.
18. The frozen artifact separates the integration base SHA from a
    content-addressed generation-worktree manifest covering the exact
    generator, public scientific modules, specification, and CAS contract.
    The output itself is excluded from that manifest to avoid self-reference.

## Candidate-bound remediation review

The first exact-candidate review run
`premise-anchor-pr257-candidate-r3-20260729` returned `FAIL`; it is preserved
and is not relabeled as a pass. Two blind-result reviewers independently
reproduced three blockers:

- a BiPoSH provider identity could change across a claimed one-factor pair;
- cross-representation held-out target identities could drift while a
  scalar-relative loss reduction was still emitted;
- the frozen artifact named only the base SHA, which did not contain its
  generator, and omitted an exact candidate/worktree generation identity.

The remediation removes caller-supplied BiPoSH values, derives signed
coefficients from each packet's bound \(a_{\ell m}\), compares provider
configuration identities, binds common sample partitions and target bytes,
reports paired loss-difference MCSE, and adds the content-addressed worktree
manifest. The original provider-drift mutation now fails during feature
registration, and focused destructive tests independently cover provider,
partition, and target-identity drift. A new candidate SHA must be sealed and
reviewed; the failed receipts for `91144acbd90382d97b7d2d6b2dad4156ec665ded`
cannot authorize publication.

The next exact-candidate review run
`premise-anchor-pr257-remediation-r4-20260729` also returned `FAIL`; it is
preserved and is not relabeled as a pass. The two blind-result reviewers
found two further mutation-control defects in candidate
`9048880acce6786354c64fdc14ad0a99d9557986`:

- benchmark arrays retained writeable NumPy ownership, so a caller could
  restore `WRITEABLE` and change held-out loss and abstention after the input
  receipts were established;
- the matched-pair gate accepted a one-ULP \(C_\ell\) difference under a
  tolerance even though the registered contract requires one exact shared
  \(C_\ell\) vector.

The follow-up remediation copies every benchmark array into an immutable
bytes-backed buffer, independently protecting both retained caller aliases
and public stored arrays. It also binds the transformed packet to the
reference packet's exact registered \(C_\ell\) tuple while separately
replaying both packets' \(a_{\ell m}\)-derived powers under the declared
numerical tolerance. Focused destructive tests now reject direct
`setflags(write=True)`, retained-caller mutation, and one-ULP registered-power
drift. The r4 failed receipts remain historical evidence only; another exact
candidate seal and independent review are required.

The subsequent exact-candidate run
`premise-anchor-pr257-remediation-r5-20260729` again returned `FAIL` and is
also preserved without relabeling. Both blind-result reviewers independently
showed that post-construction mutation of a BiPoSH feature's
`source_alm_id` could survive pair construction and report revalidation even
though the feature no longer named its packet's current \(a_{\ell m}\)
receipt. The final remediation revalidates each feature and packet at report
evaluation, recomputes both factory-owned power-tensor and signed-BiPoSH
features from the bound coefficients, and rejects stale provenance or
post-construction value mutation. The r5 receipts cannot authorize a later
candidate; a new seal and review remain mandatory.

The r6 candidate review preserved one physics/statistics `PASS` and one
harness `FAIL`. The harness reviewer showed that a nested
`LowEllInterventionSpec` could be mutated after packet construction so that
an empty `intervention_id` survived report evaluation. The nested-contract
remediation reconstructs and compares every registered feature, intervention,
and packet contract at evaluation; validates the canonical registered
\(C_\ell\) tuple; and recomputes the phase signature as well as both
factory-owned feature blocks. Empty or altered nested receipts therefore
fail before a report ID is emitted. The r6 evidence remains candidate-bound
to its historical SHA and cannot authorize the next candidate.

The r7 candidate review
`premise-anchor-pr257-remediation-r7-20260729` returned two further `FAIL`
verdicts for candidate
`82a0f4767b5cecf1257a1649a27a27b6f9338ce8`. Both reviewers demonstrated
that a different syntactically valid SHA-256 receipt could replace the nested
`intervention_id`, and that angle semantics could change while retaining the
stale valid receipt. Reconstruction alone could not detect this because the
identifier was still an unconstrained caller input. The remediation removes
that input entirely: `LowEllInterventionSpec` derives its content identity
from the registered factor, operator, and exact validated angle. Apply,
matched-pair construction, and report revalidation now reject valid-receipt
substitution and stale factor/operator/angle mutations for phase, orientation,
and parity interventions. The r7 receipts are preserved as historical
negative evidence and cannot authorize this later candidate.

After PR #365 was opened, the GitHub `Python package smoke` job exposed one

The remediation removes only that eagerly exported pair from the shared-state

It does not reorder or skip a case, relax any metadata assertion, or change
production import behavior. A clean Python 3.12 environment using the same
editable install steps as GitHub Actions passes all 27 package tests. Because
the test bytes changed after r8, the r8 seal, review, and integration evidence
remain historical and cannot authorize this revision; publication must use a
fresh candidate seal, harness review, and latest-target integration receipt.

## Claim boundary

Allowed:

- typed scalar/pseudoscalar polynomial and syzygy diagnostics;
- exact matched-counterpair construction;
- preregistered synthetic held-out feature comparison;
- O(3) covariance/parity regression;
- supported singular-spectrum, contraction, abstention, and sensitivity
  diagnostics;
- negative or inconclusive morphology results and next-observable planning.

Forbidden:

- complete invariant basis or complete morphology catalogue;
- generic orbit separation or inverse atlas;
- observed anomaly, physical-source, or FLRW-departure detection;
- geometry or Bianchi-family identification;
- native-solver or external-transfer validation;
- posterior odds, Bayes factor, e-value, or evidence from feature separation.

PR-257 closes a diagnostic methodology increment only after its future merge.
It does not change the scientific status of PR-151 or any observational claim.
