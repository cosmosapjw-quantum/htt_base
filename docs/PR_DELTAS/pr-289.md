# PR-289 - Data identity registry v2 and authorization separation

Status: `VALIDATED` (frozen R1 review FAIL preserved; bounded repair awaiting R2)

## Scope and claim boundary

PR-289 is selectively recovering a read-only external-data identity preflight owned by
COMMON. It performs no acquisition, feature extraction, observed statistic,
likelihood, posterior, figure generation, or lane execution. A process PASS
means only that the registered factories, refusal paths, identity checks, and
mutations ran. The scientific status remains `OPEN_UNCHANGED`; the claim
ceiling is C2 `diagnostic_only`, transfer source is `none`, observed and public
use are false, and the pre-native family gate remains blocked.

The backlog's `EXPLICIT_USER_AUTHORIZED` value is explicitly typed as
`authorization_domain: workflow_only`. It authorizes this implementation work,
not any lane-specific data execution. Every PR-289 execution receipt is
factory-derived `NOT_AUTHORIZED`; PR-289 has no factory for an authorized
receipt.

## Salvaged implementation candidate

- Added a machine-readable six-lane registry with exact product IDs, ordered
  component roles and cardinalities, semantic fields, analysis-plan IDs, and
  exact human-gate IDs. The HSC/KiDS gate spelling is identical in registry,
  spec, and runbook.
- Added factory-only stable component records. `record_id` excludes inspection
  time and local root path; the separate `inspection_receipt_id` binds the
  inspection time. The source locator and ordered component inventory are
  independently content-addressed.
- Added strict typed identity evidence with duplicate-key and non-finite JSON
  rejection, resolvable source/release/license identities, and independent
  units, frame, sign, direction, harmonic, mask, selection, sky, covariance,
  null, and transfer statuses.
- Added fail-closed absolute-root inspection before resolution. Symlinked roots
  and parents, path escape, hardlinks, duplicate inodes, nonregular files,
  byte-size drift, hash drift, partial files, and component-order/cardinality
  drift are refused without copying or modifying external bytes. Components
  and identity evidence are opened with no-follow semantics; descriptor and
  file-descriptor identities are compared before and after the read so an
  in-place or replacement race cannot be admitted under a stale `lstat`.
- Added canonical refusal precedence and whole-lane aggregation. Missing roots
  deterministically yield six `REJECTED_NOT_PRESENT` decisions. HSC/KiDS
  name-only input is refused, and incomplete PR-151/DESI input takes the
  registered blocking precedence.
- Added a separate per-lane execution-authorization receipt. Complete identity
  records may be named by a `NOT_AUTHORIZED` receipt, but no human receipt,
  authority, scope, issue time, or expiry is invented. Incomplete lanes carry
  no admission record IDs.
- Added executable registered-mutation results in exact spec order. The receipt
  rejects omission, duplication, reordering, skipped execution, or surviving
  mutations instead of trusting hardcoded booleans. Path, content, evidence,
  inventory, status, authorization, and claim-boundary probes construct real
  scratch inputs and invoke the same public evaluators used by preflight.
- Preserved the exact PR-274 v1 registry and result hashes. No v1 artifact was
  migrated, relabeled, or mutated. The four source-bound PR-274 replay tests
  execute against exact canonical commit `ff9ef9f4`; current-tree compatibility
  separately runs the remaining PR-274 API/identity tests. This prevents the
  later repaired PR-273 pack from being substituted into a historical receipt.

## Native identity repair

- Planck admission now requires distinct content-bound SMICA and Commander
  children, per-pipeline map/mask/beam/covariance/window identities, exact
  same-sky pixelization and selection, and an FFP10 null inventory. Collapsed
  pipelines, aliased operators, and incomplete pairings fail closed.
- CF4 admission now binds the exact catalogue, selected rows, covariance,
  frame, radial sign, units, grouping, depth, and ZoA roles. These identities
  are replayed from the admitted component inventory rather than accepted as
  generic strings.
- HSC and KiDS now have separate product, mask, random, PSF, n(z),
  calibration/response, and auto-covariance children plus one content-bound
  cross-covariance relationship. A shared-single-PSF or other aliased child
  cannot be positively admitted.
- Exported record payloads replay every typed evidence field plus the exact
  native component path/role/ordinal inventory through the existing
  `common.data_identity` evaluator. Re-signing an invalid field or duplicating
  one repeated-role ordinal while omitting another fails closed.
- The runner compiles and executes the exact bytes read from the candidate
  module path, verifies factory code origin, and requires that executed digest
  to equal the receipt source binding. Receipt writes pin the validated output
  parent inode and use directory-relative no-follow atomic replacement, so a
  parent swap cannot redirect output. The recorded build argv uses the stable
  `python3` command identity rather than an interpreter-specific absolute path.
  Portable archive extraction rejects links and traversal on supported Python
  versions.
- The fresh claim-bearing receipt binds the exact registry, spec, policy,
  runbooks, claim ledger, implementation, runner, tests, and immutable PR-274
  boundary through ten source hashes plus a content-addressed generation
  identity.
