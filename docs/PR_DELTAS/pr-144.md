## Authenticated Cosmicflows-4 provenance

`htt/src/common/cf4_manifest.py`: the CF4 release is pinned to Tully et al.
2023, ApJ 944, 94 (VizieR J/ApJ/944/94, bibcode 2023ApJ...944...94T), and
every group-level column of `table3.dat` (30 columns) and `table4.dat` (22
columns) is bound to its byte range, format, units, and a TYPE
classification: identifier (1PGC), position-observable (RA/Dec/GLON/GLAT/
SGL/SGB), velocity-observable (Vh), frame-derived (Vls, V3k, Vcmb),
cosmology-corrected (fV3k, Hi, logHi), distance-indicator (the DM*
moduli), uncertainty (the e_DM* error bars), reconstruction (Vpds, Vpwf,
Vpec), cartesian-derived (SGX/SGY/SGZ), and selection-count (o_DM*). The
group ID (1PGC) parity across the two tables is verified (38053 unique
groups, 0 duplicates), the tables and the ReadMe are content-addressed at
the file and per-row level, the per-method selection/completeness is
recorded (FP the dominant methodology at 27602 groups, TF at 10035), and
the missing/range structure is validated against the ReadMe bounds.

## Anti-drift, enforced

A peculiar-velocity RECONSTRUCTION column (Vpds/Vpwf/Vpec) is never
selected as the true flow, the audit-only 94 km/s value is never promoted
to an observed measurement, the Cartesian SGX/SGY/SGZ columns are flagged
as cz (km/s) not Mpc lengths (the rev-r196 latent-bug caveat), a column
absent from the authority registry is refused rather than used by name,
and the manifest never claims the CF4 P0s resolved.

## Adversarial review lane (multi-lane, pre-commit)

Three refute-prompted lenses (byte-range accuracy vs the VizieR ReadMe;
type-classification / provenance; overclaim / mutations / determinism),
each verifying by reading the ReadMe and running extractions on the real
tables. NO P0 / P1 — the byte-range transcription was verified CORRECT for
every registered column (values physically sane, record counts and record
lengths consistent, parity and completeness genuine, the SGX/SGY/SGZ cz
caveat confirmed against the value magnitudes). Four P2 were fixed: (1/2)
`table3` omitted the six per-method uncertainty columns (e_DMsnIa, e_DMfp,
e_DMtf, e_DMsbfo, e_DMsbfi, e_DMsnII) while the docstring claimed every
column — now all 30 are registered and a completeness test cross-checks the
count; (3) e_DMav / e_DMzp were mistyped as distance-indicator — now a new
`UNCERTAINTY` type; (4) the `cf4_p0_resolution` mutation was the cz-units
guard relabeled — now a real `refuse_cf4_p0_resolution_claim` guard plus a
separately-labeled `cartesian_as_mpc_length` mutation.
