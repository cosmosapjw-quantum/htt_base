## Reproduced capability gap

The historical MIO curve records empirical threshold exceedance but does not
type its conditioning coordinates or probability law. The historical HTT
helper computes a posterior summary in a separate module. Neither surface can
represent a partial-identification envelope, and an optimizer output could be
misdescribed outside those APIs as if it were a draw. A single untyped `Pi`
therefore cannot distinguish five materially different statements.

## Implemented change

1. Added `SamplingLawSpec` for the five registered law labels and five
   conditioning-source labels. Each law has exactly one owner lane:
   `MIO_NULL`, `HTT_OBJECTIVE`, or `HTT_POSTERIOR`.
2. Added sealed `SamplingDraws`. A `PROFILE_LIKELIHOOD` law is explicitly
   non-probabilistic and can create only `LikelihoodObjective`; its optimizer
   point cannot enter either exceedance builder.
3. Added `ConditionalExceedanceProfile` with distinct point, lower-envelope,
   upper-envelope, law, conditioning, covariance, calibration, and refusal
   fields. Strict-tail values are non-increasing over a registered threshold
   grid.
4. Added MIO-owned `NullCalibratedExceedance` for fixed-injection mocks and
   bootstrap resampling only. Finite-draw uncertainty uses a simultaneous
   two-sided Dvoretzky-Kiefer-Wolfowitz band with explicit alpha and draw
   count.
5. Added HTT-owned `PosteriorExceedance`. Numeric output requires an explicit
   posterior law, sealed posterior draws, and a preregistered
   `PosteriorCalibrationReport` with status `PASSED`; otherwise it returns
   `POSTERIOR_CALIBRATION_REQUIRED` without a number.
6. Added the partial-identification envelope over the exact PR-250
   `IdentifiedDepartureSet`. Vertex enumeration is allowed only for a bounded
   set and a monotone certificate, or for the combined upper-quasi-convex and
   lower-quasi-concave certificate. Quasi-convexity alone, an active recession
   direction, or an unverified condition returns `OPTIMIZER_REQUIRED`.
7. Added owner-specific MIO and HTT facades. MIO exports no likelihood or
   posterior builder; HTT exports no MIO null-exceedance builder.
8. Bound laws, draws, objectives, calibration, coverage, profiles, and wrapper
   results to mutation-detecting content identities.

## Statistical and claim boundary

- The estimand is a law- and conditioning-specific strict-tail probability,
  not an unconditional truth probability.
- MIO owns matched-null and empirical diagnostics only.
- HTT owns likelihood objectives and explicit posterior-conditioned
  probabilities only.
- An identified set yields an interval unless it is point identified.
- A finite-draw confidence band does not validate a DGP, covariance model,
  transfer function, geometry, or family.
- No result is evidence, native-solver validation, geometry detection, or
  Bianchi family identification.

- Optimizer points and objective values are not samples.

- Upper quasi-convexity alone cannot certify a lower envelope endpoint.
- Unbounded identified sets require an optimizer contract.
- MIO cannot own posterior, likelihood, Bayes-factor, or evidence semantics.
- No native, truth, geometry, or family-identification language is permitted.
