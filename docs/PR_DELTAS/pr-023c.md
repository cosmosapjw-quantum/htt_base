## 주요 설계 결정

### 1. Sector 호출 순서 분석 (pre-audit §7)

PR-022a `rhs_free.rs` 의 dy 쓰기 방식을 pre-audit 단계에서 grep 으로 확인:
- `dy[idx(0)] = -k * get(1) + s_metric;` — **assignment** (`=`)
- `dy[idx(1)] = ...`, `dy[idx(ell)] = ...`, `dy[idx(ell_max)] = ...` — 전부 assignment

다른 3 sector 는 `+=`:
- PR-022b collision: `dy[idx_theta(1)] += -kd * ...` 등
- PR-023a metric: `dy[layout.i_metric_etak()] += etakdot;` 등
- PR-023b fluid: `dy[layout.i_cdm_delta()] += -hdot / 2.0;` 등

**Dispatcher 호출 순서 결정**:
1. `dy.fill(0.0)` — zero-init (PR-022a assignment 이후 다른 sector += 가 정상 동작하려면 필수)
2. **PR-022a 를 첫 번째 호출** (photon/ν 슬롯에 assignment 로 값 설정)
3. PR-022b collision / PR-023a metric / PR-023b fluid — 임의 순서 (모두 `+=`)

이 분석이 `identity_dispatcher_composes_all_sectors` test 에서 dispatcher 결과 vs manual composition 일치로 검증됨.

### 2. Slot overlap 분석 (모든 sector 가 올바르게 composable)

| Slot | PR-022a | PR-022b | PR-023a | PR-023b | 결과 |
|---|:---:|:---:|:---:|:---:|---|
| photon ℓ=0 | `=` (with metric source) | — | — | — | ✓ PR-022a 가 set |
| photon ℓ=1 | `=` free-streaming | `+=` drag | — | — | ✓ PR-022a set, PR-022b add |
| photon ℓ=2 | `=` free-streaming | `+=` damping (pol off) or pol feedback | — | — | ✓ |
| photon ℓ≥3 | `=` | `+=` pure damping | — | — | ✓ |
| ν ℓ=0 | `=` (with metric source) | — | — | — | ✓ PR-022a only |
| metric etak | — | — | `+=` etakdot | — | ✓ PR-023a only |
| metric σ | — | — | `+=` sigmadot | — | ✓ PR-023a only |
| metric[2..=10] (Bianchi) | — | — | — | — | ✓ 누구도 touch 안 함 |
| CDM δ_c | — | — | — | `+=` -hdot/2 | ✓ PR-023b only |
| CDM v_c | — | — | — | — | ✓ sync gauge (누구도 touch 안 함) |
| baryon δ_b | — | — | — | `+=` continuity | ✓ PR-023b only |
| baryon v_b | — | `+=` drag | — | `+=` Euler | ✓ collision + fluid additive |

**Double-counting 없음 확인**. 모든 slot 이 최대 2 개 sector 에서 write (photon ℓ≥1 or baryon v_b), 그중 하나는 assignment + 하나는 additive (or 둘 다 additive, 명시적 disjoint physics).

### 3. hdot Compute-Once Pattern

`hdot` 은 3 sector 에서 필요:
- PR-022a: `metric_monopole_source = -hdot/6` → photon/ν ℓ=0 coupling
- PR-023a: 내부에서 compute (sigmadot 계산 시) — 이 값을 dispatcher 에서 pre-compute 하여 전달하면 중복 제거 가능하나 현재 `pstf_metric_rhs` API 는 hdot 을 받지 않음 (내부 compute). Future optimization.
- PR-023b: `clxcdot = -hdot/2`, `clxbdot = -k·v_b - hdot/2`

Dispatcher 에서 `let hdot = pstf_hdot(state, v_b, &metric_inputs, layout);` 한 번 호출 후:
- `metric_monopole_source = -hdot / 6.0` 로 PR-022a 에 전달
- `FluidInputs.hdot = hdot` 로 PR-023b 에 전달

이것으로 **free-streaming 과 fluid 가 동일 hdot 값 사용** 보장 (numerical consistency). `caveat_hdot_computed_once` test 가 간접 검증: dispatcher 의 dy[i_cdm_delta] = -hdot/2 와 dy[i_photon_i_m0(0)] + k·Θ_1 = -hdot/6 이 같은 hdot 에서 유래함을 확인.

### 4. Retrospective G2 승격 메커니즘

PR-022a 최초 closure 시 `metric_monopole_source = 0.0` placeholder 이었음. G2 partial (cap 7, score 7).

PR-023c 에서 새 test `regression_rhs_matches_mb95_full_path_with_metric` 를 `rhs_free.rs` tests mod 에 추가:

// 1. Compute hdot via PR-023a
let hdot = pstf_hdot(&state, v_b, &metric_inputs, &layout);

// 2. Wire source into PR-022a RhsInputs
