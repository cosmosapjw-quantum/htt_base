# PR-299 — production Bayesian readiness after the PR-288 audit

Status: `PREPARATION_ONLY`

## Delivered, observable output

PR-299 adds one HTT-owned typed production-model contract and one read-only
readiness runner for `H-PLANCK`, `H-DESI`, `H-CF4`, `H-JWST`, and `H-ACT`.
The contract requires an arbitrary callable likelihood and prior transform,
an explicit parameter schema, data and covariance identities, registered
block partition, response rank, replicate generator, and discrepancy family.
It binds sampler samples, normalized weights, weighted ESS, and the required
nested-sampling settings to an exact consumer plan for PPC and blockwise LOO.

The runner imports no historical observed-data producer and opens no payload.
It only confirms that each registered production entrypoint still exists and
emits `observed_data_executed: false`.  At this stage all five lanes return
`BLOCKED_PRODUCTION_MODEL_CONTRACT_UNBOUND`.

`dynesty==3.0.0` is declared as the `bayes` optional extra.  This is an
environment-reconstruction requirement, not an observed inference result.

## Deferred gates and scientific ceiling

No posterior, evidence, PPC, LOO, ELPD, rank, null statistic, or source result
is generated here.  Exact PR-289 admission plus a distinct human execution
receipt are required before a lane can become ready.  Before any headline
observed result, the lane must additionally supply its preregistered repeated
nested-run ensemble, prior sensitivity, independent likelihood/SBC or
injection evidence, PPC discrepancy family, and blockwise delta-ELPD report.

The independent read-only review found and this repair closes one P1: an exact
authorization receipt could formerly yield a ready decision without a sampler
lineage and its PPC/blockwise-LOO consumer plan.  A ready decision now requires
all four bindings: exact model contract, exact PR-289 authorization type,
matching sampler lineage, and matching consumer plan.  Missing lineage remains
an explicit blocked readiness result.

Claim tier remains `diagnostic_only`; transfer source is `none`; native solver
validation and Bianchi family identification remain blocked.
