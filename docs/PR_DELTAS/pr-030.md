# PR-030 - TSC legacy boundary and import compatibility

## Goal

- Owner: COMMON
- Depends: PR-015
- Level: L2
- Scope: pre-solver
- Risk: high

Freeze TSC/Teff as a legacy reproduction and import-compatibility surface while
preserving existing `import tsc` consumers. New claim-bearing artifacts must use
the canonical `TSC_LEGACY` owner and `tsc_legacy` implementation scope, and
may only emit legacy-reproduction bundles. This PR does not make TSC an active
science owner, runtime gate, HTT evidence path, MIO certificate path, transfer
validation path, native solver path, OBSSTAT feature owner, or family-claim
path.

## Chosen plan

- Add `tsc_legacy` as the canonical legacy-boundary metadata package.
- Re-export the metadata and manifest helper from `tsc` without import-time
  deprecation warnings.
- Keep old raw `owner="TSC"` pack references loadable only through canonical
  owner normalization to `TSC_LEGACY`.
- Add package discovery coverage so `tsc_legacy` is importable from editable
  installs and temp working directories.
- Add a static production import allowlist for current MIO/HTT/BASS advisory
  TSC imports. Any new production `tsc.*` import must update the allowlist and
  justify why it is legacy/advisory-only.
- Document the deprecation boundary in `htt/tsc_legacy/README.md` and
  `docs/deprecation/tsc_legacy.md`.

## Review findings and fixes

- Finding: `tsc_legacy` was not importable after adding the package.
  - Fix: added `tsc_legacy*` to `htt/pyproject.toml`, refreshed the editable
    install, and covered package discovery in `htt/test_packaging_imports.py`.
- Finding: import-time `DeprecationWarning` would make strict warning harnesses
  fail even though import compatibility is required.
  - Fix: kept imports quiet and carried the deprecation status through explicit
    metadata, docs, and tests.
- Finding: raw legacy pack refs with `owner="TSC"` still appear in generated
  VER2 artifacts and bridge fixtures.
  - Fix: kept raw refs for reproducibility, but made bridge checks compare
    normalized owners and assert canonical `TSC_LEGACY` manifests after load.
- Finding: active MIO/HTT/BASS modules still import selected `tsc.*` helpers.
  - Fix: added an exact static allowlist test for current advisory/caveat-only
    imports. Any new production import must be explicitly reviewed.
- Finding: deprecation wording initially risked describing TSC as a posterior
  owner even in a negative sentence.
  - Fix: changed docs and caveats to `not posterior-producing` or
    `not a posterior-producing or likelihood-producing layer`.

## Risk log

- DoD:
  - TSC legacy remains import-compatible where needed.
  - New artifacts cannot set owner TSC except through legacy reproduction
    normalization to `TSC_LEGACY`.
- Kill switch:
  - Active MIO/HTT/BASS modules may not add new `tsc.*` imports for scientific
    claims. Current production imports are pinned by a static advisory/caveat
    allowlist.
- Residual risk:
  - The allowlist cannot prove semantic intent by itself; reviewers must keep
    future TSC imports advisory, caveat-only, or legacy reproduction-only.
  - Broader extraction of generic semantic guards from TSC remains PR-031.
