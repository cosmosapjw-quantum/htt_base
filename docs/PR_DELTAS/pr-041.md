## Chosen plan

- Add a small HTT `zoa` package at the live import path
  `htt/htt/htt/zoa/selection_ladder.py`.
- Add `source_mask_from_pixel_mask()` to COMMON `healpix_selection.py` so HTT
  can map PR-040 sky-support pixel masks to per-source masks without duplicating
  pixelization math.
- Return a `ZoASelectionLadder` with four immutable mode summaries and a
  `to_directional_summary()` adapter for the existing COMMON
  `DirectionalSummary` four-channel wrapper.
- Keep all ladder summaries diagnostic/support-only. Even with adequate
  mock-calibration inputs and `production_mode=True`, the returned summaries
  keep `production_allowed=False`; posterior promotion remains the job of the
  existing HTT production-axis gate.
- Reject production uniform fallback through `SkySelectionConfig`; require
  explicit adequate mock-calibration weights when the caller opts into
  production-mode strictness.

Alternatives rejected: a literal `htt/src/htt` package root, merging this into
the older COMMON bulk-flow artifact generator, or making mock-calibrated support
produce a production axis directly.

## Claim-tier impact

This PR adds an HTT L2 diagnostic support ladder for sky-selection modes. It is
not scientific readiness evidence, native solver validation, transfer
validation, posterior evidence, MIO diagnostic certificate evidence, morphology
compatibility, or family-identification evidence. It carries no C5/C6 science
claim.
