# PR-080 - External transfer registry wrapper for current AniCLASS-calibrated path

## Goal

- Owner: BASS
- Depends: PR-014, PR-070
- Level: L2
- Scope: pre-solver
- Risk: high

Add a BASS_PY transfer-provenance adapter and registry for current legacy
AniCLASS-calibrated and empirical-proxy transfer-dependent callables. This PR
records transfer source, calibration status, callable provenance, and callable
input domains. It does not call CLASS/AniCLASS, implement a native low-ell
solver, validate external transfer as native, create HTT evidence, create a
MIO certificate, or provide morphology/family evidence.

## Chosen plan

- Add `bass.transfer.aniclass_adapter.ExternalTransferAdapter` and
  `ExternalTransferAdapterRegistry` as lazy wrappers over existing legacy
  callables.
- Add `bass.transfer.registry.default_external_transfer_registry()` for pure
  PR-014 `TransferRegistry` consumers and
  `default_external_transfer_adapter_registry()` for value-producing wrapper
  consumers.
- Register current AniCLASS-calibrated paths as `AniCLASS_external` and the
  BASS comparison power-law path as `empirical_proxy`.
- Store callable input domains separately from PR-014 `valid_range` and label
  PR-014 `k_min/k_max` fields as schema carriers for these scalar legacy
  callables.
- Reject native specs, `TransferSource.NONE`, malformed callable paths,
  non-callable attributes, unknown IDs, external/native spoofing, and
  out-of-domain inputs.
- Keep the implementation provenance-only and diagnostic-only; no live CLASS,
  AniCLASS, native-solver, likelihood, MIO, atlas, or morphology path is
  introduced.

## Review findings and fixes

- Finding: the PR card target `htt/src/bass/transfer/...` does not exist as a
  live BASS package root.
  - Fix: implemented under `htt/bass/transfer`, matching the existing BASS
    package and avoiding a duplicate namespace.
- Finding: initial metadata used a noncanonical `transfer_conditional` claim
  tier string.
  - Fix: canonicalized to `claim_tier="conditional"`,
    `production_status="diagnostic_only"`, and an explicit
    `transfer_conditional=True` flag.
- Finding: initial domain metadata risked treating PR-014 `k_min/k_max` as the
  scalar callable domain.
  - Fix: added `callable_input_domain` and `valid_range_role`; `x_h` and
    `Sigma2` bounds are enforced before legacy-callable evaluation.
- Finding: native transfer specs and `source="none"` could be confused with
  external adapter inputs.
  - Fix: adapter construction rejects native specs and non-external/proxy
    sources.
- Finding: malformed callable paths were not fully covered.
  - Fix: tests now cover malformed path strings, missing functions,
    non-callable attributes, and unknown transfer IDs.
- Finding: future one-sided domain ranges could raise `KeyError` instead of a
  clear domain error.
  - Fix: added one-sided bound support and numeric bound validation.

## Claim-tier impact

This PR is BASS_PY transfer-provenance plumbing for current external/proxy
legacy callables. It is conditional, transfer-dependent, and diagnostic-only.
It is not native solver validation, transfer validation, HTT posterior/evidence
input, MIO diagnostic certificate evidence, morphology compatibility, or
family-identification evidence. It carries no C5/C6 science claim.

## Risk log

- DoD:
  - Current transfer-dependent paths record `AniCLASS_external` or
    `empirical_proxy` status.
  - The canonical claim tier is `conditional`; adapter metadata also carries
    `transfer_conditional=True` and `production_status="diagnostic_only"`.
- Kill switch:
  - External transfer output must never be labeled native.
- Residual risks:
  - The adapter wraps existing legacy scalar callables and checks their input
    domains. It does not rederive, recalibrate, or validate the AniCLASS
    calibration.
  - `TransferValidRange.k_min/k_max` remains present because PR-014 requires
    the schema field; PR-080 explicitly separates that from scalar callable
    domains.
  - The family string on AniCLASS paths is provenance for the external
    calibration label only. It is not morphology compatibility or family
    identification.
  - No downstream HTT inference producer or MIO diagnostic producer has been
    migrated in this PR; they should consume this registry in later DAG nodes.
