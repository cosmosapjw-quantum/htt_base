# PR-070 - Create obsstat package and ObservableVector contract

## Goal

- Owner: OBSSTAT
- Depends: PR-010, PR-011
- Level: L2
- Scope: pre-solver
- Risk: medium

Create an `htt.obsstat` package facade for observable feature packaging while
keeping `common.contracts.ObservableVector` as the single schema authority.
OBSSTAT may package alms, templates, covariance/BiPoSH blocks, scalar features,
morphology descriptors, and null-feature summaries; it must not emit HTT
likelihood/evidence, MIO certificates, transfer validation, or Bianchi family
identification/ranking.

- code_cartographer:
  - Steelman: make `htt.obsstat` a thin facade over the canonical COMMON
    `ObservableVector` to avoid a second observable schema.
  - Attack: a new obsstat-local dataclass would split the SSoT and conflict
    with the existing workspace alias pattern; routing through BASS would also
    misassign solver-output packaging to observer-side extraction.
- harness_engineer:
  - Steelman: lock the facade with focused tests plus adjacent ownership,
    schema-barrier, and packaging import tests.
  - Attack: a test that only imports the package misses the kill switch; the
    suite must also statically reject HTT/MIO/likelihood imports and check
    import side effects.
- physics_stat_auditor:
  - Steelman: allow diagnostic scalar, morphology, null, covariance, template,
    and BiPoSH feature blocks, but require null and transfer provenance when
    those summaries carry p-values or transfer-derived observables.
  - Attack: top-level-only p-value and transfer-source checks can be bypassed
    by nested feature dictionaries, so both gates must recurse.
- claim_gate_reviewer:
  - Steelman: `morphology_features` may contain compatibility descriptors such
    as axis coherence, but family-identification, family-ranking, and
    geometry-detection claims are blocked, as are posterior odds, evidence, or
    MIO certificate semantics.
  - Attack: words like `identified_family` and `family_rank` are claims even if
    wrapped inside BiPoSH/morphology dictionaries; accepting them would violate
    the pre-native-atlas family gate.
- regression_tester:
  - Steelman: focused obsstat tests are the acceptance suite, with adjacent
    contract/firewall tests guarding spillover.
  - Attack: exact system `python -m pytest ...` remains an environment failure
    on this machine because `/usr/bin/python` lacks pytest; venv-backed pytest
    is the usable validation path.

## Chosen plan

- Add `htt/obsstat/__init__.py` as the public facade exporting the canonical
  `ObservableVector`, `build_observable_vector`, and `obsstat_manifest`.
- Register the top-level `obsstat` package as installed `htt.obsstat` through
  the `htt` wrapper and package metadata so repo-root and temp-CWD imports use
  the same public facade.
- Add `htt/obsstat/observable_vector.py` with:
  - an OBSSTAT-owned, diagnostic-only manifest helper;
  - a builder that maps alm/scalar/morphology/null/template/covariance/BiPoSH
    feature blocks into the canonical COMMON `ObservableVector`;
  - recursive claim-key rejection for inference/evidence/posterior/MIO
    certificate and premature family-identification/ranking keys;
  - recursive p-value provenance checks requiring a non-empty
    `null_ensemble_ref` and tracked/corrected `look_elsewhere_status`;
  - recursive transfer-derived metadata checks using the COMMON transfer
    registry vocabulary and native-validation gates.
- Reject alternatives that redefine `ObservableVector`, import HTT/MIO
  inference code, use MIO certificates as observable features, or label
  external transfer summaries as native solver output.

## Review findings and fixes

- Finding: family-identification payload keys such as `identified_family` and
  `family_rank` still passed the first implementation.
  - Fix: broadened family-claim key rejection and kept tests for morphology and
    BiPoSH payloads.
- Finding: null p-value provenance was initially top-level-only.
  - Fix: recursive p-value scans now require `null_ensemble_ref` and
    `look_elsewhere_status` anywhere p-values appear in observable feature
    payloads.
- Finding: transfer-derived provenance was initially shallow and accepted
  value-free source strings.
  - Fix: recursive transfer metadata checks now use COMMON transfer-source
    vocabulary and native validation gate checks before accepting
    transfer-derived blocks, and the final implementation applies the check to
    alm/scalar/morphology/null/template/covariance/BiPoSH blocks.
- Finding: package smoke showed `htt.obsstat` was not importable from an
  installed temp-CWD environment.
  - Fix: package discovery includes `obsstat*`, the installed `htt` wrapper
    aliases top-level `obsstat` as `htt.obsstat`, and package tests cover the
    temp-CWD import.
- Finding: null p-value provenance could be present but empty or explicitly
  untracked.
  - Fix: null p-value features now require a non-empty `null_ensemble_ref` and
    a tracked/corrected look-elsewhere status.
- Finding: family-identification wording could appear in string values rather
  than keys.
  - Fix: feature payload string values are scanned for strong family/geometry
    claim phrases and rejected.
- Finding: exact system-Python PR-card pytest command cannot run in this
  checkout.
  - Fix: recorded the failure and used `venv/bin/python` evidence for pytest
    acceptance.

## Claim-tier impact

This PR adds OBSSTAT diagnostic feature packaging only. It is not scientific
readiness evidence, native solver validation, transfer validation, posterior
evidence, MIO diagnostic certificate evidence, morphology compatibility, or
family-identification evidence. It carries no C5/C6 science claim.

- owner: OBSSTAT
- implementation_scope: obsstat
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- transfer_source: none by default; transfer-derived blocks must carry COMMON
  transfer provenance metadata and cannot claim native validation without the
  required native gates.
- sky_support_status: required through the canonical `SkySupport` contract
- null_mock_status: diagnostic-only; any p-value feature requires a non-empty
  null ensemble reference and tracked/corrected look-elsewhere provenance.
- covariance_status: descriptive feature payload only
- ppc_status: not_applicable
- loocv_status: not_applicable

## Risk log

- DoD:
  - `obsstat` owns feature extraction, not inference.
  - `ObservableVector` can hold alm, templates, covariance, scalar/morphology,
    null, and BiPoSH features.
- Kill switch: reject if `obsstat` imports HTT likelihood/evidence code, MIO
  certificate surfaces, or emits family-identification/ranking semantics.
- Residual risks:
  - The builder validates transfer provenance metadata but does not compute or
    validate transfer functions.
  - Feature payload values remain descriptive Python mappings; richer shape and
    harmonic-convention validation belongs in later obsstat PRs.
  - Native transfer sources remain blocked unless explicit native validation
    gates are present; no native solver output is produced here.
