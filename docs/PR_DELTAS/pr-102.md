# PR-102 - FLRW null-predictive tension gate

## Goal

- Owner: MIO
- Depends: PR-076, PR-100
- Level: L3
- Scope: pre-solver
- Risk: high

Add a MIO-owned FLRW null-predictive diagnostic gate that requires
PR-076 typed null provenance before certificate/artifact readiness can become
candidate-level. Raw empirical tail probabilities remain descriptive statistic
rows only and are not exported as a FLRW-tension certificate departure.

## Chosen plan

- Added the root PR-card test `tests/mio/test_flrw_tension_gate.py`.
- Added `null_predictive_payload` support to `to_mio_certificate()` and
  `emit_flrw_tension_artefact()`.
- Reused PR-076 `validate_null_feature_payload()` instead of creating a MIO
  null metadata dialect.
- Required exact FLRW null-family, statistic-key, tail-definition,
  mock-count, corrected-tail-probability, look-elsewhere, covariance, null,
  sky, mask, noise, config-hash, and input-hash matches.
- Replaced substring readiness heuristics with exact ready-status allowlists.
- Made `null_mocks_calibrated=True` insufficient without the typed payload.
- Bound certificate manifest `config_hash` and `input_hashes` to the accepted
  null-predictive payload, and rejected caller mismatches.
- Removed raw/minimum empirical tail probabilities from certificate departure
  and consistency metrics; raw empirical per-statistic tails remain only as
  descriptive audit rows with explicit role metadata.
- Updated the HTT/MIO cross-check rule to accept PR-102 corrected-tail fields
  while retaining compatibility with legacy PPP fixture fields.
- Updated generated status-snapshot claim notes for PR-102 using structured
  PR-card detection rather than title-only matching.

Rejected alternatives: generating FLRW mocks inside MIO, treating a boolean
calibration flag as sufficient, treating local raw tails as global
null-predictive calibration, adding native-solver or family/morphology language,
or merging MIO certificate information into HTT inference output.

## Review findings and fixes

- Finding: the PR-card test path was absent.
  - Fix: added `tests/mio/test_flrw_tension_gate.py`.
- Finding: `null_mocks_calibrated=True` could be mistaken for a calibrated
  null-predictive distribution.
  - Fix: typed PR-076 null payload is required; the boolean alone remains
    blocked.
- Finding: local raw tails could be treated as global null-predictive p-values.
  - Fix: PR-076 payload `p_values` must match corrected tail probabilities,
    with a multi-statistic regression.
- Finding: substring readiness heuristics promoted adversarial statuses such as
  `not_complete` or `*_hash_pending`.
  - Fix: exact allowlists now gate covariance, null mocks, mask, noise, and sky
    support.
- Finding: null-predictive payload hashes were copied into metadata but not
  bound to the certificate manifest.
  - Fix: manifest `config_hash` and `input_hashes` now come from the payload
    and mismatches are rejected.
- Finding: PR-102 field renames broke the existing HTT/MIO cross-check adapter.
  - Fix: cross-check reads corrected-tail fields first, keeps legacy fallback,
    and now has a regression using a real PR-102 certificate.
- Finding: package-level docs still called the surface posterior-predictive.
  - Fix: downclaimed to null-predictive empirical tail checks.

## Claim-tier impact

This PR adds a MIO diagnostic-only FLRW null-predictive tail gate. It is not
native solver validation, transfer validation, HTT model-dependent inference
output, a truth certificate, morphology compatibility, or geometry/family
evidence.

- owner: MIO

- ppc_status: not_applicable for MIO; HTT owns model-dependent predictive checks
