# PR-072 - Low-ell scalar summaries as OBSSTAT features

## Goal

- Owner: OBSSTAT
- Depends: PR-071
- Level: L2
- Scope: pre-solver
- Risk: medium

Add OBSSTAT-owned low-ell scalar feature summaries for `C_l`, `S_1/2`,
parity, and input-frame planarity. These summaries are diagnostic observable
features only. They are not model inputs, not MIO outputs, not native solver
outputs, not morphology-compatibility outputs, and not geometry or
family-identification support.

## Chosen plan

- Add `LowEllScalarSummary` and `summarize_lowell_scalars()` as an OBSSTAT
  feature facade.
- Add `LowEllNullCalibration` for p-values that carry required null ensemble,
  look-elsewhere, tail, mask, covariance, scan-volume, and mock-count metadata.
- Compute `S_1/2` by Gauss-Legendre quadrature over `x in [-1, 1/2]` using the
  selected `C_l` Legendre two-point function.
- Compute parity from even and odd sums of `l(l+1)C_l/(2pi)` over the selected
  ell range.
- Compute input-frame planarity as `sum_m m^2 |a_lm|^2 / (l^2 sum_m |a_lm|^2)`
  with a null policy for `ell < 1` or zero power.
- Require dense full `a_lm` storage with every `m=-l..l` mode present when
  alms are supplied, so packed real-map storage cannot be silently
  misinterpreted.
- If callers supply both `C_l` and `a_lm`, require overlapping `C_l` values to
  match the alm-derived value.
- Normalize JSON payload keys recursively and alias `obsstat.scalar_lowell` to
  `htt.obsstat.scalar_lowell` to preserve class identity.

Alternatives rejected: accepting sparse alms with missing modes treated as
zero, accepting p-values with only a null reference, or letting downstream HTT
or MIO code reinterpret these scalar summaries.

## Review findings and fixes

- Finding: nested payload maps such as `parity.weights_by_ell` and
  `planarity.by_ell` retained integer keys.
  - Fix: `to_feature_payload()` now recursively stringifies payload mapping
    keys, and tests assert the JSON-shaped output.
- Finding: direct construction of the exported `LowEllScalarSummary` could
  carry non-finite or negative values into a payload.
  - Fix: the dataclass now validates ell range, contiguous `C_l` coverage,
    finite non-negative `C_l`, finite non-negative `S_1/2`, and finite
    nested numeric values.
- Finding: top-level `obsstat.scalar_lowell` and `htt.obsstat.scalar_lowell`
  loaded as distinct module objects.
  - Fix: `htt/obsstat/__init__.py` now aliases package and submodule entries
    in `sys.modules`; package tests cover both import orders.
- Finding: the exported alm-derived `C_l` path was not tested and sparse alm
  storage could be undercounted.
  - Fix: `compute_cl_from_alm()` now requires dense full `m=-l..l` storage and
    tests cover expected `C_l`, missing modes, invalid `m`, and non-finite
    coefficients.
- Finding: mixed `C_l` and `a_lm` inputs could represent different skies.
  - Fix: overlapping supplied and alm-derived `C_l` values must agree within a
    tight numerical tolerance.
- Finding: `ell=0` planarity divided by zero.
  - Fix: planarity uses a null value for `ell < 1` or zero power and records
    the degeneracy policy.
- Finding: null calibration could expose p-values without tail, mask,
  covariance, scan-volume, or mock-count metadata.
  - Fix: `LowEllNullCalibration` now requires all of those fields, validates
    p-value keys against known low-ell statistics or `cl_ell_<n>`, and keeps
    p-values out of uncalibrated payloads.
- Finding: free strings could inject overclaim language before downstream
  `ObservableVector` checks.
  - Fix: scalar summary and null-calibration constructors screen user strings
    and labels for forbidden model, MIO, geometry, and family-claim language.

native validation, morphology-compatibility output, or geometry/family claim.

## Risk log

- DoD:
  - `C_l`, `S_1/2`, parity, and input-frame planarity are computed with
    explicit definitions.
  - Scalar summaries are tagged `feature_only` unless a strict
    `LowEllNullCalibration` is attached.
- Kill switch:
  - Reject if a low-ell feature can trigger a geometry or family claim.
- Residual risks:
  - The planarity scalar is input-frame only and must not be promoted into a
    morphology result in later PRs.
  - The dense full alm convention is intentionally strict. Packed real-map or
    healpy-style positive-`m` storage requires a future explicit adapter rather
    than silent interpretation here.
  - Null-calibrated p-values are metadata-bearing diagnostic features only.
    They are not full null-ensemble machinery; PR-076 owns null ensembles and
    look-elsewhere bookkeeping.
