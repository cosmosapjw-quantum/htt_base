## Outcome

PR-282 executes one frozen synthetic estimator, mask, weighting, and parity
action and derives the G3 terminal token from exact arithmetic. The clean
registered path returns `PASS_EXECUTABLE_P_EQUIVARIANCE`; asymmetric mask,
asymmetric weighting, estimator-sign erasure, missing mutations, and contract
drift fail closed. No caller readiness boolean or numerical tolerance enters
the API.

This is C2 `diagnostic_only` synthetic method-readiness evidence. It does not
execute observed data, validate a physical parity signal, establish a null
law, validate a transfer function, or identify a geometry or family.

## Governing contract and theorem boundary

- The registered action uses the exact reflection
  `P = diag(1, 1, -1)`, with determinant `-1`, and support involution
  `[1, 0, 3, 2]`.
- Each synthetic `sigma` is exactly symmetric and trace-free. The estimator is
  the masked weighted mean of
  `K_beta = det[beta, sigma beta, sigma^2 beta]`.
- The executable relation is anti-equivariance: the transformed estimator is
  exactly the negative of the baseline estimator. Arithmetic uses rational
  values and no tolerance.
- H2 is executed only for the registered fixed synthetic mask and weights.
  Mask deconvolution, observed selection functions, and point-source-hole
  correction are not executed.
- H1, reflection symmetry of a scientific null, is not evaluated. H3, absence
  of an atom at zero, remains conditional and unestablished. A G3 method pass
  does not imply either premise.
- The downstream e-value example is an exact convex arithmetic mean. Its
  arbitrary-dependence validity remains conditional on every nonnegative input
  being a valid e-value under the same registered null and on weights fixed
  before output is viewed. Dependent sign counts are not pooled as binomial
  trials.

## Implementation

- `obsstat.exact_parity_readiness` parses the closed specification, checks the
  reflection, support action, fixture, receipt contract, theorem boundary, and
  complete mutation registry, then computes both clean and mutated executions.
- The clean registered execution is exact:
  baseline `-115/3`, transformed `115/3`, and relation residual `0`.
- Three registered mutations execute and are killed: absolute-value sign
  erasure, one-sided mask removal, and one-sided weight skew.
- `obsstat.egs3_evalue_merge.merge_evalues_arbitrary_dependence` adds an exact
  convex arithmetic merge with explicit common-null, input-validity, fixed
  weight, and arbitrary-dependence conditions. It exposes no product or pooled
  sign rule.
- `common.vector_tensor_statistical_foundations.exact_parity_sign_test`
  preserves the sign of exact rational values below floating-point range while
  retaining the previous general numeric validation path.
- `run_pr282_exact_parity_readiness.py` builds, byte-checks, and tests the
  content-addressed generated receipt. The artifact binds all scientific
  source and test paths named by the specification.
- Claim-language lint now has an opt-in `--strict-missing` mode so publication
  commands cannot silently skip an explicitly required PR surface. Default
  behavior remains backward compatible.
- Publication-policy parsing now rejects relaxed agent-mutation flags, empty
  review invalidation rules, unregistered claim ceilings, and a pre-native
  family gate that is not blocked. When a policy declares change-set,
  publication-group, target-ref, and target-SHA metadata, run initialization
  and candidate sealing cross-bind all four to their live inputs.

## Test and failure chronology

The implementation followed a fail-first sequence:

1. The new focused test failed at collection because the exact merge API did
   not exist.
2. The first implementation then produced `6 failed, 7 passed`: the flat
   input rows included `vector_id`, while the exact fraction parser correctly
   required only numerator and denominator. The parser now extracts the exact
   fraction fields explicitly.
3. A direct extreme-value discriminator showed that
   `Fraction(1, 10**400)` and its negative were both converted to floating
   zero by the existing sign test. The new regression failed before the
   compatibility-preserving exact-rational branch was added.
4. The publication claim command returned zero when an explicitly named delta
   path was absent. The new strict-missing regression failed before the
   opt-in fail-closed CLI mode was implemented.
5. Scratch mutations showed that the original receipt builder ignored its
   `required_bindings`, `output_path`, `terminal_precedence`, and
   `mutation_rule` fields. Those fields and the proportional claim metadata
   are now exact contract inputs.
