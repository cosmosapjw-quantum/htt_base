# PR-074 - Template-fit diagnostics with orientation scan metadata

## Goal

- Owner: OBSSTAT
- Depends: PR-071, PR-073
- Level: L3
- Scope: pre-solver
- Risk: high

Add an OBSSTAT-owned diagnostic template-fit feature payload for
caller-supplied observed/template vectors. The payload records amplitude,
DeltaChi2, orientation scan volume, covariance weighting assumptions, and an
explicit split between deterministic template-mean fitting and covariance
metadata. It does not create HTT model output, MIO diagnostic reports, transfer
validation, native solver output, morphology compatibility, or
geometry/family-identification evidence.

## Chosen plan

- Add `OrientationScanMetadata` for scan id, parameterization, orientation
  count, scan volume, coordinate frame, sky/mask status, hashes, best
  orientation, and caveats.
- Add `CovarianceAssumption` as a declared weighting operator only, with
  identity, diagonal inverse-variance, and full positive-definite covariance
  constructors.
- Add `TemplateFitDiagnostic` and `fit_template_diagnostic()` for one
  deterministic template amplitude diagnostic.
- Serialize separate `template_mean_branch` and `covariance_branch` blocks,
  with `covariance_anomaly_status="not_evaluated"` and
  `collapsed_with_template_mean=False`.
- Reject covariance anomaly inputs in this API rather than folding them into
  the template statistic.
- Export the feature through `htt.obsstat` and top-level `obsstat` aliases.

Rejected alternatives: pseudo-inverse support without explicit projected
subspace metadata, p-values without null ensemble/look-elsewhere provenance,
storing template fits under covariance features, and adding any solver/native
atlas/family-identification behavior.

## Review findings and fixes

- Finding: `CovarianceAssumption.diagonal_inverse_variance` collided with the
  dataclass field of the same name, so identity/full assumptions observed a
  method object as stored metadata.
  - Fix: renamed the stored sequence to `inverse_variance_weights` while
    keeping the public constructor named `diagonal_inverse_variance`.
- Finding: public `TemplateFitDiagnostic` construction could serialize
  inconsistent DeltaChi2 and chi-square fields.
  - Fix: added constructor invariants and red-green tests for non-negative
    chi-square values and `delta_chi2 == chi2_without_template -
    chi2_with_template`.
- Finding: public `TemplateFitDiagnostic` construction could serialize
  inconsistent duplicate norm aliases.
  - Fix: added invariants and tests requiring `observed_norm_weighted` to
    equal `chi2_without_template` and `residual_norm_weighted` to equal
    `chi2_with_template`.
- Finding: reviewer noted low-risk gaps for off-diagonal full covariance and
  direct top-level exports.
  - Fix: added an off-diagonal positive-definite full-covariance test and a
    `from obsstat import TemplateFitDiagnostic` assertion.

Residual risk: orientation scan `global_local_status` and
`look_elsewhere_status` are intentionally separate metadata fields in PR-074
because no null tail probability is emitted. Future null-calibrated template
fits should add stricter matched-null scan metadata before reporting any
p-value.
