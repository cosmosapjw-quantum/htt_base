# PR-304 — externally rooted authorization contract

## Scope and terminal ceiling

PR-304 defines a non-executing contract for a future human authorization. It
does not issue authorization, install a trust root or launcher, handle a
private key, consume a nonce, admit data, open an observed payload, execute a
lane, or create a scientific result. Its dependency is the exact PR-289 source
integration completed by PR-303 at base
`612c2c11ad448df9d48040fb6d0e5e459b97fe8d`.

The terminal state is `PASS_AUTHORIZATION_CONTRACT_ONLY` with zero admitted,
authorized, executed, and active-authority lanes. Observed execution and nonce
consumption remain false. PR-305 is not started by this change.

## External trust boundary

Candidate code and `human_authority_registry.json` cannot establish their own
authority. Every tracked lane row remains `PENDING_HUMAN_PROVISIONING`, and
the tracked signature sidecar is explicitly
`PENDING_EXTERNAL_ROOT_SIGNATURE`, `template_only: true`, and
`authority_granted: false`.

The future authority boundary is an independently installed root-owned
launcher at `/usr/local/libexec/htt-auth-launcher`, with an externally
provisioned Ed25519 root key and reviewed fingerprint under `/etc/htt/trust/`.
No such launcher, key, signature, or active authority is created here.
Candidate validation APIs fail closed with
`ExternalTrustedLauncherRequired`, even if a candidate commits an attacker key
and marks its own lane row active.

The tracked launcher contract requires the external launcher to verify the
detached registry signature, candidate commit/tree, exact admission, model,
runtime, response-rank, normalization, and execution-plan bindings before it
may later control nonce consumption and process start.

## Candidate and exact-blob inspection

Diagnostic candidate inspection uses the absolute `/usr/bin/git` executable,
a minimal scrubbed Git environment, disabled hooks/replace objects/lazy fetch,
and exact `commit:path` blob reads. Ambient `PATH`, `GIT_DIR`, `GIT_WORK_TREE`,
`GIT_INDEX_FILE`, object-directory, namespace, config, and Python loader
variables cannot select the candidate identity or resource bytes.

The PR-289 lane registry, candidate authority metadata, provider manifest,
provider source and dependencies, configuration, environment contract,
response matrix, normalization evidence, and execution plan are read from the
validated candidate Git object. Worktree pathname check-then-read is not an
authority input.

## Provider, runtime, rank, normalization, and plan binding

`htt.production_bayesian_contract.v3` rejects arbitrary caller-supplied
callables, response-rank integers, and normalization booleans. A
`ProviderManifestV1` names exact candidate-relative blobs and exports. The
non-executing loader parses the exact provider blob, rejects imports,
top-level executable statements, closures, defaults, mutable global
declarations, and undeclared exports, binds declared dependency blobs, and
records per-definition AST fingerprints. Candidate code is never executed by
the validation process. A future external launcher must reverify these bytes
and execute them only inside its reviewed OS-level isolation boundary.

The bound production contract also contains:

- a live `RuntimeEnvironmentReceiptV1` with interpreter, platform, required
  package versions, and NumPy native-extension identity;
- a `ComputedResponseRankReceiptV1` derived from the exact response matrix,
  feature/parameter order, threshold, covariance, and admission bundle;
- `NormalizationEvidenceV1` tied to exact likelihood/prior identities and
  registered analytic methods;
- `ExecutionPlanBindingV1` tied to exact entrypoint, argv, output root, run
  mode, provider manifest, and runtime receipt.

Binding and readiness replay reconstruct and compare all of those objects from
the exact candidate blobs. Resource swaps, runtime mismatch, deficient rank,
invented normalization, provider dependency drift, and plan substitution fail
closed.

## Readiness and authorization receipt

Wire schema `common.human_execution_authorization_receipt.v3` adds exact model,
runtime, response-rank, normalization, and execution-plan identities. The
historical Python name `HumanExecutionAuthorizationReceiptV1` is retained only
for source compatibility; the schema field is authoritative.

The nonce parser validates only the canonical `nonce:v1:` plus 64 lowercase
hexadecimal characters. It does not claim to measure entropy. A future external
issuer must use a CSPRNG, and PR-305 must atomically enforce one-time use.

`ValidatedHumanExecutionAuthorization` is non-authoritative cache evidence.
The candidate cannot emit `READY_TO_START_SAMPLER`. Any supplied posterior
lineage or consumer plan produces `BLOCKED_SAMPLER_TERMINAL` with reason
`pr305_observed_run_terminal_contract_unavailable`; PR-304 cannot emit
`READY_FOR_POSTERIOR_CONSUMERS`. PR-305 must define and bind observed-run and
sampler-terminal receipts before either transition can be enabled.
