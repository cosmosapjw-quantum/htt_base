# PR-304 — admission-bound human authorization contract

## Scope

PR-304 introduces a validator for a future, external human authorization. It
does not issue an authorization, store an authority key, consume a nonce,
admit data, open an observed payload, execute a lane, or create a scientific
result. Its terminal condition is `PASS_AUTHORIZATION_CONTRACT_ONLY` with
zero admitted, authorized, and executed lanes.

## Contract

`HumanExecutionAuthorizationReceiptV1` is a canonical HMAC-SHA256 receipt
bound to an exact PR-289 `LaneSpec`, a replayed complete
`LaneAdmissionDecision`, its ordered record IDs, its bundle ID, analysis plan,
human gate, lane scope, code commit/tree, expiry interval, nonce, and the
SHA-256 identity of a single external authority-key file. The key is never
stored or emitted by this repository. The external key must be an absolute,
non-symlinked, single-link regular file outside the repository.

Validation returns a factory-only `ValidatedHumanExecutionAuthorization` that
retains the replayed lane-spec content ID and admission bundle ID. It does not
consume the nonce; PR-305 owns one-use nonce consumption and the transaction
that may later open observed bytes.

## Bayesian readiness

The readiness path distinguishes incomplete admission, missing human
authorization, permission to start a sampler, incomplete sampler terminal
state, and permission for posterior consumers. `READY_TO_START_SAMPLER` never
requires posterior samples, PPC, or LOO. The previous rootless read-only
serialization remains a compatibility alias for the initial blocked state;
it does not grant a capability.
