# PR-304 — admission-bound human authorization contract

## Scope

PR-304 defines a non-executing contract for a future human authorization. It
does not issue an authorization, store a human private key, consume a nonce,
admit data, open an observed payload, execute a lane, or create a scientific
result. Its dependency is the exact PR-289 source integration completed by
PR-303 at base `612c2c11ad448df9d48040fb6d0e5e459b97fe8d`.

## Trust and cache boundary

`HumanExecutionAuthorizationReceiptV1` now carries schema v2 Ed25519 evidence.
The verifier resolves the signer through the exact lane row in
`human_authority_registry.json`; callers cannot select a key path. The tracked
registry contains public-key slots only and every lane remains
`PENDING_HUMAN_PROVISIONING`, so this PR creates no usable authorization.
Private signing keys remain outside repository and agent access.

`ValidatedHumanExecutionAuthorization` is display/cache evidence, not an
authority token. Every readiness transition reparses the original canonical
receipt bytes and repeats signature, admission, clean-candidate, scope, and
expiry validation. PR-305 must repeat that verification immediately before it
may consume a nonce.

## Admission-bound production model

`htt.production_bayesian_contract.v2` binds all of the following into its
content identity:

- the exact lane admission bundle and ordered PR-289 record IDs;
- admitted data and registered covariance identities;
- a factory-derived clean candidate commit and tree;
- every likelihood/prior/replicate/discrepancy source path and byte hash;
- the provider configuration and environment paths and byte hashes.

Readiness rebuilds those bindings from the current clean candidate. An
unbound model, covariance mismatch, admission-bundle substitution, provider
byte change, stale candidate, forged cache, or expired signed receipt fails
closed before `READY_TO_START_SAMPLER`.

## Nonce and candidate boundary

The receipt requires `nonce:v1:` plus 64 lowercase hexadecimal characters and
rejects low-diversity repeated shapes. This is structural admission only;
there is no nonce ledger and no nonce is consumed in PR-304. Candidate
commit/tree values are derived from an attached, clean Git worktree rather
than caller-supplied strings.

## A3 replacement

The inherited PR-289 interpreter-alias node assumes that the deliberately
removed candidate receipt exists in the canonical worktree. It is classified
`SUPERSEDED_FIXTURE_ASSUMPTION`, not repaired by restoring stale authority.
The replacement test creates a disposable `git archive`, builds the PR-289
receipt only there, checks it under `/usr/bin/python` and `/usr/bin/python3`,
compares receipt hashes, deletes the disposable root, and confirms that
`docs/generated/pr289_data_identity_v2_receipt.json` remains absent before
and after. The boundary command deselects only the obsolete historical node.
