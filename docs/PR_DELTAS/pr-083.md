# PR-083 - Budget ceiling optimizer policy interface

## Goal

- Owner: BASS_PY
- Depends: PR-051, PR-082
- Level: L3
- Scope: pre-solver
- Risk: high

Add a BASS_PY diagnostic-only budget ceiling policy interface that emits
positive finite `U_C` ceiling candidates with explicit transfer source, valid
range, prior, admissible set, rank, config/input, command, and worktree
provenance. MIO can reference the policy explicitly through `BudgetSpec` and a
compact reference payload, while PR-051 certified-F and depth-gap gates remain
in force.

## Chosen plan

- Add `CeilingPrior` and `AdmissibleSetMetadata` as explicit policy metadata.
- Add `BudgetCeilingCandidate` for one positive finite `U_C` with transfer
  source, optional PR-014 metadata, valid range, and rank diagnostics.
- Add `BudgetCeilingPolicyResult` with full payload, compact MIO reference
  payload, and `to_mio_budget_spec()`.
- Add `optimize_budget_ceiling()` with deterministic `max_ceiling`,
  `min_ceiling`, and `quantile_higher` selection over compatible candidate
  sets only.
- Reject schema-only future-native atlas entries as numeric ceilings.
- Preserve full rejected-candidate provenance rather than keeping only scalar
  values.
- Delegate final MIO denominator validation to PR-051 `BudgetSpec`.
- Keep external/proxy ceilings non-certifying for F before native validation
  gates; allow certified F only for explicitly admissible MES-style policies.
- Require depth-bin/null/covariance metadata for depth-gap references.

Rejected alternatives: native adapter calls, synthetic native values, family
ranking, MIO-owned optimizer logic, COMMON policy extraction, HTT posterior
plumbing, or legacy BASS clipped filling paths.

## Review findings and fixes

- Finding: mixed MES/external candidate sets could hide rejected transfer
  provenance.
  - Fix: optimizer now requires shared transfer source/spec and valid-range
    schema, and rejected candidates preserve full candidate metadata.
- Finding: direct candidates accepted malformed `valid_range` payloads.
  - Fix: direct ranges now require valid bound pairs; PR-014-style ranges
    validate `k` and `ell` bounds.
- Finding: certified F could be built from a rank-unevaluated ceiling.
  - Fix: non-sensitivity MIO uses require `full_rank` with rank diagnostics or
    explicit `rank_not_applicable_certified_mes`.
- Finding: depth-gap metadata was not propagated to MIO references.
  - Fix: compact MIO reference payload includes depth metadata, and BudgetSpec
    assumptions carry a depth metadata hash for depth-gap use.
- Finding: claim key filtering missed substring keys and global negation could
  mask a later forbidden phrase.
  - Fix: key substring scans catch posterior/certificate/evidence/family keys,
    and phrase negation is evaluated clause-locally.

## Claim-tier impact

This PR adds BASS_PY diagnostic pre-solver ceiling-policy metadata and a MIO
denominator reference bridge only.

- owner: BASS
- implementation_scope: bass_py
- pr_scope: pre-solver
- claim_tier: diagnostic_only
- transfer_source: explicit per candidate, none or external/proxy only
- native_solver_result: false
- sky_support_status: inherited through MIO BudgetSpec defaults unless supplied
- covariance/null status: required for depth-gap references
- ppc_status: not_applicable
- loocv_status: not_applicable

PR-083 does not run or fake a native solver, validate external transfer as
native, produce HTT posterior/evidence content, create a MIO certificate, or
support morphology compatibility or geometry/family-identification evidence.
