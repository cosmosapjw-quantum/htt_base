## Chosen plan

- Add `htt/htt/htt/direction/preferred_axis.py` as an HTT helper over the
  canonical COMMON `PreferredAxis`, with a fail-closed constructor default and
  coordinate/provenance validation helpers.
- Add `htt/htt/htt/zoa/axis_promotion.py` as the downstream synthesis lock. It
  wraps the existing `htt.infer.axis_gate.evaluate_axis_gate` and then adds
  PR-040 sky-support, mask, scan-volume, mock-coverage, and promotion-record
  checks required before harmonic use.
- Tighten `restore_full_a2m()` so `production_allowed=True` alone no longer
  reaches the rotation stub. A caller must provide rich `SkySupport` plus a
  matching `AxisPromotionRecord`.
- Keep all ZoA ladder outputs diagnostic-only. A PR-041 mock-calibrated support
  axis remains blocked from `a_lm` and `a_2m` rotation.

Alternatives rejected: creating `htt/src/htt` to match the stale card path,
rewriting the older directional-shell gate wholesale, or treating ZoA
mock-calibrated support as posterior-derived axis provenance.

## Review findings and fixes

- Finding: direct `restore_full_a2m()` still allowed a manually constructed
  fiducial axis with only `production_allowed=True` to reach the rotation stub.
  - Fix: it now calls `require_axis_for_harmonic_synthesis(..., target="a_2m")`
    and requires `SkySupport` plus an `AxisPromotionRecord`.
- Finding: a production-looking `PreferredAxis` literal can be constructed
  outside `axis_from_posterior()`.
  - Fix: the downstream lock requires stable axis provenance and a matching
    promotion record before harmonic synthesis.
- Finding: weak sky metadata such as `sky123`, `mask123`, missing
  `sky_fraction`, and `legacy_unspecified` coordinate frames could pass older
  basic gates.
  - Fix: the new downstream lock requires sha256 support/mask/scan hashes,
    explicit coordinate/completeness/pixelization metadata, positive sky
    fraction, nside, and adequate mock coverage.
- Finding: adversarial reviewers found `sha256:` prefix-only validation and
  arbitrary axis-provenance strings were weaker than the documented lock.
  - Fix: `AxisPromotionRecord` and `SkySupport` lock checks now require
    `sha256:<64 hex chars>` for support/mask/scan/config/input/mock/posterior
    hashes, and axis provenance must match the existing 16-hex
    `axis_from_posterior()` token shape or a full sha256 digest. Tests now
    reject `sha256:not-a-digest`, `sha256:z`, and `not-a-real-hash`.
- Finding: the PR-card kill switch should exercise the public
  `restore_full_a2m()` path with a real ZoA ladder diagnostic axis.
  - Fix: `tests/htt/test_preferred_axis_gate.py` now calls
    `restore_full_a2m()` with `ladder.mock_calibrated.to_diagnostic_axis()` and
    verifies the synthesis lock rejects it before the stub.
- Finding: repo-root export shims did not expose the new `htt.direction`
  surface via `from htt import *`, and backlog mirrors still pointed future
  agents to nonexistent `htt/src/htt` files.
  - Fix: `htt/__init__.py`, `htt/htt/__init__.py`, and
    `htt/test_packaging_imports.py` now cover `htt.direction` and
    `htt.zoa.axis_promotion`; canonical backlog YAML/JSON mirrors and
    long-range markdown mirrors now list the live `htt/htt/htt` paths.
- Finding: `AxisPromotionRecord` fields such as `posterior_bundle_hash`,
  `config_hash`, and `input_hashes` are not matched to upstream artifacts by
  PR-042.
  - Fix: `AxisPromotionRecord` now carries
    `lineage_status="self_attested_pre_solver"` and its docstring/metadata
    state that PR-042 matches axis/sky/mask/mock fields while carrying
    posterior/config/input hashes forward for later bundle wiring.

## Risk log

- DoD:
  - `PreferredAxis.production_allowed` default remains False.
  - Axis promotion for harmonic synthesis requires sky support, mask provenance,
    scan-volume provenance, adequate mock coverage, and a matching promotion
    record.
  - Diagnostic ZoA axes cannot rotate `a_lm` or `a_2m`.
- Kill switch: reject if diagnostic axis can rotate `a_lm` or `a_2m`.
- Residual risks:
  - The promotion record is provenance metadata, not cryptographic proof of
    posterior construction. It blocks missing/mismatched metadata but cannot
    prove caller honesty by itself.
  - The older `htt.infer.axis_gate` and directional-shell gate remain less
    strict for non-harmonic readiness summaries; PR-042 adds the stricter
    downstream synthesis lock rather than rewriting all legacy gate surfaces.
  - Mock/null ensemble validation remains a later PR. This PR requires adequate
    mock-coverage metadata before harmonic synthesis but does not create
    publication-grade null evidence.
