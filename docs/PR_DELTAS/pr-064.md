## Chosen plan

- Added `MatchedNullCompetitionReport` and
  `build_matched_null_competition_report()` in
  `htt/htt/htt/infer/null_competition.py`.
- The report carries an `ArtifactManifest`, stable report hash, config/input
  hashes, generating command, worktree or commit state, `transfer_source=none`,
  sky support status, null-status summary, blocker list, and explicit
  claim-status fields.
- `FamilyCompetitionResult` and `NullCompetitionResult` now validate finite
  FPR/statistic fields, count consistency, nonempty family results, and
  internal family-result consistency.
- `build_null_competition_hook()` now fails closed unless robust structured
  nulls, a passing matched-complexity hook with controls, and a matched-null
  report hash are all present.
- `NullCompetitionHook` now records matched-complexity readiness, matched-null
  report hash, matched-null status, and blocked reasons.
- Existing VER2 tests and integration helpers now pass explicit matched-null
  provenance for intentionally ready fixtures. The BASS-to-HTT adapter accepts
  an optional matched-null report hash and remains blocked when callers request
  null readiness without that hash.
- Backlog mirrors now point PR-064 at the live
  `htt/htt/htt/infer/...` paths rather than stale `htt/src/...` paths.

Rejected alternatives: treating null FPR as model evidence, letting a boolean
stand in for a matched-null report hash, storing MIO certificate material in HTT
gate payloads, labeling external/native transfer status, or allowing family or
geometry claims from null competition.

## Review findings and fixes

- Finding: the initial payload exposed a `headline_bayes_factor_allowed` flag as
  true once matched-null prerequisites passed, which was too strong before
  PR-065 prior/PPC/LOOCV gates.
  - Fix: `headline_bayes_factor_allowed` is now always false in PR-064, while
    `matched_null_headline_gate_passed` records only the matched-null slice.
- Finding: blocked reports with missing null-flexibility scores could raise
  during payload rendering.
  - Fix: blocked payloads now render missing scores as `None` and preserve the
    blocker; added regression coverage.
- Finding: `NullCompetitionResult` could be constructed with inconsistent
  family counts and empty or mismatched family-result maps.
  - Fix: added count/key/value consistency validation and updated fixtures.
- Finding: `build_null_competition_hook()` accepted a passing matched hook with
  empty controls as readiness evidence.
  - Fix: readiness now requires nonempty matched-complexity controls and records
    `matched_complexity_controls_missing` otherwise.
- Finding: the BASS-to-HTT adapter briefly used a hard-coded report hash in the
  explicit ready path.
  - Fix: replaced it with a caller-supplied optional
    `matched_null_report_hash`; without it, the hook remains blocked.
- Finding: the PR-card file paths were stale.
  - Fix: corrected YAML, JSON, and Markdown backlog mirrors to the live
    `htt/htt/htt/infer/...` paths.

## Claim-tier impact

This PR adds an HTT-owned matched-complexity null-competition gate. It is
diagnostic-only pre-solver metadata and a readiness prerequisite surface for
later HTT inference gates. It records null and alternative flexibility,
structured-null FPR, matched-complexity status, report hashes, and blockers.
It does not create decisive evidence wording, MIO certificate content, native
solver validation, transfer validation, morphology compatibility, or geometry
or family claims.
