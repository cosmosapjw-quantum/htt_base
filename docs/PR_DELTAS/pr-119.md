## Evidence-first divergence and SPEC adjudication

Four non-overlapping roles reviewed the frozen PR-118 baseline before code
changes:

- Code mapper steelmanned a small typed COMMON contract over the existing DAG
  and objected to ambiguous bare `C0..C6` levels, owner aliases, and direct
  construction of promoted states.
- Harness engineer steelmanned deterministic YAML authoring with generated
  mirrors and objected to mutable live-worktree validation of the immutable
  PR-118 seal.
- Physics/statistics auditor steelmanned terminal negative receipts for
  completing adjudication aggregation and objected to treating those receipts
  as successful scientific inputs.
- Claim-gate reviewer steelmanned a versioned claim-level namespace and
  default-deny principal registry and objected to internal subagents being
  represented as external replication or scientific promotion authority.

The non-author SPEC review initially rejected five ambiguities: claim identity,
success-edge scientific use, active TSC aliasing, registry roots, and YAML/JSON
mirror semantics. The revised SPEC received
`APPROVE_SPEC_FOR_IMPLEMENTATION`. Subsequent hostile contract review found
forged-boolean receipt, direct scientific-transition, cross-scheme comparison,
unordered-tier, and owner-normalization bypasses; all were patched and the
fresh re-review returned `PASS`.

The final three-axis adversarial review then rejected the first implementation
for a shape-only receipt bypass, terminal-bucket/resolution inconsistency,
floating frozen-authority inputs, mutable reconciliation/checkpoint behavior,
ambiguous bare claim-level prose, incomplete generated-artifact metadata, and
the inherited PR4 subset-download clause. The corrected implementation now
uses typed hash-bound receipt verification with exact scope and trusted
verifier injection, keeps the CLI fail-closed without a trust root, pins the
PR-118/PR-119 authority snapshots, and passed fresh regression review.

Web verification was not required for this PR. It changes repository-local
orchestration and authority semantics only; no mutable external API or package
behavior is used.

## State and dependency semantics

- Orchestration: `PENDING | IN_PROGRESS | TERMINAL | DORMANT_EXTERNAL`.
- Terminal execution resolution:
  `COMPLETED_SUCCESS | COMPLETED_FAILED_WITH_RECEIPT |
  BLOCKED_WITH_RECEIPT | ABANDONED_WITH_RECEIPT`.
- Scientific status:
  `OPEN -> IN_REMEDIATION -> EVIDENCE_READY -> ADJUDICATION_PENDING`, followed
  only by an independently authenticated, claim-identity-bound adjudication.
- `requires_success` accepts only a receipted `COMPLETED_SUCCESS` and carries no
  scientific input.
- `requires_terminal_receipt` accepts any receipted terminal process outcome
  for PR-157 aggregation only and carries no scientific input.
- `requires_adjudicated_claim_set` accepts only a successful aggregation with
  an authorized non-author claim subset.
- `PR-159..166` remain dormant until an independently authenticated native
  delivery receipt exists. External/AniCLASS/proxy paths cannot satisfy it.
