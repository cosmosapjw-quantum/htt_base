## Chosen plan

- Extend `progress_report.py` to parse an optional `skipped` status list.
- Reject skipped IDs that are unknown or overlap with `completed`, `blocked`,
  or `in_progress`.
- Exclude skipped PRs from completed percentages, dependency satisfaction, and
  `unblocked_next`.
- Add `skipped` and `skipped_count` to JSON output and list skipped PRs in
  checkpoint markdown.
- Add `--write-scoreboard PATH` to emit deterministic current progress
  markdown even when a five-PR checkpoint is not due.
- Update checkpoint protocol docs to describe skipped accounting and the
  scoreboard.

Alternatives rejected: storing skipped state as prose only, adding a second
scoreboard generator, or counting skipped PRs as blocked without a distinct
report field.

## Risk log

- DoD:
  - `At least every 5 completed PRs, percent progress and blockers are generated`
  - `Stagnation triggers written replan, not silent continuation`
- Kill switch: Reject if percent progress can be gamed by marking skipped PRs complete.
- Residual risks:
  - A malicious user could still move an item from skipped to completed by
    editing status manually; this harness rejects explicit overlaps and
    incomplete dependencies, but it cannot prove a PR was genuinely completed
    without the review artifacts and tests recorded by the per-PR loop.
  - Progress metrics remain project bookkeeping and not scientific readiness
    evidence.
