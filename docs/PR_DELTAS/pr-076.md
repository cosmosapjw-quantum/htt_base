# PR-076 - Null ensembles and look-elsewhere bookkeeping

## Goal

- Owner: OBSSTAT
- Depends: PR-072, PR-073, PR-074, PR-075
- Level: L3
- Scope: pre-solver
- Risk: high

Add OBSSTAT-owned diagnostic metadata for null ensembles and look-elsewhere
bookkeeping so p-value-shaped feature payloads cannot appear without matched
null provenance. The implementation represents FLRW+mask+noise,
local/systematic, and injected-template null families as metadata contracts,
then validates them at `ObservableVector` assembly time.

This PR does not generate null mocks, run or fake a native solver, validate
transfer, create HTT evidence/posterior content, create MIO certificate
content, establish morphology compatibility, or support geometry/family claims.

## Chosen plan

- Add `NullEnsembleSpec` for declared OBSSTAT null ensemble provenance with
  allowed null families, mock count, feature/statistic keys, sky/mask/noise/
  covariance/null status, config/input hashes, generating command, and git or
  worktree provenance.
- Add `LookElsewhereBookkeeping` for scan-volume metadata, derived SHA256
  scan-volume hash, correction method, pre-registration status, trial count,
  and explicit tail definitions.
- Add `NullCalibratedFeature` plus
  `build_null_ensemble_feature_payload()`/`validate_null_feature_payload()` to
  serialize and validate diagnostic-only null feature payloads.
- Make `ObservableVector` validate a typed `null_features` payload
  whenever p-value-shaped keys appear in scalar, morphology, null, BiPoSH, or
  other feature blocks, including p-values nested inside lists or tuples.
- Export the new OBSSTAT module through `htt.obsstat` and top-level
  `obsstat`, with packaging identity tests.

Rejected alternatives: generating null mocks, deriving empirical p-values,
creating HTT likelihood/evidence inputs, creating MIO certificate content,
using BASS/native transfer metadata, and allowing scalar or morphology feature
tails to imply geometry/family claims.

## Review findings and fixes

- Finding: the first payload caveat used a word that the local overclaim guard
  correctly rejected.
  - Fix: the default caveat now says diagnostic descriptor with no model-input
    role, and the guard still rejects certificate-like wording elsewhere.
- Finding: `ObservableVector` only checked loose `null_ensemble_ref` and
  `look_elsewhere_status` fields.
  - Fix: p-value-shaped keys now fail closed unless accompanied by a typed
    PR-076 diagnostic-only `null_features` payload.
- Finding: p-value-shaped keys nested inside lists could bypass the recursive
  scanner.
  - Fix: key, string-value, and metadata lookup walkers now recurse through
    non-string sequences, with regression coverage.
- Finding: existing scalar and morphology tests still used legacy loose null
  metadata.
  - Fix: test fixtures now build typed PR-076 null payloads and preserve the
    older scalar/morphology payloads as feature-only inputs.
- Finding: the literal PR-card command uses host `python`, which lacks pytest
  in this workspace.
  - Fix: the failed host command is recorded explicitly, and the equivalent
    venv-backed command is the authoritative passing run.
- Finding: post-implementation reviewers found that transfer-derived feature
  metadata recursed through mappings but not list-wrapped feature payloads.
  - Fix: transfer-provenance recursion now descends through non-string
    sequences, with regression coverage for list-wrapped `transfer_derived`
    payloads.
- Finding: post-implementation reviewers found that a typed null payload for
  one statistic could accompany an unrelated p-value-shaped feature key.
  - Fix: `ObservableVector` now extracts p-value statistic keys, including
    keys inside `p_values` containers and lists, and requires the typed
    diagnostic-only null payload to cover those statistics.
- Finding: post-implementation reviewers found that serialized null payload
  validation was weaker than the dataclass constructors.
  - Fix: `validate_null_feature_payload()` now rechecks scan-volume hash
    derivation, trial-count/status consistency, allowed tail names,
    non-empty feature targets, required provenance fields, and nested
    `null_ensemble` / `look_elsewhere` consistency.

## Claim-tier impact

This PR adds OBSSTAT diagnostic-only null provenance and look-elsewhere
bookkeeping for feature p-values. It is metadata validation only and does not
estimate null distributions, generate mocks, create model-dependent inference,
validate transfer, or establish morphology, geometry, or family conclusions.

## Risk log

- DoD:
  - FLRW+mask+noise, local/systematic, and injected-template null families can
    be represented.
  - Look-elsewhere metadata attaches to feature vectors.
  - P-values are rejected unless a typed null ensemble payload is present.
- Kill switch:
  - Satisfied. P-value-shaped keys without PR-076 null provenance fail closed.
- Remaining risk:
  - The PR records provenance for null ensembles but does not generate or audit
    the null mock bank itself. Downstream PRs must keep empirical tail
    generation and validation separate from this OBSSTAT metadata contract.
