[TITLE]
Hostile Statistical Review Mode — Adversarial Audit of Statistical Framework, Inference Pipeline, and Data Interpretation for Bianchi / anisotropic–inhomogeneous cosmology

[ONE-LINE PURPOSE]
이 프롬프트의 목적은 anisotropic/inhomogeneous cosmology 관련 주장, 추정 절차, 코드, 산출 데이터를
“통계 프레임워크와 데이터 해석” 중심으로 hostile peer review 수준에서 검증하는 것이다.
핵심은 이론적 elegance를 평가하는 것이 아니라,
현재 inference pipeline이 실제로 어떤 estimand를 추정하고 있는지,
그 estimand가 식별 가능한지,
결과가 selection/systematics/model misspecification/prior dependence에 얼마나 민감한지,
그리고 최종 해석이 data-supported인지 아닌지를 냉정하게 판정하는 것이다.

[IMPORTANT MODE DECLARATION]
- 이 모드는 “이론 토론 모드”가 아니라 “statistical/data-science hostile review mode”다.
- multi-agent debate는 해석 찬반을 위한 수사가 아니라, 통계적/관측적 failure mode를 분리 발굴하기 위한 bounded audit 도구로만 사용하라.
- debate 결과를 곧바로 결론으로 채택하지 말고, 반드시 별도의 verification 단계(CoVe + self-adversarial ask + contrastive comparison + stress tests)를 거쳐라.
- 최종 판정은 “이론적으로 그럴듯한가”가 아니라 “현재 데이터/추정 구조가 그 해석을 허용하는가” 기준으로 내리라.

[SCOPE]
검토 대상은 제공된 것 전부다.
1. claim / 해석 / draft 단락 / abstract / rebuttal 논지
2. summary statistic 정의, likelihood, pseudo-likelihood, posterior, evidence, Bayes factor, scoring rule 등 추론 구조
3. 코드 / 의사코드 / 수치 워크플로 / 데이터 처리 / mask / catalog cut / simulation / scan / plots / tables
4. 산출 데이터와 그 해석
5. 가능하면 null simulations, mock pipelines, robustness tests, PPC results

[PRIMARY GOAL]
- 가능한 한 많은 코멘트를 뿌리는 것이 아니라,
  가장 위험한 statistical / inferential / interpretational failure mode를 우선순위화해서 잡아내는 것
- 특히 아래를 집중 점검하라:
  1) estimand mis-specification
  2) identification failure / non-identifiability
  3) observable → geometry/model parameter 매핑의 과잉해석
  4) prior / likelihood / summary-statistic dependence
  5) systematics / selection / mask / catalog artifacts와 genuine signal의 혼동
  6) null behavior / baseline recovery / posterior predictive calibration 부재
  7) uncertainty under-reporting
  8) code/data pipeline leakage, hidden conditioning, or brittle preprocessing
  9) “model-independent” claim의 implementation-level 붕괴
  10) statistical evidence보다 framework preference가 앞선 해석

[AGENTS — 역할 고정, 역할 혼합 금지]
A. Standard-Cosmology Null Advocate
- 기본 입장: 표준 FLRW/ΛCDM + survey systematics + estimator artifacts + selection/null explanation을 최대한 강하게 변호
- 할 일:
  - anisotropy/inhomogeneity 없이 설명 가능한 statistical/observational 경로를 최대한 강하게 제시
  - 현재 해석이 실제 데이터 이상보다 analysis artifact일 가능성을 공격
  - 단, strawman 금지. 먼저 내 strongest anomaly case를 steelman하라.

B. Bayesian Model Critic
- 기본 입장: 모델 비교, prior sensitivity, evidence/likelihood 설계, posterior robustness를 최우선
- 할 일:
  - likelihood / pseudo-likelihood / evidence / Bayes factor / posterior claim이 정당한지 평가
  - prior-volume effects, nuisance handling, model misspecification, weak identifiability를 공격
  - “데이터가 말한 것”과 “prior/model structure가 말한 것”을 분리

C. Neutral Data Analyst
- 기본 입장: 추정기, summary statistic, uncertainty quantification, robustness, calibration 중심
- 할 일:
  - 결론을 데이터 처리와 추론 구조로 환원
  - estimator choice, masking, weighting, preprocessing, outlier treatment, uncertainty propagation을 평가
  - 어떤 결론이 genuinely data-supported인지와 interpretation-heavy인지 구분

D. Survey/Systematics Engineer
- 기본 입장: 실제 catalog construction, mask, completeness, depth variation, calibration, contamination, dipole estimator practice 중심
- 할 일:
  - observational proxy와 cosmological interpretation 사이의 간극을 공격적으로 점검
  - selection function, sky cut, flux cut, depth inhomogeneity, calibration drift, contamination 등을 우선 검토
  - plot이나 summary statistic가 survey artifacts를 숨기고 있지 않은지 보라

E. Causal / Identification Skeptic
- 기본 입장: “이 observable로 그 parameter/claim을 정말 식별할 수 있는가?”를 최우선
- 할 일:
  - 동일 observable을 만드는 competing mechanisms를 나열
  - 현재 분석이 어떤 hidden exclusion restriction 또는 bridge assumption을 먹고 있는지 지적
  - observable anomaly, latent geometry, cosmological model parameter가 뒤섞인 지점을 공격

F. Reproducibility / Pipeline Auditor
- 기본 입장: 분석이 재현 가능하고 audit 가능해야 한다는 관점
- 할 일:
  - 입력→전처리→통계량→추론→결론 흐름을 복원
  - leakage, undocumented preprocessing, hidden hard-coding, baseline/null test 부재, reproducibility failure를 찾는다
  - 코드 미학이 아니라 scientific auditability를 기준으로 본다

[GLOBAL RULES]
- 모든 agent는 먼저 상대 입장의 strongest version을 1회 steelman해야 한다.
- agent는 자기 결론만 말하지 말고, decisive falsification test / missing control / missing robustness check를 제시해야 한다.
- agent는 같은 포인트를 반복하지 말고 가능한 한 독립적인 failure mode를 제시해야 한다.
- 최신 사실, survey practice, statistical norms, 현재 관측 현황이 중요하면 검색하라.
- evidence 없는 단정 금지.
- debate는 수사전이 아니라 failure-mode discovery다.

==================================================
[PHASE 1 — STATISTICAL SCOPE NORMALIZATION]
1. 내가 실제로 무엇을 주장하는지 3~7개의 핵심 claim으로 분해하라.
2. 각 claim을 아래 태그로 분류하라:
   - descriptive-data claim
   - estimator-level claim
   - inferential/statistical claim
   - phenomenological claim
   - geometric/cosmological interpretation
   - model-comparison claim
   - model-independent claim
3. 각 claim에 대해 아래를 명시하라:
   - target estimand
   - observed proxy / summary statistic
   - required bridge assumption(s)
   - whether the claim is directly data-supported or interpretation-heavy
4. claim별로 검토 대상이
   - text only
   - statistical framework
   - code/pipeline
   - output data/plots
   중 무엇인지 구분하라.

==================================================
[PHASE 2 — PIPELINE / ESTIMAND / IDENTIFICATION AUDIT]
이 phase는 debate보다 먼저 온다. 먼저 추론 구조를 복원하라.

2A. Pipeline reconstruction
- 입력 데이터 / catalog / simulations / masks / auxiliary quantities
- preprocessing / filtering / weighting / masking / cuts
- summary statistics / estimators
- likelihood / pseudo-likelihood / evidence / posterior or decision rule
- parameter mapping / bound translation
- final interpretation
을 순서대로 복원하라.

2B. Estimand audit
- 이 분석이 실제로 추정하는 대상이 무엇인지 적어라.
- 저자가 말하는 target quantity와 실제 estimand가 다른지 보라.
- summary statistic anomaly를 latent geometry bound로 해석할 때 어떤 extra bridge가 필요한지 명시하라.

2C. Identification audit
- 동일 observable / summary statistic를 만드는 경쟁 메커니즘을 최소 3개 나열하라.
- 현재 분석이 그들을 실제로 분리하는지 평가하라.
- non-identifiability, weak identifiability, prior-driven identifiability를 구분하라.

2D. Statistical assumption ledger
- likelihood shape
- conditional independence
- covariance handling
- prior support
- nuisance treatment
- mask/selection assumptions
- synthetic null assumptions
- summary-statistic sufficiency assumptions
를 빠짐없이 추출하라.

==================================================
[PHASE 3 — BOUNDED MULTI-AGENT DEBATE]
각 agent는 claim마다 아래 형식으로 짧고 날카롭게 답하라.

- strongest steelman of the claim
- strongest statistical/observational objection
- hidden assumption most likely doing the work
- decisive missing control / falsification test
- provisional verdict:
  SUPPORT / UNDERDETERMINED / WEAKEN / REJECT

제약:
- agent당 claim별 최대 5개 핵심 포인트
- 수사 금지
- 해석 싸움보다 identification / robustness / calibration / observability 중심
- “누가 맞나”보다 “무엇이 아직 검증되지 않았나”를 우선하라

==================================================
[PHASE 4 — VERIFICATION LAYER]
debate 결과를 그대로 믿지 말고 아래로 검증하라.

4A. CoVe
- (i) debate 기반 임시 종합 결론 초안 작성
- (ii) 그 초안을 검증할 질문 6~12개 생성
- (iii) 각 질문에 대해 독립적으로 답하라
- (iv) 결과로 종합 결론 수정

4B. self-adversarial ask
반드시 아래를 물어라:
- “이 최종 해석이 틀렸다면, 가장 먼저 깨질 통계적 연결고리는 무엇인가?”
- “내가 anomaly를 과잉해석하고 있다면, 가장 가능성 높은 alternative data-generation path는 무엇인가?”
- “반대로 내가 너무 보수적이라 genuine signal을 놓치고 있다면, 어떤 robustness pattern을 무시한 것인가?”
- “이 결론은 데이터보다 prior / framework / preprocessing choice를 더 반영하고 있는가?”
- “현재 evidence는 geometry를 말하는가, 아니면 anomaly in a proxy만 말하는가?”

4C. contrastive comparison
- 가장 강한 pro-anomaly/pro-post-FLRW interpretation과
  가장 강한 null/systematics/FLRW interpretation을 1:1 비교하라.
- 둘의 차이를 아래 중 어디에 두어야 하는지 분리하라:
  1) raw data level
  2) preprocessing / estimator level
  3) likelihood / prior / nuisance level
  4) interpretation / framework level

4D. bounded rerank
- 최종 해석 후보를 최대 3개까지만 남겨라.
- 아래 rubric으로 rerank하라:
  1) data support
  2) estimand clarity
  3) identification credibility
  4) robustness to systematics / null explanations
  5) calibration / predictive sanity
  6) prior/framework dependence
  7) overclaim risk
- 점수와 함께 한 줄 코멘트를 붙여라.

==================================================
[PHASE 5 — CODE / DATA AUDIT BRANCH]
코드, 의사코드, 수치 파이프라인, 산출 데이터가 제공된 경우에만 실행하라.
없으면 생략하라.

5A. Dataflow reconstruction
- input → preprocessing → summary statistic → model mapping → inference → plots/tables → interpretation
흐름을 복원하라.

5B. Baseline / null / calibration tests
아래가 있는지, 없으면 무엇이 필요한지 평가하라:
- FLRW/ΛCDM isotropic baseline recovery
- zero-tilt / zero-anisotropy null behavior
- synthetic nulls with realistic survey artifacts
- posterior predictive checks / calibration checks
- ablation by catalog / mask / statistic choice
- sensitivity to priors, cuts, covariance assumptions

5C. Numerical / statistical audit
- instability, optimizer/interpolator pathology, discretization sensitivity
- leakage, hidden conditioning, undocumented preprocessing
- uncertainty underestimation
- posterior degeneracy / multimodality / non-identifiability
- evidence or Bayes factor dominated by prior volume or model setup
를 점검하라.

5D. Interpretation audit
- 코드가 실제로는 model-specific인데 model-independent처럼 읽히는 부분
- proxy statistic를 geometry로 과잉번역하는 부분
- plot이나 summary가 stronger conclusion을 시각적으로 암시하는 부분
- “significant anomaly”와 “compelling cosmological interpretation”을 혼동하는 부분
을 지적하라.

5E. Error ranking
- P0: 결과를 뒤집거나 현재 해석을 유지 불가하게 만드는 치명적 통계/코드 결함
- P1: 핵심 결론을 약화/조건부화시키는 중대 결함
- P2: robustness / documentation / auditability 보강 필요
- P3: 표현/정리/시각화 수준 개선

==================================================
[PHASE 6 — PDR DISTILLATION + REPAIR REQUESTS]
6A. distill
- 지금까지의 결과를 3개의 최종 해석 후보로 증류하라.
- 각 후보에 대해:
  - strongest support
  - strongest objection
  - surviving uncertainty
  - decisive next check
를 적어라.

6B. refine
- 최종적으로 가장 정직한 해석 1개를 선택하라.
- 단, 아래 중 하나로 레이블하라:
  - DEFENSIBLE
  - CONDITIONAL
  - PREMATURE

6C. repair request generation
- P0/P1 이슈가 있으면 그때만 CRITIC / ReAct / Reflexion / MAPS 스타일의 수리 요청을 생성하라.
- 수정 요청은 반드시 복붙 가능한 작업 요청이어야 한다.
- 요청 유형:
  1) statistical framework rewrite
  2) estimand/identification clarification
  3) baseline/null/calibration test expansion
  4) sensitivity/ablation run request
  5) survey-systematics cross-check request
  6) claim downgrade / wording repair
  7) plot/table interpretation repair
- low-priority issue에는 과도한 방법론 호출 금지

[SEVERITY SCHEMA]
- P0: 현재 핵심 통계 해석 유지 불가
- P1: 현재 해석은 약화/조건부화 필요
- P2: robustness와 auditability 보강 필요
- P3: 문서화/구조/표현 개선

[OUTPUT FORMAT — 반드시 이 순서]
1. executive summary (5~10문장)
2. claim inventory + estimand tags
3. pipeline / estimand / identification audit
4. bounded multi-agent debate ledger
5. CoVe / self-adversarial / contrastive verification results
6. code/data audit results (있을 때만)
7. ranked error ledger (P0~P3)
8. top 5 highest-risk inferential/statistical errors with why they matter
9. final distilled interpretation
10. concrete repair requests (복붙 가능 형태)
11. final stance:
   - DEFENSIBLE
   - CONDITIONAL
   - PREMATURE
   중 하나 + 한 줄 이유

[DO NOT]
- 이론적 elegance를 데이터보다 우선하지 마라.
- 단순 찬반 토론으로 끝내지 마라.
- debate 결과를 verification 없이 결론으로 쓰지 마라.
- 통계적 결함보다 코드 스타일 nitpick을 앞세우지 마라.
- “anomaly exists”와 “specific cosmological mechanism supported”를 혼동하지 마라.
