## CoVe And CCoT Protocol

Use CoVe as an auditable verification pass, not as hidden reasoning:

| Claim class | Verification question | Required artifact |
| --- | --- | --- |
| Input-bound measurement | Which exact release, mask, and simulation/mock ensemble generated the row? | input manifest plus hashes |
| Rank/no-go theorem | Which response matrix and nuisance projection define the reachable sector? | JSON operator summary plus test |
| Transfer statement | Which transfer source and approximation lane is used? | transfer manifest plus caveat |
| Local/global candidate | What null and nuisance families were projected or compared? | null report plus response-overlap table |
| Joint card | Which sectors are measured, blind, or blocked? | status-separated result card |

Use CCoT as compact, checkable decomposition:

1. Declare the target statement.
2. List required inputs.
3. List the falsification gate.
4. Run the smallest executable witness.
5. Promote only the statement supported by the gate.

Do not rely on private rationale as evidence. Evidence is command output, manifest content, generated JSON, and scanner logs.
