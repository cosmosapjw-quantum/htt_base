1. 사용자의 기존 primary checkout에서 git status와 HEAD를 확인한다. dirty 변경은 보존한다. git fetch origin 후 위 브랜치로 안전한 전환/fast-forward만 한다. 새 clone/worktree, force-push, main merge, remote desktop은 하지 않는다.
2. AGENTS.md, RESEARCH_DAG.json(R52), IMPLEMENTATION_CONTRACT.json, R51/R51_REPORT_KO.md, R51/R51_SOURCE_OPERATOR_CONTRACT.json을 읽는다.
3. 먼저 회귀와 R51 관측 실행을 재현하고 stdout/exit code를 저장한다. 재현은 baseline reuse로 기록하고 새 성과로 집계하지 않는다:
   PYTHONPATH=htt/src:htt:. python -m pytest tests/r49 tests/r50 tests/r51 -q
   PYTHONPATH=htt/src:htt:. python scripts/r51/run_r51_pr3_lowell.py   (원자료 /mnt/extdrive/workdir 필요, 약 6.5분, 최대 RSS 약 4.9GB; 결과 파일을 덮어쓰므로 커밋본과 비교 후 복원)
4. R51에서 확정된 규칙을 유지한다:
   - 물리 추론은 R49GeneralBianchiLikelihood(response_policy="source_bound") 또는 그 후속만 사용한다. r49_working_model은 과거 receipt 재현 전용이다.
   - CMB의 Sigma(z_*->0 시선 적분 shear)와 오늘의 sigma/H0는 다른 epoch다. 명시적 history operator로만 연결한다(현재 Bianchi-I, 비등방 stress 없음 조건부 I_hist=3.927e4).
   - MC로 추정한 공분산에는 finite-MC(Sellentin-Heavens) law를 쓴다. 그 law에서 tensor carrier는 (F,t,Q0)가 필요하다. plug-in Gaussian은 heldout에서 기각됐다.
   - 하나의 Gaussian에서 mu와 C가 같은 모드에 함께 있어도 된다. 같은 data block을 두 독립 factor에 넣는 것만 DataBlockRegistry로 막는다.
   - Commander primary calibration은 matching MC가 없어 unavailable이다. SMICA는 SMICA 진단 lane으로만 부른다. PR4 NPIPE와 새 다운로드는 critical path에 넣지 않는다.
   - 옛 null_beta/ffp10_null_beta는 쓰지 않는다. 같은 추정량 joint null 반복이 없으면 BETA_MO_MATCHED_NULL을 출력하지 않는다.
5. R52 작업(RESEARCH_DAG.json#R52):
   - CF4 grouped distance/selection likelihood로 방향별 monopole/dipole/STF quadrupole을 공통 calibration nuisance와 함께 적합한다. reconstruction grid를 독립 은하처럼 넣지 않는다.
   - Gaia E1/B1/E2 공동 공분산을 쓰고 E2는 R50의 endpoint-history 응답 A_PM=2c(B_o-B_s)/D-dot B_o에 연결한다. frame spin과 공간계통을 marginalize하고 순간 sigma/H로 부르지 않는다.
   - beta_MO와 beta_RM history 응답을 분리 유도한다. Pantheon+는 z_HD의 상위 보정(Carr et al. 2022)을 결합한 저-z Heinesen jet와 remainder로만 사용한다.
   - 각 깊이와 공동 probe에서 nuisance-projected response 특이값과 estimand kernel을 계산한다. likelihood rank를 기록한 뒤에만 proper prior를 더한다.
   - Cobaya Likelihood/Theory provider를 같은 정규화 likelihood로 확장하고 검증된 sampler를 유지한다. 다섯 view는 하나의 posterior에서만 계산한다.
6. 매 변경은 구체 실패 -> 최소 수정 -> 회귀/물리극한 -> 보유 실자료 실행 -> 한 번의 독립 심사 순서로 한다. tolerance, source hash, claim 상태를 통과시키려고 바꾸지 않는다.
7. raw 자료와 chains는 로컬에 둔다. R52_RESULT.json, identified_combinations.npz, joint_posterior_summary.json, cobaya_config.yaml, chain_manifest.json, test_log.txt를 커밋한다. canonical DAG/status와 machine_readable mirror, 이 재개 프롬프트를 갱신하고 non-force push한다.
