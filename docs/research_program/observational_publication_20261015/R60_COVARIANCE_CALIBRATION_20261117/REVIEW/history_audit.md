## Concrete old defect relevant to the parent's new route

`htt/obsstat/cf4_growth_covariance.py::amplitude_mle` at the baseline still states that the whitened amplitude score is monotone decreasing and returns A=0 whenever score(0)<=0. This is already disproved in `docs/research_program/mes_verified_checkpoints_20260928/I1/recovery/research/audit_prose/audit_v4/report-source.md` and flagged for replacement in `tensor_joint_r7/REUSE_MAP.md:32`.

For C(A)=A S+N and fixed mean, l(A)=-1/2 sum_i[log(1+A lambda_i)+p_i^2/(1+A lambda_i)]. The exact counterexample lambda=(100,1), p^2=(0,20) has l'(0)=-81/2 but l(1)-l(0)=(10-log 202)/2>0. This is an implementation/numerical optimization error, not a cosmological effect. For positive eigenvalues, U=max(0,max_i((p_i^2-1)/lambda_i)) bounds every fixed-mean global maximizer. The profiler must evaluate all relevant extrema or use a justified bounded global search; a single endpoint/root is insufficient. That U must not be copied without derivation into a problem where the mean is also profiled.

The historical note says the impact on actual CF4 results was not computed. R58's new fixed-C code does not call this legacy function, so this defect alone does not invalidate R58. If a new covariance-amplitude route uses it, correction and the exact counterexample are immediately necessary.
