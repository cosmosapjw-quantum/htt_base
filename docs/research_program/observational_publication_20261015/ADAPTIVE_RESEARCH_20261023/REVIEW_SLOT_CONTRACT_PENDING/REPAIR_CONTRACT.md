## Minimal coherent repair

The scope is one typed source-closure helper used by the optional review context, with **the two exact input identities above as its actual acceptance consumers**. The helper should interpret source types generically; it must not add task-ID-specific dispatch or an allegedly reusable scheduler restricted to spent task IDs. Preserve legacy behavior for other untyped tasks, while allowing explicit, sealed future contract/data/reference declarations through the same helper. Do not add mandatory metadata to, reseal, rewrite, or weaken any frozen task/input/candidate. A small explicit compatibility interpretation for these existing source schemas and records is preferable to pretending their old documents already carry a new field. Any compatibility role map binds the exact frozen root and source record identities, not a task name alone.

The helper must distinguish three types:

- **External reference:** string HTTP(S) reference, or a strictly recognized URL-only dictionary (the observed `url` plus optional textual `scope` form). Retain its identity as part of the enclosing sealed metadata. Do not fetch it, resolve it locally, or count it as a local read. If a record also has local declarations, either process all of them under a supported explicit type or reject the unsupported mixed record; never silently skip it. Unknown schemes/malformed records continue to refuse.
- **Contract/manifest:** bounded JSON metadata with declared dependency containers or supported manifest inventories. Preserve the existing maximum 1MiB per metadata document, 4MiB cumulative parsed metadata, 64 documents, depth 16, and 256 declared local scopes. Traverse declared fields only; do not scan arbitrary prose, expand directories, or infer paths from arbitrary strings.
- **Data/code leaf:** a local source whose bytes are used but whose serialization extension does not make it a dependency contract. It remains in the complete local read closure and receives a streaming SHA/size seal. For the oversized property table, authorize leaf classification only through the exact frozen root input and its already sealed path/SHA/size record; do not grant a generic `large JSON => data` exemption or trust an unvalidated mutable role label. The frozen role map must not downgrade a contract, manifest, or record that declares local sources.

Recognize the actual local declaration forms without losing their validation:

1. Existing `input_sources`, `sources`, and `inputs` string/path-record lists.
2. The explicit `source_id_input` and `method_source` path records.

Resolve source-manifest-relative names using the existing ambiguity rejection policy. Preserve all declared inventory members, even if another path already reaches the same bytes. Deduplicate actual hashing by resolved file while checking every declaration for consistency.

For each local declaration, retain the lexical alias and resolved target, confirm the target exists, reject missing/ambiguous paths and unsupported glob/scheme forms, enforce declared `resolved_path`, validate declared SHA and both size spellings, and reject conflicting duplicate declarations.
