# 원래 acceptance를 향한 연구 경로 재정렬

이 묶음은 이미 독립검토된 결과의 출판 준비본이다. canonical 채택, Git publication, 물리 admission을 실행하지 않는다. 감사 당시 원래 external 기준선은 **17/42**, V03 analytic alternate를 포함한 기준선은 **18/42**다. 확장 작업 **44/75**는 상속18개와 새 조건부 실행을 포함한 당시 snapshot이며 원래 acceptance의 증가 증거가 아니다. 감사 이후 root가 **2026-10-23T23:23:18.676306+00:00**에 [S02/S03 adoption](FOLLOWTHROUGH/ACTUAL_S02_S03_ORIGINAL_SCOPE_ADOPTION.json)을 실제 기록했다. 현재 명시적 original scoped 수용은 **19/42=45.2381%**, analytic alternate 포함 **20/42=47.6190%**이며 확장 완료는 **46/75=61.3333%**다. 기준선과 감사 원문17/42·18/42·44/75는 그대로 둔다. 이것은 unchanged 원래 조건부 의무에 대한 별도 채택이며 새 조건부 task 자동 승격이 아니다.

## 감사가 드러낸 전략 실패

root controller가 원래 의무를 닫는 입력·실행 전이를 마련하지 못한 채, 실행 가능한 조건부 결과와 보증 작업을 늘린 것이 전략 실패다. 이는 개별 worker나 모델의 책임으로 돌릴 문제가 아니다. [동결된 독립 ultra 감사](AUDIT/REPORT_KO.md)의 일곱 finding을 실행 선택에 적용한다.

1. 원래 목표와 확장 작업 분모를 함께 표시한다. task 완료 수를 원래 과학 acceptance로 환산하지 않는다.
2. 선택한 방법의 실패를 원래 목표의 보편 AND로 고정하지 않는다. 대체 경로는 같은 원래 의무를 실제 충족할 때만 소비한다. 과거 frozen 계약은 고쳐 쓰지 않는다.
3. 이미 결과가 있는 조건부 질문에는 종료점을 둔다. 같은 질문의 새 view·sensitivity를 늘리는 대신 원래 root 결손이나 명명된 새 과학 질문을 다룬다.
4. 실제 규모의 메모리 수명 검증이 full7 실행 전에 부족했다. 현재 허용된 memory/source guard 수리를 같은 task·연산자·입력·잔여 예산 안에서 끝내고 실제 native host가 결과를 소비하게 한다.
5. 되돌릴 수 없는 실행 계약 실패를 새 assurance로 복원하려 하지 않는다. 과거48/R9, one-use 할당, 실패 receipt, 초과 사용, ultra 기록과 누적 비용을 그대로 보존한다.
6. 외부 atlas/payload 부재와 native solver/ODE 금지 아래 전체42 완료를 보장하지 않는다. 정확한 외부 HOLD와 진행 가능한 독립 질문을 구별한다.
7. 모델, compaction, 병렬성에 지연을 정량 배분할 근거는 없다. 실제 입력·메모리·연산자·실행 소비 결손을 고친다. 기존 ultra 감사는 여기서 재사용하며 전면 감사를 반복하지 않는다.
