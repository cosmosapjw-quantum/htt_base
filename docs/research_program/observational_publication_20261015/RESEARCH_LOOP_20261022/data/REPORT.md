## Main source correction: Pantheon+ frame and likelihood convention

The pinned [Pantheon+ distance README](https://github.com/PantheonPlusSH0ES/DataRelease/blob/c447f0fea703fcd0fff57de5000947b5ca81286b/Pantheon%2B_Data/4_DISTANCES_AND_COVAR/README) calls `zCMB` the CMB-corrected redshift, `zHD` the Hubble-diagram redshift with CMB and peculiar-velocity corrections, `zHEL` the heliocentric redshift, and `m_b_corr` the standardized apparent magnitude. The [release's SN-only CosmoSIS likelihood](https://github.com/PantheonPlusSH0ES/DataRelease/blob/c447f0fea703fcd0fff57de5000947b5ca81286b/Pantheon%2B_Data/5_COSMOLOGY/cosmosis_likelihoods/Pantheon%2B_only_cosmosis_likelihood.py) selects `zHD > 0.01`, reads `m_b_corr`, and compares it with

\[
m_{\rm th}=5\log_{10}\!\left[(1+z_{\rm HD})(1+z_{\rm HEL})D_A(z_{\rm HD})/{\rm Mpc}\right]+25+M.
\]

If `D_A` is the ordinary angular-diameter distance, this is equivalently `D_L(zHD) (1+zHEL)/(1+zHD)`, or in flat FLRW `D_L=(1+zHEL)c/H0 integral_0^zHD dz/E(z)`. This equivalence is an algebraic inference from the released code, not a statement that its corrected redshift is the analytic normal-frame observable. The [release's joint Pantheon+–SH0ES likelihood](https://github.com/PantheonPlusSH0ES/DataRelease/blob/c447f0fea703fcd0fff57de5000947b5ca81286b/Pantheon%2B_Data/5_COSMOLOGY/cosmosis_likelihoods/Pantheon%2BSH0ES_cosmosis_likelihood.py) instead includes `zHD > 0.01 OR IS_CALIBRATOR` and compares calibrators to `CEPH_DIST`; it uses the same Hubble-flow expression for noncalibrators. Both trim the original-order full covariance by their row masks. The README explicitly warns that diagonal magnitude errors are not a cosmology fit covariance.

[Carr et al., arXiv:2112.01471v2, §5, Eqs. 2–7](https://arxiv.org/html/2112.01471) provides the source-side redshift semantics: `(1+zHEL)=(1+zCMB)(1+zSun)=(1+zHD)(1+zSun)(1+zp)`. `zCMB` removes observer Solar motion; `zHD` additionally removes the *estimated* source peculiar redshift. `zp` is positive for recession under their convention. [Brout et al., arXiv:2202.04077v2, §III.1.2–3](https://arxiv.org/html/2202.04077) states that heliocentric redshifts enter SALT2 fitting and that baseline PV corrections are based on 2M++/group assignments; the released covariance includes velocity uncertainty. These source conventions do not independently establish a total-energy normal-to-CMB frame map, a coherent-flow response of the fitted/removed `zp`, or a finite optical/calibration/selection remainder.

The retained 1,701-row Pantheon table and 651-row D03 index were inspected without rerunning the fit. `zHD != zCMB` on 1,692/1,701 released rows and 645/651 D03 rows; the D03 median `|zHD-zCMB|` is 0.00040 and maximum is 0.00156. Only 556/651 D03 rows satisfy the released SN-only `zHD>0.01` cut. The cached D03 `zCMB` array matches its original table column exactly. [verify_sources.py](verify_sources.py) reproduces these read-only counts after checking source and D03 hashes. Therefore the existing 651-row zCMB projection is a fiducial template calculation and cannot be described as the released likelihood response. No revised F04 projection was run in this task.
