# Codex 연속 연구 인계 프롬프트

아래 블록을 로컬 Codex에 그대로 붙여넣는다. `METHOD_FRONTIER.json`은 계획이며 아직 runtime state로 append되지 않았다. 존재하지 않는 `append-frontier` 명령을 실행하라는 뜻이 아니다. 먼저 최소 패치를 구현·검증한다. 연구 수식과 retained-summary 결과는 이미 실행된 증거이므로 그대로 재사용한다.

```text
당신은 cosmosapjw-quantum/htt_base의 HTT campaign controller다. 목표는 기존 6개 논문/42개 원래 scientific objective를 최대한 달성하면서, native Boltzmann solver나 ODE를 만들거나 풀지 않고 가능한 모든 구별 가능한 연구 경로를 실제 결과까지 진행하는 것이다. 한 노드, 한 PR, 한 감사 문서를 끝냈다고 종료하지 마라. fixed-plan ready:[]를 전체 연구 소진으로 해석하지 마라.

먼저 실제 checkout/branch/HEAD/AGENTS.md를 읽고 작업 변경을 보존하라. 새 패키지 docs/research_program/observational_publication_20261015/METHOD_REBOOT_20261023/의 README_KO.md, THEOREMS.md, METHOD_FRONTIER.json, REVIEW_MATH.md, REVIEW_PLAN.md, agent_dag_audit.md를 읽어라. 기준 source HEAD는 cd2bf729f12a4229f0bb423850372a511dcff78b다. 이후 변경이 있으면 관련 소비 경로만 비교하라. 전체 repo를 재감사하는 것으로 시작하지 마라.

원래 external-output 17/42, V03 analytic alternate18/42를 보존한다. 원래 V03 외부 history, B02 physical atlas, 2048 source physical unknown mass1, 97 LP/D07 endpoint crossing, 628/274 실제 실패 T=4.5553218238,p=.0009763241396, SN nominal parity 실패, K03 물리 HOLD를 새 conditional 결과로 지우지 마라. 원래 acceptance를 충족한 실제 증거가 생겼을 때만 정확한 objective/acceptance/prerequisite mapping을 독립 검토하여 승격하라. 대체 estimand는 별도 연구 결과다.

핵심 표현은 full tensorized (x,F,Pi,Q,G_F)다. July tensor plan과 docs/research_program/tensor_joint_r9/revision2/MODEL_TO_DATA.md를 재사용하라. x는 typed functional bundle, Q는 anchor gauge/margin, F는 support/pushforward/occupancy를 구별한 객체, Pi는 explicit-law exceedance surface, G_F는 full-covariance functional depth path다. x_C/U_sigma와 floored bin ratio는 eligible legacy projections일 뿐이다. 원 Y 또는 (Y0,DeltaY)와 전체 cross covariance를 유지하라. signed/zero/undefined/unbounded strata를 버리거나 zero fill하지 마라. shared nuisance/anchor는 같은 confidence event에서 교차한 뒤 사영하라. 기존 R9 alpha는 동결하며 새 검정에 사후 전용하지 마라.

기존 .agent-harness/runtime/r23-continuous/STATE.json과 48-task campaign을 재초기화하지 마라. 실제 상태를 복사한 fixture로 최소 controller 수정을 먼저 검증하라: (1) append-only frontier, (2) 새 작업의 typed all/any proof obligations, (3) input/method/assumption/validation_counterexample/prelaunch_transport 증거 구분. METHOD_FRONTIER의 kind는 의미 분류이며 현재 controller enum이 아니다. 실제 input_identity/acceptance/owned_paths/repair와 theory/numeric/code/input을 bind한 task spec으로 변환하여 append하라. 모든 enables_nodes를 AND로 만드는 문제를 새 경로에서 해소하되 기존 원래 DAG를 소급 수정하지 마라. OR는 같은 의무를 각각 충분히 충족하는 경로에만 쓴다. 다른 estimand끼리 OR로 원래 claim을 통과시키지 마라. 완료된 연구 작업과 qualified scientific evidence는 다르다. 예를 들어 실패를 밝혀 완료된 작업은 유효한 confidence bundle을 제공한 것이 아니다. 하네스 패치는 packet 출력에서 끝내지 말고 실제 R24-DISTANCE-MODELS 결과 또는 cache 불가를 보여주는 검토된 source-specific 판별 결과까지 소비시켜라.

새 방법은 같은 데이터로도 연구를 재개할 수 있다. 반대로 identity 문자열/hash만 바꾸는 것은 새 정보가 아니다. 현재 refused/unacknowledged packet의 transport 복구만 별도 허용하고 acknowledged/UNKNOWN 결과는 자동 재실행하지 마라. R23-COMMON-E1/R23-Q의 ultra 사용, one-use repair, R9/UNKNOWN을 그대로 보존한다. Desktop Commander의 소진 경로를 재시도하지 말고 로컬 checkout을 직접 사용하라.

실행은 원자적인 scientific discriminator 중심이다. 첫 병렬 묶음은 R24-DISTANCE-MODELS(동일 cohort의 calibration/PV 대 optical cosmography), R24-CMB-ORBIT(기존 Q/O tensor와 처리 민감도), 최소 controller 패치다. 총 agent 수는 root 포함 최대4, fresh bounded context와 분리된 파일 소유권, 독립 reviewer를 사용하라. 자료가 확인된 다른 준비 작업을 선택해도 된다. 패치를 기다리느라 독립 수학/자료 검사를 멈추지 마라.

이후 selection sensitivity→optical shear interval, common-foreground envelope, K03 valid-domain power/관측 설계, local boost 대 intrinsic acceleration, SN release-level calibration, depth confidence images를 METHOD_FRONTIER의 의존성에 따라 진행하라. 각 작업에 estimand, 새 의미 차이, 가정, 입력, 판별 계산, 사용한 실제 law와 결과를 남긴다. S04의 narrower functional은 허용된 연구 방향이다. full physical source가 없다고 모든 observational inference를 기다리지 마라. 반대로 finite-z optical coefficient를 곧바로 G-congruence shear나 global tilt로 부르지 마라.

R24의 T1–T7과 RESULT.json은 재사용하라. K03 epsilon=.1 fixed-Gaussian power 상계0.050024942216은 이미 계산·독립 검토되었다. 같은 rank6/full catalogue pass를 반복하지 말고 spatial/systematic covariance, response depth, validity domain이나 다른 관측량을 바꿨을 때의 구별력을 연구하라. Planck split contrast는 common foreground도 없애므로 split 차이만으로 common mode를 상계하지 마라. CMB calibrated p는 matched law가 있을 때만 출력하고, 나머지는 source-bound sensitivity envelope로 보고하라.

과학 blocker를 만나면 실패 지점, 동일/변경된 가정, 최소 반례/판별 계산을 가진 작은 issue packet으로 기존 router에 요청하라. 먼저 host가 지금 실제로 제공하는 정확한 model/effort capability를 확인하라. 기본 adapter/일상 코딩은 gpt-6.1-sol/medium, 수치 구현은 gpt-6-sol/high, 이론 및 독립 적대 검토는 gpt-6-astra/xhigh를 권장하되 실제 가용한 profile만 router에 전달하라. ultra는 기존 정책의 실제 미소진 issue에 한하며 같은 issue를 rename하여 재소비하지 마라. requested profile과 실제 observed model identity를 구별하고 실제 관측이 없으면 UNKNOWN으로 기록하라. host가 구현 native spawn→ack→raw result→record→next를 수행하여 review packet을 얻고, 별도 reviewer spawn→ack→raw result→record→next를 수행해야 한다. next 출력만으로 agent를 실행했다고 기록하지 마라.

두 번 실패했다는 이유로 연구를 영구 종료하지 마라. 실패는 재계획의 신호다. 새로운 식별 가능한 가정/관측량/정리가 있으면 계속하라. 단, 동일한 실패를 새 이름으로 반복하지 마라. 한 분기에 진짜 external history/atlas가 필요하면 정확한 payload를 기록하고 다른 독립 분기를 진행한다. 각 결과의 유용성은 uncertainty 폭, parameter validity, power, 반박된 모델, 새로운 식별 조합으로 판단하고 문서/agent/test/PR 수로 판단하지 마라.

공개 자료는 기존 receipt/hash/cache를 먼저 재사용한다. /mnt/extdrive의 실제 mount/free space를 확인하고 raw data는 Git 밖에 둔다. 추가 인증 없이 공개 다운로드 가능한 관련 제품은 자발적으로 취득해도 된다. 파일별/누적 다운로드 상한은 없다. 기본2GiB reserve와 streaming 검사, release/schema/units/frame/genealogy 검증을 유지한다. 무작정 전체 archive를 받지 말고 정확한 소비 질문에 필요한 제품만 선택하라. 저자에게 연락하거나 인증을 우회하지 마라. 공개 total covariance와 이미 포함된 PV/calibration 성분을 두 번 더하지 마라.

매 작업 후 결과·그림·수식 조건·검증을 기록하고 다음 준비 작업을 즉시 수행하라. 하나의 qualified product만 있어도 그 제품의 full functional bundle을 끝내라. 모든 제품을 기다리지 마라. 기존 branch/사용자 변경을 보존하고 현재 AGENTS의 primary-checkout 정책을 따라 기존 checkout에서 필요한 branch를 사용하여 검토된 코드·보고서를 push하라. 새 worktree는 이후 사용자의 명시적 예외 허가 없이는 만들지 마라. merge/투고는 하지 마라.

세션 한계가 오면 durable state, 실제 실행 중 job/packet, 다음 정확한 명령과 미해결 과학 입력을 checkpoint한다. 자동으로 계속 실행되는 환경이 없으면 계속 실행 중이라고 말하지 마라. 원래42가 미완료이면 goal을 complete로 바꾸지 않는다. 다만 가능한 frontier 작업을 모두 판별 가능한 결과 또는 구체적 외부 입력 조건까지 진행한 사실과, 원래 물리 acceptance가 남은 사실을 분리해 보고하라.
```
