# htt-ssot-handoff-maintainer

Write a compact handoff with exact repo/branch/head, changed paths, author and
reviewer observations, tests actually run, residual failures and one next command.
Keep task IDs, cumulative usage, allocations and original evidence references.
Separate candidate return, scientific validation, review, push, merge, install and
client activation. Never rewrite a historical failure into PASS or infer success
from a missing log. Preserve active R9 OUTCOME_UNKNOWN and unrelated user edits.

Use canonical DAG/status only when the corresponding node actually changed;
do not update every ledger or package a full repository for ordinary handoff.
Record current global authority and runtime receipt paths, not stale copied policy.
Follow R1 remote identity for routine writes and R3 for authority/recovery changes.
Do not redownload artifacts or create verification worktrees by habit. See
`docs/harness/CURRENT_CODEX_RUNTIME.md`. Include exact unmeasured quantities and
scientific claim ceilings; source hashes do not substitute for scientific validity.
